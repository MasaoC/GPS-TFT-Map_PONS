# 電源の異常の検出（0.503〜）
 * 充電 IC が壊れて電池から VBUS へ逆流すると、USB を挿していないのに Pico の VBUS が立つ。
   「VBUS があるのに VSYS が 3.9V 未満」が 3 秒（GPIO24 で VBUS が見えず VSYS だけで見えているときは 10 秒）続いたら、
   どの画面でも赤枠で `POWER FAULT !!` / `SW OFF + UNPLUG USB` を出す。
   再起動するまで消えない。v3 には音が無いので知らせるのは画面だけ。SD の `log2.txt` に `POWER FAULT: ...` を残す。
 * 使う信号は Pico 基板に作り込まれた GPIO24（VBUS 検出）と GPIO29（VSYS÷3）。v3 基板は Pico の VSYS に何もつないでいないので、
   VSYS は「VBUS − Pico の D1」になる。本物の USB なら 4.4V 以上、逆流なら電池電圧より低い。
 * **書き込んだら実機で確かめること（ADC_VREF が基板で決まっていないため）。**
   1. `settings.h` の `ADC_VREF_V` は 2.95V（Pico の R7＝200Ω を外し、外付けの LDO で与えている前提。電池の式の「Vref2.95」と同じ）。
      **高温での充電の警告を信用するには、テスターで Pico の 35 番ピン（ADC_VREF）と GND の間を測って書き換えること。**
      CPU 温度は ADC_VREF_V が 1% ずれると約 4°C ずれる。R7 が残っている基板（約 3.16V）だと、VSYS は低めに出るだけで誤報しないが、
      CPU 温度は約 27°C 高く出て充電のたびに高温の警告が出る。設定画面の下の `CPU` が室温 +5°C 前後なら合っている。
   2. USB をつないで設定画面を開き、最下行の `VSYS:` が 4.6〜4.9V 程度になることを確かめる（同じ値が Serial と `log2.txt` に 60 秒ごとに `PWR ...` で出る）。
   3. できれば USB の VBUS に安定化電源で 3.5V を入れ、3〜10 秒で `POWER FAULT !!` が出ること、5.0V では出ないことを確かめる。
   4. USB を何度か抜き差しして、`POWER FAULT !!` が出ないことを確かめる（抜いた直後の VSYS の下がり方で誤報しないか）。

# 機能 Detail.
 * 基本機能
    * 画面上部：対地速度、航路（True Track）の特大フォント表示。直下に `GS` / `sAcc`（速度精度）と `TT`（コース警報時点滅）のラベル。GPS が止まった・測位を失ったときはグレー。
    * 画面下部：目的地への True Course（TC）と距離（km）/ 電池残量 %。BATLOW（点滅）= 3.49V 未満。電池交換推奨。表示されてから約30分程度は正常に動作する。
    * その上の行：最大 G/S（起動から・その時刻 / 直近 5 分）/ 水平精度が悪いときの Acc / 時刻（JST）。
    * 画面最下部：緯度/経度/SD認識 SDカード正常認識＝緑色。SDカードエラー＝赤色。
 * 緯度/経度/速度(m/s)/真航跡/GNSS 高度/電圧/捕捉数/時刻（JST）/水平精度/速度精度の SD カードへの保存（GPS 位置捕捉時のみ、1 秒に 1 度）
 * 過去の航跡は緑色の線で引かれる。おおよそ過去10分の履歴が表示される。
 * 内蔵のベクタ地図（日本の海岸線・琵琶湖周辺）に、SDカードの独自地図（`mapdata.csv`）を重ねて表示する
 * ボタン（1 つ）: 地図画面でダブルクリック = 縮尺、長押し = 設定画面。設定画面では 1 回押し = 次の項目、長押し = 選ぶ／決める。
 * 設定画面
    * 目的地（Set destination）と Destination Mode（INTO / AWAY / Auto 10km）
    * 地図の縮尺（Map scale）、NORTH UP（北が上） / TRACK UP（進行方向が上） の設定
    * デモモード（DEMO BIWA）、リプレイ（Replay / Replay speed）
    * GPSのコンステレーション表示（受信中衛星）、地図一覧（Maplist detail）
 * 琵琶湖付近にいる場合
    * 自動的にプラットホームから離れる方向にピンク色で線が引かれる。
    * タケシマ・北パイロン・南パイロンに向けて自動で線が引かれる。
    * 北・南・1km パイロンに黒枠付きオレンジ三角コーンアイコン、PLATHOME にスタート台のロゴアイコン、折り返しの目安の 10.975km の円（橙）が描かれる。

# SD カードの設定ファイル（0.503〜）
 * `settings.txt` … 自動で書かれる。`id:value` の 1 行 1 項目（`destination` / `navigation_mode`（INTO・AWAY・AUTO10K）/
   `auto10k_status`（AWAY・INTO）/ `upward_mode`（TRACKUP・NORTHUP）/ `scaleindex`）。読めない値は無視して既定のまま。
 * `override_pilon_coordinate.csv` … 置いたときだけ。`#` で始まる行と空行は無視。
   ```
   # name,latitude,longitude
   PLATHOME,35.294222,136.254333
   N_PILON,35.377878,136.189907
   S_PILON,35.274220,136.136183
   PILON_1KM,35.297961,136.243624
   ```
   使える名前は `PLATHOME` / `N_PILON` / `S_PILON` / `PILON_1KM` / `TAKESHIMA`。書いた地点だけが上書きされる。
   緯度 ±90・経度 ±180 の外と `0,0` は打ち間違いとみなして無視。適用結果は `log2.txt` に `PILON OVERRIDE ...`。


# SD：Creating map.  地図作成
 * 追加地図（独自地図）の作り方・使い方
 * Google Earthでパスを作り、KMLファイルをダウンロードする。
 * kml_to_mapcsv.py を使って、KMLファイル名を入力すると、自動でmapdata.csvファイルが作成される。
 * 作成された 「mapdata.csv」ファイルをSDカードのルートフォルダに追加する。
 * 捕捉：CSVデータ形式＝名前,point数,lon1,lat1,lon2,lat2,lon3,lat3....(point数分続く）。改行ごとに線が引かれる。
 * 捕捉：名前は英語のみ対応。また1文字目によって線の色が決まる。r:RED,o=ORANGE,g=GRAY,m=MAGENTA,c=CYAN,b=BLUE（それ以外は緑）
   * 赤色の線の例：r_warningline,2,135.0,46.0,135.1,46.1
 * 捕捉：描ける線の数を便宜上100に制限している（`navdata.h` の `MAX_MAPDATAS`）。zoom7 より広い縮尺では描かない。
 * 捕捉：点の数と座標の数が合わない行は捨てる（`log2.txt` に `ERR mapdata.csv bad size ...` / `MAPDATA: ... ignored`）。

# PC側ツール（tools/）
ログの可視化・動画作成・地図作成用の Python スクリプト群（PONSv7.1 と共通）。

* **動画作成・可視化**
  * `tools/createmovie_csv2mp4.py`: 飛行ログCSVから速度・進路・航跡・高度などを可視化した動画（MP4）を生成。
  * `tools/logcsv2tourkmz.py`: 飛行ログおよびボートログCSVから Google Earth のツアー再生用 KMZ ファイルを生成。
  * `tools/logcsv2kml4earth.py`: 飛行ログCSVから Google Earth 用の軌跡 KML を生成。
* **地図作成**
  * `tools/kml_to_mapcsv.py`: Google Earth で作成したパス（KML）から、SDカードに置く `mapdata.csv` を生成。
  * `tools/vectormap/`: OpenStreetMap（.osm.pbf）から PONS 内蔵用のベクタ地図バイナリ（`vectormap_data.cpp`）を構築するツール。
* **フライトログ解析**
  * `tools/flight_preprocess.py`: 姿勢補正および風・偏流角の推定。
  * `tools/flightanalysis/`: 機体運動・フゴイド・スペクトログラム等の詳細解析スクリプト群。
