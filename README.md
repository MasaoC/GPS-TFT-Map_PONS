人力飛行機のパイロットが使いやすいことを目標とした航法装置です。琵琶湖の鳥人間コンテストに特化しています。  
GPS/GNSS navigation for human-powered aircraft, specialized for the Japan International Birdman Rally at Lake Biwa, Japan.

* **本ブランチ（`PONSv7.1`）は 2027・2028 年大会向け v7.1 基板専用です。**  
  姿勢センサーを Murata SCH16T-K01（外付け FPC）とし、電源回路の安全対策（Q3/Q4/F1/U10）を施した最新設計です。  
  BNO085 搭載の初代 v7 基板用は [`PONSv7`](https://github.com/MasaoC/GPS-TFT-Map_PONS/tree/PONSv7) ブランチを参照してください。
* **v3〜v6 ブランチが実際にフライト利用した実績のある安定版です。**

## PONS を導入するメリット

**飛んでいる間の「道具」であり、飛んだあとの「計測器」でもあります。** 当日の誘導と、次期機体の設計の両方に活用できます。

### 鳥人間コンテストに特化している点
* **パイロット中心設計**: 直射日光下（1000ニト高輝度 TFT）や騒音・ペダリング負荷のなかでも、画面を注視せず音声警報だけでコースやバンク角を把握可能。
* **Auto 10km 自動誘導**: プラットホーム離脱から 10km 折り返し、帰還までを距離判定で自動認識・案内（→ [大会本番での使い方](#大会本番での使い方auto-10km-モード)）。
* **機上風向・風速推定**: 対気速度センサー不要で、ピッチ角と対地速度から機上で風向・風速ベクトルをリアルタイム推定（→ [風の推定](#風の推定)）。
* **PONS Link（機体⇄ボート テレメトリ）**: 920MHz 帯 LoRa により、ボート側の受信機へ機体の航法画面・風情報・警報音をリアルタイムで完全ミラーリング（→ [PONS Link](#pons-link機体ボート-テレメトリ無線)）。

### 次期機体の設計へのフィードバック
SD カードのログを付属ツール（`tools/`）で解析し、機体特性の定量評価が可能です。
* **縦の癖**: フゴイド周期の同定、対気速度の分散推定、巡航余裕度の確認。
* **横の癖**: 上反角・ラダー効果に起因するロール／ヨーの固有周期分析。
* **構造荷重の検証**: 巡航中の鉛直加速度（実測最大 +0.18 / −0.25 G、荷重倍数 1.17 / 0.77）から主桁設計荷重を裏付け。

## 設計と根拠

### 1. 姿勢推定（ESKF: 誤差状態カルマンフィルター）
内蔵フュージョンチップ（BNO085 等）は協調旋回時に比力横成分がゼロになるためロール角を過小評価し、地磁気方位も機体電子機器の影響で 30° 以上狂う課題がありました。  
本システムでは **生のジャイロ・加速度（SCH16T）** と **GNSS 航跡・対地速度** をカルマンフィルター（ESKF）で機上融合しています。
* **初期水平化**: 静止 2 秒間の平均比力から初期ロール・ピッチを決定。
* **初期ヨー注入**: 発進滑走時（対地速度 > 3.0m/s）の最初の航跡（True Track）から真方位を注入（接地中は横滑り角が原理的にゼロのため、航跡＝機首方位）。
* **重力観測（レベリング）**: 準定常直進時（旋回レート小、$\|a\| \approx 1g$）に比力水平成分を 2Hz で観測更新し、GNSS 途絶時でもロール・ピッチの長期ドリフトを防止（実機走行試験で誤差中央値 21.3° → 1.3° に抑制）。

### 2. 風の推定と推定 TAS
定常飛行時の揚力平衡式 $L = W = \frac{1}{2}\rho V^2 S C_L$ および揚力傾斜の線形性から、ピッチ角 $\theta$ [deg] から対気速度 $V$ [m/s] を算出します。

$$V(\theta) = V_0 \sqrt{\frac{K}{K + \theta}}$$

* **係数は機体・重量・重心で変わるため、SD カードの `settings.txt` で設定可能**:
  | キー | 意味 | 既定値 | 設定範囲 |
  |---|---|---|---|
  | `airspeed_v0` | $V_0$: ピッチ 0 度での巡航対気速度 [m/s] | 7.00 | 3〜20 |
  | `airspeed_k` | $K$: θ=0 の姿勢から揚力ゼロの姿勢までの角度（取付角 − 零揚力角）[度] | 10.00 | 3〜60 |
  | `airspeed_min` | 推定対気速度の下限 [m/s] | 5.80 | 1〜20 |
  | `airspeed_max` | 推定対気速度の上限 [m/s] | 9.00 | 1〜25 |

  `airspeed_min` ≥ `airspeed_max` のときは両方を既定（5.80〜9.00）に戻して log.txt の `ERR airspeed_min ...` に残す。
* ピッチには**過去 10 秒の移動平均**（平均ピッチ `Pavg`）を使う（2026-11-07 までは時定数 10 秒の一次遅れだった）。
* $\text{風ベクトル} = \text{対地速度ベクトル} - \text{対気速度ベクトル}$（対気速度の向き＝機首方位）により算出。
* 同じ式の値を**推定 TAS** としてヘッダー右の大きい枠にも出せる（IMU/ESKF 画面 1 ページ目の `Header: Pavg / TAS`。`settings.txt` の `header_tas:1`）。
  青い箱に白字・縦書きの `TAS`。地上は数字に白い横線が入り、対地速度 3m/s 以上が 10 秒続くと線が取れる。上下限に張り付いたら灰色の箱。
  平均ピッチは地図の上端（`TAS` の小箱の左）に小さく残る。TAS にすると日本語の案内（画像と曲線の 2 画面・音声）が出る。
  仕組みと精度は **[docs/pons_tas.md](docs/pons_tas.md)**（増減は信用できるが、値は取り付け 1° で約 0.4m/s ずれる）。
* 旋回中の横滑り角による誤差混入を防ぐため、直進が累計 10 秒以上継続した場合のみ更新。
* `settings.txt` は本体が保存のたびに書き直します（書き込んだコメント行は消えるため、メモは別ファイルに残してください）。

### 3. GNSS の起動を速くする（AssistNow Autonomous）
SAM-M10Q が自律予測した数日先までの衛星軌道をバックアップ電池（MS621FE）で保持することで、前日と同じ時間帯であれば **起動から 3〜4 秒で測位完了** します（通常コールドスタート 23 秒）。

バックアップ電池が切れた起動に備えて、通電中に GNSS の航法データベース（UBX-MGA-DBD）を SD の `gnss_dbd.bin` へ写しておき、
起動時に時計が死んでいたときだけ GNSS へ戻します（2026-11-09〜、まだ実機で確かめていない。`gnss_dbd.cpp`）。
効くのは前回の保存から約 3 日以内。保存は止まっているときだけ（飛行中はしない）。
`log.txt` の `GNSS FIXED ... after boot rtc=lost dbd=40/52 resend=52/52 time=14.2s` で、戻した結果と測位までの秒数がわかります。
吸い出し・戻しの 1 回ごとに `GNSS DBD IO (...)` の行で通信の様子（位置の更新が待たされた最大・受信 FIFO のたまり・バイトの欠け・返事の遅れ）を残します。
机の上では USB シリアルの `PONS:DBD,COLD`（コールドにして戻す）/ `COLDONLY` / `HOT` / `SAVE` / `STATUS` で試せます
（`COLD` / `COLDONLY` / `HOT` を打つと、再起動するまで自動の吸い出しは止まります。`SAVE` は効きます）。
計画と根拠は [docs/pons_ttff_assist_plan.md](docs/pons_ttff_assist_plan.md) §3。

### 4. PONS Link（機体⇄ボート テレメトリ無線）
* 送信機（機体）から受信機（ボート）へ、**32 バイト固定フレーム**（印 `0xA4`。2026-11-07〜）を送信（下り一方向）。
  グループは A〜D（`settings.txt` の `link_group:B`）。推定 TAS と平均ピッチは毎回、風は 4 秒に 1 回。
* 電波法適合のため、標準ではローワーバンド（CH0/3/6/9/12、SF8、1Hz）を使用し、混雑時はアッパーバンド（CH15/21/27）へ退避可能。
* 詳細は **[docs/pons_link.md](docs/pons_link.md)** を参照してください。

## 画面仕様と操作

### 画面各部の構成
* **画面上部**: 対地速度 (m/s)、10秒平均ピッチ（`Pavg`。大きい枠。設定で推定 TAS にもできる）、真方位（`TT`）、速度精度（`sAcc`）。
  対地速度と真方位は、GNSS が断線した・fix していない・衛星 0 のとき赤い横線で消す（読まない値。受信モードでは送信機の断線と fix で判断）。
* **画面中央**: 内蔵ベクタ地図（OSM 由来）、現在位置、航跡（緑線、最大 500 点 / 約 25km。跳躍 300m 以上は線引き除外）、パイロン基準線、コース警報アーク（向かうべき方位への赤線円弧）、旋回指示矢印（コースズレ 15° 以上で点滅）。
* **画面左下**: 風向風速ベクトル矢印（吹いていく方向、色は風速）、風向 3 桁（吹いてくる真方位）、ヨー精度（`Y95`）、瞬時ピッチ（`P`）、ロール（`R`）、自動ロールトリム（`Rtrim`）。
* **画面下部**: JST 時刻、最大対地速度（MAX GS。2 回連続の小さい方のみ採用）、目的地コース（TC）、目的地直線距離（km）、捕捉衛星数（10 以上で緑、9 以下は橙、4 以下は赤地。0 個は赤地に白字と白地に赤字を交互に点滅。分からないとき（受信を始めた直後・列の無いリプレイ）は灰色の `--sats`）、バッテリー残量（充電中 `CHG`、SW OFF 充電 `SW OFF`、無線ミラー中 `s72r85`）。
* **画面最下部**: ナビゲーションモード（`10K AWAY` / `10K INTO` / `FLY INTO` / `FLY AWAY`）、目的地名、SD 認識状態。

### 設定画面
NAV 画面でスイッチ長押しで入ります。
* 各行の右端のマークが設定状態を示します：**緑の丸＝本番推奨**、**赤の ×＝本番不可（デモやリプレイ等）**、**オレンジの三角＝許容だが既定外**（グレーのハイフンは対象外・OFF）。フッターの電池のマークは充電中が青の丸。**本番フライト前に赤の × が無いことを確認してください**。
* 地図拡大率は NAV 画面でボタンの**ダブルクリック**でも変更可能（標準縮尺 scaleindex=3 / 画面幅約 18km で緑）。
* 設定は SD の `settings.txt` に自動保存されますが、**DEMO / REPLAY モードは保存されません**（再起動すれば必ず本番航法へ復帰する安全設計）。
* **`REPLAY/DEMO`** の行から入る画面で、リプレイするファイルとデモの地点（BIWAKO / SHIRAHAMA / KASAOKA / FUJIGAWA / TOKYO / OSAKA）をまとめて選びます。短押しでカーソル移動、長押しで決定（その場で始めて地図画面へ）。先頭の `OFF (Normal GNSS)` でリプレイもデモも止まります。デモとリプレイは同時には使えず、どちらかを始めるともう片方は止まります。
* `Save & Exit >>` は他の行と見分けやすいよう中央に寄せてあります。
* 設定画面を 3 分操作しないと地図へ戻ります。設定画面を含め、**地図以外の画面（IMU/ESKF・GNSS 詳細・VARIO・WIRELESS など）を出したまま動き出すと**（自機の対地速度 3m/s 以上が 5 秒）、地図へ戻ります（降下する 2 音）。受信モードと PC 接続の画面は対象外です。
* **本番前チェック（画面右上）**:
  飛ぶ前に確かめる項目が揃うと緑の `READY` となり、地上静止中に 1 度だけ「準備完了」と音声読み上げします。欠けていると赤の `NOT READY` と不足項目が表示されます。
  
  | 表示 | 足りない項目 |
  |---|---|
  | `GNSS` | 3D 測位、`gnssFixOK`、水平位置精度 5m 以内 |
  | `IMU` | SCH16T が見つからない・応答していない（v7.1 は SCH16T を必ずつなぐ。設定画面の IMU の行も赤の ×） |
  | `ESKF` | 姿勢推定が未収束 |
  | `CALIB` | 較正のやり直しが必要（マウントから外された） |
  | `ATT` | 地上で姿勢が申告値からズレ続けている（地上チェック発報中） |
  | `SET` | 設定画面に赤の × がある（標準縮尺でない、Auto 10km でない等） |
  | `USB` | USB ケーブルが挿さっている |
  | `BATT` | 電池残量 50% 未満、過放電ラッチ中、または電源異常 |
  | `SD` | SD カードが認識できない |
  | `LINK` | 送信モードで無線モジュール無応答、または重複送信機あり |
* **フッター（画面下 3 行）**: 電池（または充電の残り時間）、CPU・気圧センサーの温度、照度センサーと画面の明るさ。
  3 行目は `VEML 123lx  BL 35% AUTO` の形で、照度・いまの点灯率・その決まりを示します（右端のマークは照度センサーが応答していれば緑の丸、無ければ赤の ×）。
  起動画面の後半ページ（無線の結果）の右下にも `VEML:OK 123lx` / `VEML:NG` が出ます。

### 画面の明るさ（バックライト）
輝度スイッチと照度センサー（VEML7700、ケースカバー基板）で決まります。設定画面のフッターの名前で示します。

| 表示 | 条件 | 点灯率 |
|---|---|---|
| `SW BRIGHT` | 輝度スイッチ High | 常に 100%（待機中の減光もしない） |
| `AUTO` | 輝度スイッチ Low・照度センサーあり | 照度の対数で比例。曲線は設定画面の `AUTO Brightness` で選ぶ（下の表）。時定数 2 秒でゆっくり追う |
| `LAST LUX` | 照度センサーが途中で読めなくなった | 最後に読めた照度のまま（昼間に急に暗くしない） |
| `NO SENSOR` | 照度センサーが一度も読めていない | 5% 固定（待機中の減光に入っても表示はこのまま） |
| `IDLE DIM` | 待機中の自動減光（照度センサーがあるとき） | 5%（暗い所では `AUTO` の値を超えない） |

* **`AUTO Brightness`（設定画面。`settings.txt` の `auto_brightness:ECO` / `BRIGHT`、既定は ECO）**:

  | 照度（センサーの読み） | 10 lx | 100 lx | 1000 lx | 20000 lx | 50000 lx 以上 |
  |---|---|---|---|---|---|
  | `Eco` | 19% | 34% | 50% | 70% | 100% |
  | `Bright` | 35% | 68% | 100% | 100% | 100% |

  どちらも 1 lx 以下は 3%。Eco は曇りの昼間（約 20000 lx）を 70% で読めることを基準にしてあります。
  lx は窓越しのセンサーの読みなので照度計とは合いません。合わせるときはフッターの `VEML` の値を見てください（1 万 lx 以上は `21klx` のように k で出ます）。
  照度センサーは約 2900 lx を超えると感度を 1/32 に切り替え、約 12 万 lx まで測ります（1500 lx を下回ると戻す）。
* **待機中の自動減光**: 対地速度 0.3 m/s 未満・IMU が静止・照度が急に下がっていない、の 3 つが 30 秒続くと減光します。ボタン・輝度スイッチ High・対地速度 0.6 m/s 以上・IMU の動き・照度で見た手の動きで即座に戻り、戻ってから最低 30 秒は減光しません。手の動きは次のどちらかです（変化量 5 lx 以上のときだけ）。
  * かざす: 直近 1 秒の最大から 50% 以上下がった。
  * あおぐ: 直近 1 秒の最大から 30% 以上下がり、そこから 1 秒以内に、いちばん暗い読みから 30% 以上明るくなった。

  照度は上限なしで、50 ms ごとに読んで比べます。20000 lx を超える晴れの日でも、手の影がセンサーにかかれば戻ります。雲の縁は数秒かけて暗くなったままなので、まず反応しません。1〜2 秒で通り過ぎる雲の切れ端では戻ることがありますが、30 秒明るくなるだけです。USB 給電中・リプレイ／デモ／無線ミラー中・電源の警告中は減光しません。
* **電池低下**: 3.5V 以下で 4 秒点灯・4 秒消灯、3.0V 以下で 2 秒点灯・10 秒消灯をくり返します（点灯中はいつもの明るさ。フッターに `SAVER` / `SAVER2`）。
* 値は `settings.h` の `TFT_BL_*` / `BL_AUTO_*` / `BL_ECO_*` / `BL_DIM_*`、動きは `backlight.cpp`。

### IMU / ESKF 画面（点検と較正）
2 ページ構成（短押し＝カーソル移動、長押し＝実行）。操作する項目はすべて 1 ページ目にあります。
* **1 ページ目（点検手順）**:
  1. `SET PITCH`: 機体の現在ピッチ申告値（-3.5〜+2.0°、0.5° 刻み）。本番プラットホーム（-3.5°）でも申告値に合わせれば正確に水平較正可能。
  2. `SET ROLL`: ロール申告値（通常 0°。ウィングロー保持時のみ使用）。
  3. `APPLY`: ゼロ点較正の実行。ボタンを離してから 1 秒後に実行（ボタン押下による機体揺れを回避）。
  4. `Roll/Pitch/Yaw func`: 姿勢機能の一括 ON/OFF マスタースイッチ。
  5. `Roll trim during flight`: 直進中のロール自動トリムの ON/OFF。
  6. `Wind estimate`: 風推定の ON/OFF。
* **2 ページ目（見るだけ）**: 上に生ジャイロ・加速度と静止判定、下に ESKF 内部診断・ヨー精度・`level offset`（前回 APPLY 日時）。行は `< Back to page 1` と `Exit >>`（地図画面へ）だけ。
* 右上のマークと、設定画面の `IMU / ESKF detail` 行のマークは同じ判定です（ESKF 収束・姿勢機能 ON・自動ロールトリム ON・トリム累積が小さいで緑の丸、要 APPLY で赤の ×）。ESKF が収束するまでは設定画面の行もオレンジの三角です。

## 警告音・警報

詳細は **[音仕様 (docs/pons_sound.md)](docs/pons_sound.md)** を参照してください。

* **航路・コース警報**: 15° 以上の針路変化で Chime＋「トラック」、向かうべき方位（TC）からのズレ放置で 4Chime＋「進路、右(左)に旋回」（修正中は停止）。
* **バンク角警告**: ロール絶対値が 4° を 1 秒超えると「バンク！バンク！」音声。
* **待機中姿勢ズレ / 較正警告**: 地上静止中に申告値から 3° ズレが 60 秒継続で警告。日付を跨いだ場合は再較正を促す音声。
* **電源・安全警報**: 電池電圧 3.5V 未満で「バッテリー低下」＋バックライト点滅省電力。過放電（3.0V 未満）ラッチ時は次回 USB 接続時に完全充電禁止ロック。高温充電（45°C 超）時は抜去警告。

## 大会本番での使い方（Auto 10km モード）

1. 目的地を **PLATHOME**、Navigation Mode を **Auto 10km** に設定。
2. プラットホーム上で右上が緑の `READY` となり、「準備完了」が鳴ることを確認。
3. 発進時は自動で `10K AWAY`（往路）となり、プラットホームから離れる最短距離方角へ誘導。
4. プラットホームから 10.475km 離脱すると自動更新音が鳴り `10K INTO`（復路）へ自動反転。目視でパイロン旋回を終えるまではコース警報を無視し、旋回完了後に誘導線へ合流。
5. 復路でプラットホームから 1.5km 以内に入ると再び `10K AWAY` に切り替わり、1km パイロン探索を支援。
* 折り返し状態は SD に保存されるため、飛行中に電源再起動が発生しても直前のモードに正確に復帰します。

## SD カードの構成

```
/
├── settings.txt                  # 設定ファイル（装置が自動更新）
├── rtc_backup.txt                # GNSS の時計の電池（BT1）があと何時間もつかの推定（本体が 5 分ごとに書く。消してもよい）
├── gnss_dbd.bin                  # GNSS の航法データベースの写し（止まっているとき 30 分ごとに書く。BT1 が切れた起動で戻す。消してもよい）
├── mapdata.csv                   # 独自追加地図（KML 変換データ）
├── destinations.csv              # 追加目的地（名前, 緯度, 経度）
├── override_pilon_coordinate.csv # パイロン座標の上書き
├── data/                         # 自機の飛行ログ CSV（2Hz。姿勢・風・推定 TAS の列も含む）
├── received/                     # PONS Link で受信した他機ログ CSV
├── imuraw/                       # 生 IMU バイナリログ（62.5Hz）
└── log.txt                       # 起動・診断・通信イベントログ
```

* **飛行 CSV フォーマット (`data/*.csv`)**: 2Hz 記録
  ```csv
  latitude,longitude,gs,TrueTrack,GNSS_Altitude,KF_Altitude,KF_Vspeed,pressure,voltage,numsat,date,time,lux,backlight,
  roll,pitch,yaw,pitch_avg,roll_trim,yaw_acc95,wind_mps,wind_dir,tas_mps,hdr
  ```
  `tas_mps` は推定 TAS（大きい枠の設定にかかわらず書く。出せないときは空欄）、`hdr` は大きい枠に出していたもの
  （0 = 真方位、1 = 平均ピッチ、2 = 推定 TAS、3 = 推定 TAS・上下限に張り付き、4 = 推定 TAS・地上（数字に横線））。
  リプレイはこの 2 列で当時の画面を出す（いまの係数で計算し直さない）。受信ログ（`received/`）も末尾に同じ 2 列。
* **目的地の追加 (`destinations.csv`)**: 
  SD カードのルート直下に配置。1 行に `名前,緯度,経度`（例: `KASAOKA03,34.495000,133.495000`）を記述。内蔵 4 件（PLATHOME / N_PILON / S_PILON / TAKESHIMA）の後ろに最大 100 件追加。
* **パイロン座標上書き (`override_pilon_coordinate.csv`)**:
  大会直前に再ビルドなしでパイロン座標を上書き可能（`PLATHOME`, `N_PILON`, `S_PILON`, `PILON_1KM`, `TAKESHIMA`）。設定画面の `Map data detail >` で `COURSE SD OVERRIDE` と表示されていれば適用完了。
* **独自追加地図 (`mapdata.csv`)**:
  Google Earth の KML パスから `tools/kml_to_mapcsv.py` で生成。PATH 名の 1 文字目で線の色を指定可能（`r`=赤 / `o`=橙 / `g`=灰 / `m`=マゼンタ / `c`=シアン / `b`=青）。
* **GNSS の受信状態（`log.txt` の `grf` 行。60 秒ごと）**:
  ```
  120:grf n=60 jam50=0 jmax=12 agc=3300(2976-3534) noise=82 cno=31.8/19.5 trk=12.3 used=8.1 fix=100%
  ```
  `n` は 1 分に届いた MON-RF の数（60 前後。大きく少なければ GNSS が止まっていた）、`jam50` は jamInd（狭帯域の妨害の強さ）が
  50 以上だった数、`jmax` はその最大、`agc` は AGC の平均（最小-最大）、`noise` は雑音、`cno` は C/N0 の上位 4 / 全体 [dB-Hz]、
  `trk` は追尾していた衛星・`used` は測位に使っていた衛星の平均、`fix` は Fix していた割合。値は自機の GNSS（ミラー中も）。
  **v7 の debug/v7-noise-test と同じ行**なので、2 つの基板の GNSS の受け方をそのまま比べられる（2026-11 の GNSS 干渉試験）。
  1 秒ごとの生の行（`GRF:`）が要るときは settings.h の `GNSS_RF_LOG_RAW` を 1 にする。

## 着水（水没）後の処置

1. 電源を即座に OFF にし、外装ケースを開けて水分を完全に拭き取る。
2. バッテリー端子および TFT フレキを取り外し、基板を無水エタノールで洗浄。
3. シリカゲルを入れた密封袋で数日間徹底乾燥（湿度 20% 以下推奨）。
4. GNSS バックアップ電池（MS621FE）およびスライドスイッチは腐食しやすいため点検・交換を推奨。
