## 概要 / Abstract

* Arduino（arduino-pico）で書かれた、TFT に GNSS マップ・位置・速度・方位・姿勢を表示する航法装置です。
* 大阪大学 albatross にて使用実績あり
  （2024 追走ボート: v3 / 2025 追走ボート: v4 / 2025 機体搭載「白夜」: v5 / 2026 追走ボート: v6 / 2026 機体搭載「陽還」: v6β）。2025 年大会優勝。
  * **v7 はまだ実戦投入していません。** 基板製作中で、実結線試験もこれからです。
* 最新のソフトウェアバージョンは **0.963**（Build 20260910）。
* 3D プリントケースおよび基板データ（KiCad）あり。ケースは PLA_LW が軽量でおすすめです。
* PONS for HPA = Pilot Oriented Navigation System for Human-powered aircraft。

### v7 での主な変更点（v6 から）

* **PONS Link（機体⇄ボート テレメトリ無線）を追加。** 920MHz LoRa。
  同じ機体を 3 台つくり、設定で送信機（機体 1 台）と受信機（ボート／プラットフォーム 2 台）を切り替えます。
  パイロットに出ている航法画面を、ボート側でそのまま再現できます（→ [PONS Link](#pons-link機体ボート-テレメトリ無線)）。
* **BNO085 を標準搭載**にし、接続を i2c から **SPI** へ変更。v6 では BNO085 と気圧計が i2c を共用しており、
  BNO085 のクロックストレッチでバスがロックすると気圧計も道連れになる故障モードがありました。
  SPI にはクロックストレッチが存在しないので構造的に解消します（設定で i2c へ戻すことも可能）。
* **FLASH を 16MB**（W25Q128）に拡張。

## 設計と根拠

ここから先は「なぜこの実装になっているか」の記録です。使い方は説明書を参照してください。

### 姿勢推定（ESKF）

BNO085 内蔵の姿勢推定は、加速度計が測る「比力」を鉛直とみなすため次の 2 つで系統的に誤ります。

* **定常旋回中はロールを過小評価する**（協調旋回では比力の横成分が厳密に 0 になり、加速度計にバンクが見えない）
* **加減速中はピッチがずれる**

また BNO085 単独の YAW 角の基準は「磁場のみ」で推定していましたが、磁場は機体や周辺電子機器の影響で
簡単に 30 度以上の誤差が出てしまい、YAW 角の絶対精度は著しく悪く使えませんでした。

そこで GNSS の TT（航跡角度）と GS（対地速度）を観測に入れた自前の姿勢推定
（誤差状態カルマンフィルター＝ESKF）を実装しました。
対地加速度が分かると比力から遠心力・加減速分を差し引けるので、真の重力方向が求まります。
同時にセンサーの真方位角も求められます。

* 車載実測での単位前後加速度あたりのピッチ誤差：**BNO085 4.4〜5.6 → ESKF 0.2〜0.5 deg/(m/s²)**
* 傾斜台での絶対精度：**-0.46〜-0.63 度**、直交軸への漏れは 0.6 度以下

#### Roll/Pitch/Yaw 機能の一括 ON/OFF（マスタースイッチ）

IMU/ESKF 画面の `Roll/Pitch/Yaw func` を OFF にすると、姿勢に関する機能が全て止まり、
見た目も動作も ESKF 導入前と同じ状態に戻ります（設定は SD に保存されます）。対象は次のとおり。

* **表示（8 項目）**：`Avg10s P`（10 秒平均ピッチ・大きい字）/ `P`（瞬時ピッチ）/ `R`（ロール）/
  `Rtrim`（自動トリム累積量）/ 風ベクトル矢印と `W x.xm/s` / `Y95`（ESKF ヨー精度）/
  自機アイコンの機首向き回転 / 偏流角の点線
* **警報（4 項目）**：バンク警報（4°・1 秒継続）/ 地上ロールチェック（SET ROLL から 3°・60 秒）/
  地上ピッチチェック（SET PITCH から 3°・60 秒）/ `REMOVED FROM MOUNT` と赤ステータス丸
* **裏で走る処理（3 項目）**：自動ロールトリム / 風推定 / `imu_replaydata/` への 5Hz 記録

ESKF の計算自体は止めません（2 ページ目の診断表示を生かすためと、ON に戻した瞬間から使えるようにするため）。

### 風の推定

「ピッチ 0 度で 7.0m/s で飛ぶ」という設計前提からピッチ→対気速度を引き、
`風ベクトル = 対地速度ベクトル - 対気速度ベクトル` で求めます（対気速度の向き＝機首方位と仮定）。
対気速度の換算表は機体依存なので `settings.h` の `AIRSPEED_*` で変更できます
（既定：ピッチ +5 度で 5.8m/s、0 度で 7.0m/s、-4 度で 9.0m/s、間は線形補間、範囲外はクランプ）。

* **直進中しか更新しません。** 旋回中の人力飛行機は横滑りが大きく、横滑り角 beta があると
  風速の誤差が `対気速度 × sin(beta)` になります（beta=30 度なら 3.5m/s）。旋回中は直前の値を保持します。
* 表示されるまでに**直進が累計 10 秒**必要です（`WIND_LPF_SEC`）。
* ヨー精度の 95% 値が 10 度未満のときだけ表示されます。条件を満たさない間もその値（`Y95`）は常に見えます。
* **ヨーは補正対象外です。** 対気速度センサーが無いため、風によるカニ角を原理的に補正できません。
  またヨーは水平加速度がある間しか可観測にならないので、等速直進が続くと精度が落ちます。
  信頼できないと判定した間はグレー表示にし、自機アイコンも機首方向へ回しません。

### PONS Link（機体⇄ボート テレメトリ無線）

同じファームウェアの PONS を **3 台**つくり、SD カードの設定で役割を決めます。

| 置き場所 | モード | 役割 |
|---|---|---|
| 機体 | TX | パイロットの航法装置。これが本番 |
| 追走ボート | RX | 機体の画面を再現する。ボートマンが見る |
| プラットフォーム | RX → 途中で OFF | **予備機**。機体の PONS が壊れた／電池切れのとき TX へ切り替えて載せ替える |

目的は **パイロットに出ている航法画面をボート側でそのまま再現すること**です。
地図・対地速度・高度・姿勢・風・平均ピッチまで、送信側の画面がそのまま映ります。
コース警報やバンク角警告も、受信側が**受け取った値から自分で計算し直して**鳴らすので、
機体側と同じタイミングで同じ音が出ます。

これによって次の 3 つが得られます。

1. **飛行ログの冗長化。** 機体の水没・ロストでデータを失いません。受信側は姿勢・風まで
   `received/` に記録するので、機体の SD が失われても ESKF の解析ができます。
2. **風の共有。** ボートの PONS 単体では風を推定できません（対気速度が測れないため）。
   機体で推定した風速・風向を受け取ることで、**アシストするボートマンが風の状況を把握できます。**
3. **トリム量の共有。** 機体のピッチは刻々と変動しますが、その**平均値＝トリム量**は平均対気速度に
   対応します。これを見て**ボートマンが的確なエレベータートリム量を指示できます。**

#### 設計上の決めごと

* **通信は下り一方向だけ**で、ボートから機体へ返すものは何もありません。
  受信側の不具合が飛行中の機体へ波及する経路が**原理的に存在しません**。
  大会レギュレーション上も「操作には使えない」ことを設計で示せます。
* **受信が 10 秒途切れると**「RECEIVER MODE. NO SIGNAL.」を表示し、自機の情報表示へ戻ります。
  このとき**バリオを含めて全機能が動きます**。万一受信機モードのまま離陸しても使えるようにするためです。
* プラットフォーム機は機体が離れると当然ロストします。**これは想定どおり**で、ロストを画面と音声の
  両方で知らせたあと、人が OFF にする運用です。予備機である以上、電波が来ているかどうかは
  常にはっきり分かるほうがよいと考え、自動で静かにする仕掛けは入れていません。
* **受信モードは常に色付きの枠**を出します。数値の意味が「機体」と「自機」で入れ替わるため、
  どの画面にいても分かるようにしてあります。切り替わりは音でも知らせます。
* 電池は `S50R40%` の形で**送信側と受信側の両方**を表示します。
* 目的地とナビモードは**送信側に自動で合わせます**（RAM 上のみ）。食い違うとコース警報だけが
  静かにずれるためです。上書きしたことは音声で知らせます。
* **送信機が 2 台いる**（機体用とボート用の取り違え）と受信側が検出して警報します。
* **ボート自身の位置**を明るい緑の小さな点で地図に重ねます（受信中のみ）。地図は機体を中心に
  描かれるため、そのままではボートが地図上に存在しないためです。2m/s 以上で進んでいるときは
  進行方向へ短い線が伸びます。ボート自身の航法には v6 以前の機体を併用してください。
* 地図の左上に**アンテナ本数（0〜3 本）**を出します。ロスト時は 0 本の上に赤い×が重なります。
  本数は「感度限界からの余裕」で決めているので、SF を変えても意味が保たれます。
  送信モードでは本数ではなく、飛行機アイコンから電波が出ている絵にしてあります
  （受信していないので強度を測れず、測ったように見せるべきでないため）。
* **受信したデータはリプレイできます。** リプレイ画面の `SOURCE` を `RECEIVED` に切り替えると、
  `received/` のログ（電源を入れるごとに 1 ファイル）を選べます。姿勢・風もそのまま再生され、
  再生中は `REPLAY RX` と表示されます。なお受信モード中はルートの飛行 CSV に**ボート自身の**
  データが記録されているので、画面に出ていなかったボート自身の画面もあとから再生できます。

#### 無線の設定

| 項目 | 値 |
|---|---|
| モジュール | E220-900T22S(JP)（920MHz LoRa、技適取得済・免許不要） |
| 帯域幅 / 拡散率 | 500kHz / **SF8**（設定で SF7〜SF11） |
| チャンネル | CH0〜12（920.8〜923.2MHz） |
| 送信出力 | 13dBm（20mW）。アンテナ 2dBi、EIRP 15dBm |
| 送信周期 | 1Hz |
| 1 回の送信時間 | 98.4ms（SF8・65 バイト。メーカーの送信時間計算表による） |
| 消費電流 | 送信機 平均 4.3mA（瞬間 43mA）／受信機 8.2mA 連続（スリープは実装予定） |

設定項目は `link_mode`（OFF / TX / RX）、`link_radio_ch`、`link_radio_prof`、`link_group` の 4 つです。

`link_group` は同じ会場に別チームの PONS がいても取り違えないための識別子で、**既定は 0**。
CH と SF が偶然一致すると他チームの機体を受信してしまうため、**0 以外を各機の SD に設定してください**
（3 台とも同じ値。値は SD の `settings.txt` にだけ書き、git には既定 0 しか入れていません）。
グループ違いの電波を受けたときは「無信号」ではなく `GROUP n FOUND` と表示します。
無信号と区別できないと、SD が飛んでグループが 0 に戻った事故に気づけないためです。

CH / SF / Group のどれかを変えて設定画面を出ると、
**「送信機と受信機の設定が一致していることを確認してください」**と音声で確認を促します。
送信側が電波状況を見て勝手に設定を変え、受信側へ伝え忘れる事故を想定しています。**送信機・受信機の両方で鳴ります。**

起動時に「送信機モード」「受信機モード」を**音声で読み上げます**。片方だけ読み上げると
「何も言わない＝正常」と受け取られてしまうため、両方読み上げることで
**無音が「無線 OFF」を意味する**ようにしてあります。

#### 実測（2026-09）

| 条件 | 設定 | 到達距離 |
|---|---|---|
| 芝生（凹凸あり） | 500k SF5 | 約 100 m |
| 同上 | 500k SF8 | 約 190 m |
| **海辺・平坦なコンクリート・夜間** | **500k SF7** | **約 350 m** |

* 環境雑音は熱雑音 +7dB（BW500kHz で約 −104dBm）。屋内外でほとんど変わりません。
* **アンテナの置き方が拡散率より効きます。** 角度が 60° ずれると 6dB 失いますが、
  SF を 1 段上げても 2.5dB しか稼げません。アンテナは高く、偏波を揃えて設置してください。
* **水面での挙動は未確認**です（試験はコンクリートと芝生のみ）。

#### 電波法について

E220-900T22S(JP) は技適取得済みで、免許は不要です。ARIB STD-T108 の CH0〜12 を使います。
ボートから機体へ「操作」を送る機能は作りません。通信は下り一方向だけで、
上りの通信路そのものが存在しないため、遠隔で機体を変更する経路は物理的にありません。

設計の詳細・データシートの落とし穴・電波法の扱いは [docs/pons_link.md](docs/pons_link.md) に、
基板到着後の立ち上げ手順は [docs/pons_link_bringup.md](docs/pons_link_bringup.md) にまとめてあります。

## 画面と機能の仕様

しきい値と色の一覧です。画面写真つきの説明は説明書を参照してください。

* **画面上部**：左に対地速度 (m/s)。右の大きい枠は **平均ピッチ**（ラベル `Pavg`）。
  対地進路は地図を見れば分かるがピッチは他に得る手段が無いため、一番目立つ枠をこちらに使う。
  BNO085 非搭載機・姿勢機能 OFF・平均が未収束のときは従来どおり真方位（ラベル `TT`）。
  対地速度は 2.0m/s 未満でグレー表示。左上に `GS` と `sAcc`（速度精度、色分け）。
* **画面中央**：地図（ファームウェア内蔵のベクタ地図 ＋ SD の `mapdata.csv`）と TT の針。
  右上の枠が `Pavg` のときは、画面中央上部に真方位を `TT 232` の形で表示する。
  * 旋回角速度表示（3 秒平均 deg/sec）。2.0deg/s 超えで着色、左右端に表示。
  * 旋回すべき修正方向の表示（赤矢印）。コースズレ 15° 以上で表示・点滅。
  * コース警報 Arc：向かうべき方位 (TC=True Course) への赤線円弧。10〜60 秒放置で音声警報。
  * 過去の航跡は緑色の線。最大 500 地点（約 25km 分）を表示。
  * 琵琶湖付近にいる場合、タケシマ・北パイロン・南パイロンに向けて自動で線が引かれる。
    パイロンが表示され、折り返し目安の 10.975km 円が描かれる。
  * NORTH UP / TRACK UP 切替対応。
  * 30 度範囲表示：針の先の三角形（薄い線）が過去の針路から左右 15 度の範囲を示す。
    15 度を超えるたびに三角形が更新され、警告音＋「トラック」音声が鳴り 8 秒間点滅する。
  * **姿勢表示**：左下に上から順に、**風ベクトルの矢印** → `W 1.5m/s`（風速）→
    `Y95 4°`（ヨー精度の 95% 値）→ `P`（瞬時ピッチ）→ `R`（ロール）→ `Rtrim`（自動ロールトリムの累積補正量）。
    平均ピッチはヘッダー右の大きい枠へ移したので、ここには出ません。
    * ロールがバンク角警告のしきい値（4 度）を超えると**赤**。
    * ロールまたはピッチの絶対値が 10 度以上だと**グレー**（設置ミスを疑うべき値）。赤より優先。
    * `Rtrim` は累積が 1.5 度以上でオレンジ、3.0 度以上で赤。
    * 風の矢印は**風が吹いていく方向**を指し、地図と向きが揃う。長さは固定で強さは色で表す
      （2m/s 以下=緑 / 4m/s 以下=青 / 超=紫）。
    * ヨーが十分信頼できるとき（95% 値 <10 度）、機首の先に**偏流角を示す点線**が出る。
    * 自機アイコンは、ESKF のヨーで機首を向けているとき**黒**、対地進路を向けているだけのとき**グレー**。
    * 較正が必要なときは `ESKF CALIBRATION REQUIRED!` を赤字で、未収束のときは `ESKF Not ready` を表示。
* **画面下部**：時刻（JST）と 最大 GS（過去 5 分・累計）と発生時刻。
  緯度・経度は v0.94 で削除した（飛行中に読む場面が無いため）。sAcc は左上へ移動。
* **画面下部 2**：目的地コース (Magnetic Course) / 目的地までの距離（km、直線距離）/ 捕捉衛星数（10 以上で緑）/ 電池残量 (%)
* **画面最下部**：目的地モード（FLY INTO / FLY AWAY / 10K INTO / 10K AWAY）/ 目的地名 / SD 認識表示（正常=緑、エラー=赤）
* **状態表示**：`Acc: XXm`（水平位置精度 1σ、10m 以上のとき表示）、`Scanning GNSS/GPS Signal`（起動直後）、
  `Weak GNSS/GPS Signal`（衛星数 0）、`No GNSS connection !!`（GNSS 通信不可＝要再起動）
* **ロガー**：緯度/経度/対地速度/時刻を SD へ保存（GPS 位置捕捉時、1 秒に 2 回）。気圧データも記録。
* **バリオメーター**：昇降計。設定画面でボリューム 0 にすると無音・非表示。
  デッドバンドは ±0.25m/s（BNO085+MS5611 の KF 融合時。BNO085 が応答しない場合は MS5611 単独へ
  フォールバックし ±0.6m/s）。v7 は BNO085 標準搭載なので全機で使えます。

### 設定画面

NAV 画面でスイッチ長押しで入ります。**項目の一覧と操作手順は説明書を参照してください。**
ここには、あとから理由を思い出せなくなる部分だけを残します。

各行の右端の丸が設定状態を示します。
**緑**＝本番推奨設定、**赤**＝本番では不可（デモ/リプレイが有効など）、
**オレンジ**＝本番でも許容だが既定から外れている。**本番前に赤が無いことを確認してください。**

* 地図の拡大率は NAV 画面でボタンの**ダブルクリック**でも変更できます
  （誤操作防止のためシングルクリックでは変わりません）。通常使用する zoom11 のとき緑、それ以外は赤。
* 設定は SD カードに保存し、次回起動時に自動読込します。ただし **DEMO / REPLAY モードは保存しません**。
  電源を入れ直せば必ず本番設定に戻る、という安全側の作りです。NAV 画面の scale（拡大率）は保存されます。
* 画面下部にバッテリーの目安持続時間と CPU 温度を表示します。
  CPU 55 度（外気温 35 度）までは動作確認済み。2026 年大会では CPU 最大 48 度でした。

#### リプレイモード

SD カードに保存された**飛行 CSV をそのまま再生**します。操作は説明書を参照してください。

* v5 までのように Python で NMEA へ変換する必要はありません。**列名で解釈する**ので、
  v5〜v6 のログも、後から列を足したログもそのまま読めます。
* **一覧の並びはファイル名順ではなく、SD カードへ書き込まれた順（ディレクトリの登録順）です。**
  過去大会のログなど上に出しておきたいものは、カードへ**最初にコピー**してください。
* 設定用の CSV はルート直下にあり、リプレイ一覧は `data/` と `received/` しか見ないので、
  設定ファイルを誤って再生対象にする経路がそもそもありません。
* **再生を続けられなくなったら、音を鳴らして取り消し、通常の GPS に戻ります。**
  黙ってファイルを開き直し続けると、地図が固まったまま SD を叩き続けることになるためです。
  理由は `log.txt` に残ります。
  * `REPLAY canceled: file is not a flight log` … 開けない / ヘッダが無い / 空
  * `REPLAY canceled: SD not available` … SD カードが読めなくなった

#### IMU / ESKF 画面

2 ページ構成（短押し=カーソル移動、長押し=実行）。

1 ページ目は飛行前の点検手順の順に並べてあります。

1. `SET PITCH`：「いま機体のピッチは何度か」の申告値（-3.5〜+2.0 度、0.5 度刻み）
2. `SET ROLL`：同じくロールの申告値（±3.0 度、既定 0）。通常は 0 のままにする。
   横風でウィングロー保持のまま較正せざるを得ないときだけ使う。0 以外はオレンジ表示＋音声で警告。
3. `APPLY`：上の申告値で機体ゼロ点を較正。本番プラットホーム（-3.5 度）でもその値を申告すれば正しく較正できる。
   **ボタンを離してから 1 秒後に実行される**（スイッチを押す力でマウント上のデバイスが傾くため）。飛行中は実行できない。
4. `Roll/Pitch/Yaw func`：姿勢に関する機能の一括 ON/OFF

各行の右端に状態の丸が出ます。画面右上の丸が緑にならない原因をここで辿れます。
緑の条件は「ESKF が収束」「Roll/Pitch/Yaw func が ON」「Roll trim during flight が ON」
「自動トリムの累積が 1.5 度未満」の 4 つ。較正が必要なときは赤。

2 ページ目はセンサー生値と ESKF の内部状態（診断用）、および
`Roll trim during flight` / `Wind estimate` の ON/OFF（既定はどちらも ON）。

## 警告音・警報

* **旋回率警告音**：旋回率が 2deg/s を超えるとピピと高音（v6 では音程固定）。2.0m/s 以下では鳴らない。
* **航路 (TRACK) 警報**：左右 15° 範囲を超えて航路が変わると Chime 音＋「Track！」音声。
* **目的地自動更新音**：Auto 10km モードで 10K AWAY ↔ 10K INTO 切替時に 4Chime ＋音声。切替時に 1 回のみ。
* **コース警報**：針路のズレが 10〜60 秒放置されると 4Chime ＋「針路、右(左)に旋回」音声。
  コース警報 Arc がピンク線 (TC) に到達すると鳴る。
  * 15° 未満のズレでは鳴らない。15° で 60 秒、90° 以上で 10 秒放置が条件。
    修正操作中は鳴らない。前回警報から 30 秒以内は再警報しない。GS が 2m/s 以下でも鳴らない。
* **電圧低下警報**：3.5V 未満で音声案内（60 秒に 1 回）。この警告のみ強制的に最低音量 60 で鳴る。
  * 画面モードにも無線モードにも依存せず鳴る。USB 充電中とリプレイ中は鳴らない。
  * **受信モードでは、機体（送信機）の電池低下も別の音声で知らせる**（`battery_low_sender.wav`）。
    本番では飛行中に交換できないが、試験飛行ではボートが先に気づいて降ろす判断ができる。
* **目的地確認**：目的地まで 100km 以上あると 120 秒に 1 回、確認を促す音声。

### バンク角警告と姿勢まわりの警報

* ロールの絶対値が 4 度を超えた状態が 1 秒以上続くと音声警報。
  2026 年大会の実測（45 分）では 3 回鳴る計算です（継続条件を付けないと 31 回鳴ってしまいます）。
  * 誤警報の連発を防ぐため、一度鳴ったら**ロールが 3 度未満に戻り、かつ 10 秒（音声の再生時間）経つまで**再警報しません。
    センサーのズレで 4 度超過が続いている場合は、時間が経っても鳴りません。
    起動時も「発報済み」の状態から始まるので、電源投入時点で既に 4 度を超えていても鳴りません。
* **待機中（静止・対地 1m/s 以下）は別建てで見張ります。** SET ROLL / SET PITCH からのズレが
  3 度を超えた状態が 60 秒続くと音声で知らせます（2 分に 1 回上限）。自動ロールトリムは対地 3m/s 超で
  しか働かず地上では動かないため、マウントのズレを直せる唯一のタイミングを別の仕組みで補います。
* **マウントから外すと検出します。** ロールかピッチが 30 度（右バンクのみ 40 度）を超えると
  「手に持って外した」とみなし、次に APPLY するまで地図と設定画面に赤で警告を出します。
  この状態は SD に保存され、電源を切って充電しても保持されます。
* 同じ理由で **Roll trim during flight**（直進中のロール自動トリム、2 ページ目）があります。
  直進が 60 秒続くごとに評価し、**2 回続けて同じ向きに 0.5 度以上**のズレが出たときだけ
  0.5 度ずつゼロへ寄せます（累積上限 5 度）。2 回の一致を要求するのは、60 秒窓の平均ロールが
  実測で std 0.27 度ばらつき、1 回だけの判定ではノイズで補正してしまうためです。
  補正量は `log.txt` に記録されます。旋回中は一切働かないので、真のバンクは消えません。
* どちらも設定画面で OFF にできます。OFF にすると IMU / ESKF 行の丸がオレンジになります。

### 無線（PONS Link）関連（v7〜）

* 起動時に「送信機モード」「受信機モード」を読み上げ。無線 OFF なら無音。
* ミラー ⇄ NO SIGNAL の切り替わりを音で通知。復帰は短い和音、喪失は音声。
* 目的地を送信側に合わせて自動変更したとき、音声で通知。
* 送信機が 2 台いることを検出したとき、低音 3 回＋音声（設定ミスは飛ぶ前に気づく必要があるため）。
* CH / SF / Group を変更して設定画面を出たとき、設定一致の確認を促す音声。
* 無線モジュールが応答しないとき、音声。SD カードが無くても代替トーンが鳴ります。
* **機体の電池が低下したとき、受信側で音声**（60 秒に 1 回）。受信が切れれば止まります。
* 機体の SD / IMU / 較正未適用の異常は、立ち上がりで低音 2 回のみ（内訳は WIRELESS 画面）。

## 大会本番での使い方（Auto 10km モード）

* 目的地はパイロンではなく **PLATHOME** を選択し、Navigation Mode を **Auto 10km** にする。
* 自動で FLY AWAY（表示は `10K AWAY`）で始まる。プラットホーム上や上昇中はプラットホームから
  離れる方角（南東）を指すが正常で、数秒飛べば北西方面の指示に変わる。
* このモードはパイロンへは誘導せず、**プラットホームから離れる最短距離の方角（マゼンタ線=TC）** に
  誘導する設計。風は考慮していない。
* パイロンに向かいたい場合は、画面上の北パイロン・南パイロンへの線と True Track (TT) を見て
  パイロット自身が判断する。**2026 ルール**ではプラットホームから各パイロンへの TC はそれぞれ
  **328°（北）** と **258°（南）**（真方位。`navdata.h` の座標から計算した値）。
* 目的地から 10.475km 離れると自動更新音が鳴り `10K INTO` に切替。以降はパイロンを旋回したかに
  関係なくプラットホームへ戻る警告が出るので、**目視で折り返しを終えるまではコース警報を無視する**。
* 復路で目的地から 1.5km 以内に入ると再び `10K AWAY` に切替。同様に警告を無視して目視で
  1km パイロンを探して旋回する。
* 実際のパイロン位置は目安の 10.975km 円からズレる（2025 大会では 5km 通過で膨らんだ）。
  6km 過ぎたあたりから目視で探すこと。
* 目的地の `N_PILON` / `S_PILON` は、飛行中に急遽反対側のパイロンへ向かう場合に FLY INTO で
  直接誘導するためのもの（主にボート側での操作を想定）。
* 折り返しの状態（10K AWAY / 10K INTO）は SD カードに保存することで保たれます。飛行中/乗船中に
  再起動しても、直前のモードに復帰し、再開します。10K INTO のままプラットホームで電源を入れた場合には
  「1.5km 以内なら AWAY」のルールで自動的に復路→往路へモードが切り替わります。
  このとき目的地が変更された警告音声が鳴りますので、AWAY か INTO か正しいモードか確認を促します。

## 設計上の留意事項

使用者（パイロット/ボートマン）に向けた留意事項は、ここには記載しません。Google Docs の説明書を確認してください。

* 方位はすべて真方位（True）で、磁方位を廃止しました。機体に磁気コンパスを載せない方針になったため、
  磁方位と真方位が混在する意味が無くなったからです。
* **方位の精度は対地速度に依存する。** 移動速度が遅いと方位が大きく変化しやすい。
  徒歩ではばらつくが、ジョギング (3m/s) 以上で安定する。
* **航路 (TRACK) 警報が鳴っても、すぐに画面を注視しないこと。** 警告音は航路変化＝姿勢変化を
  知らせている。まずバンクなど機体姿勢の安定が最優先。姿勢が落ち着いてから修正方向・修正量の確認に使う。
* 稼働時は捕捉衛星数が 10sats 以上（緑色）、`sAcc: 0.2m/s` 以下になっていることを確認するとよい。
* パイロン座標は 2026 ルールに合わせてありますが、現実のパイロン位置はズレることがあるようです
  （SD カードで上書きできます。後述）。

### 自作の手順

工夫して外注費を節約すれば１個あたり 1 万円と 10 時間程度の作業時間で作れそうですが、
時短と確実性を優先し JLC にて PCBA での発注を強く勧めます。PCBA を使うと１個あたりの材料費は約 2 万円です。
電子工作（PCBA とリフロー含む）経験者でないと苦戦すると思いますが、各自の責任で自作する場合は次の手順で作れます。

1. **JLCPCB に基板を 3 種類発注します。**
   * KiCad の JLCPCB プラグインを使うと、production フォルダに発注に必要な zip ファイル等が生成されます。
     kicad フォルダに 3 つプロジェクトがあります。
   * `mainboard` は PCBA Standard で片面発注をお勧めします。手で実装するには困難なパーツが多いです。以下推奨設定PCB推奨発注設定
     * 軽量化とコスト削減：0.8mm,FR4 TG135,OSP
     * インピーダンス：JLC04081H-3313
     製造費の削減のため手実装が難しいパーツは裏面に集中させ、表面は手実装がしやすいパーツのみにしています。
     1 枚あたり約 1.4 万円になります。
     かなり工夫して手作業を増やせば 1 枚あたり約 5 千円に減らせますが作業時間が著しく増えてしまいます…。
   * `GNSSboard_SAM-M10Q` は Economy で発注し自身で実装ができます。節約できます。
     ただし SAM-M10Q はリフローが必要です。
   * `FPC` も JLCPCB で発注してください。ガーバー出力時には、必ず Stiffener も出力してください。
2. **Digikey・マルツ・秋月電子通商で部品を発注します**（→ 下の表）。
3. **基板が到着したら、残りの部品を手実装します。**
   * `mainboard` の `U12` E220-900T22S(JP) は、技適対応パーツが JLC にないため手実装。
     アンテナ (TX915-FPC-4510) は IPEX コネクタへ接続し、**カーボンや金属の陰にならない位置**へ固定します。
   * `mainboard` の `U6`,`U7` CUS-12TB Switch は、定格電流の都合で JLCPCB にないパーツのため手実装。
   * `GNSSboard_SAM-M10Q` のパーツ（リチウム二次電池・GNSS モジュール・コンデンサ・抵抗）は全て手実装。
     その際、SAM-M10Q は最初に**リフロー**してください。
4. `case_3Dmodel` にあるケースを 3D プリントします。
5. mainboard にリチウム電池 (860mAh) を接続します。mainboard をプラネジでケースに固定し、
   mainboard と GNSSboard_SAM-M10Q を FPC で繋ぎます。GNSSboard を隙間に固定します。
   アンテナを右側面の適当な部分に固定します。

### PCBA とは別に発注する部品（v7）

## SD カードの構成

| 場所 | 中身 |
|---|---|
| ルート直下 | **設定ファイルだけ**（`settings.txt` / `mapdata.csv` / `destinations.csv` / `override_pilon_coordinate.csv` / `logo.bmp` / `wav/`） |
| `data/` | 自機の飛行 CSV。**過去大会のデータもここに置きます** |
| `received/` | 無線で受け取った機体のログ（受信モードのときだけ） |
| `imu_replaydata/` | 姿勢（ESKF）の記録 |
| `imuraw/` | 生 IMU のバイナリ |
| `euler/` | 0.93 以前の姿勢ログ（読み込みのみ） |

リプレイ対象は `data/` と `received/` です。

> **v6 以前のカードから移行する場合**：ルート直下にある飛行 CSV を `data/` フォルダへ移動してください。
> 移動しないとリプレイ一覧に出てきません。

microSD カードスロットはバネ式です。取り出す時は指で押し込めばカチッと音がして取れます。

### ログの記録項目

* **`data/` の飛行 CSV**（例：`data/2026-03-26_1519.csv`）：2Hz
  ```
  latitude, longitude, gs, TrueTrack, GNSS_Altitude, KF_Altitude, KF_Vspeed, pressure, voltage, numsat, date, time
  ```
  * `GNSS_Altitude` は GNSS のみ。`KF_*` は Kalman filter による推定（MS5611+BNO085+GNSS 融合）。
* **`imu_replaydata/`**（例：`imu_replaydata/20260324.txt`）：5Hz。
  ```
  time, roll, pitch, yaw, pitch_avg, roll_trim, yaw_acc95, wind_mps, wind_dir
  ```
  * ESKF の結果＝**画面に出ていた値そのもの**。リプレイ時にこれを読んで、そのとき画面に何が出ていたかを再現します。
  * 列名で解釈するので、後から列を足しても古いファイルが読めなくなることはありません。
* **`imuraw/`**（例：`imuraw/20260324.bin`）：生 IMU の 28 バイト固定長バイナリ。
  ジャイロ・加速度（各 50Hz）、地磁気（10Hz）、GNSS 速度（2Hz）。PC 側の解析は `tools/imulog/` を参照。
* **`euler/`**：**0.93 以前**の形式（`time, roll, pitch, yaw`、BNO085 由来）。現在は書き出しません。
  過去のログをリプレイするために読み込みだけ対応しています（`imu_replaydata/` が無い日はこちらを探します）。
* **`received/`**（v7〜）：**受信モードのときだけ**、無線で受け取ったテレメトリを記録します。
  列は飛行 CSV と同じ並びで、末尾に `rssi, seq, age_ms` と姿勢・風が付きます。
  姿勢の列名は `imu_replaydata/` と同じにしてあるので、機体の SD が失われてもこちらで ESKF の解析ができます。
  * **自機の GNSS は混ぜません。** 無線で得た情報だけを置きます。
  * これによりフライトログが二重化されます。機体が着水して SD が読めなくなっても、ボート側に同じ航跡が残ります。
* **`/log.txt`**：起動からの秒数、電圧、センサー類の初期化結果や GNSS 精度などのイベントログ。
  60 秒ごとに電圧・CPU 温度・センサーの受信レートを記録し、無線が有効なときは
  **通信レポート**（受信数・取りこぼし・RSSI）も残します。
  ```
  0:SD INIT
  2:BNO085 init OK
  2:MS5611 init OK
  2:VARIO: BNO085+MS5611 Kalman fusion enabled
  4:GPS TIME: 2026-03-26 06:16:52 UTC
  6:SETUP DONE Battery: 4.15V
  6:Initial airdata: Temp=33.18 C, Press=1009.49 hPa, Alt=31.4 m
  60:volt=4.15V cpu=41.2C --:-- JST      ← 測位前は時刻を書かない
  120:volt=4.14V cpu=42.0C 15:18 JST
  148:GPS FIXED fix=3 sats=0 hAcc=60.2m
  1303:ACC hAcc=1.4m vAcc=1.9m sAcc=0.19m/s fix=3 sats=21
  ```
  * 時刻は **GNSS の日時が確定してから**しか書きません。確定前は `--:--` になります
    （以前は 0 時として扱っていたため、測位していなくても `09:00 JST` と記録されていました）。

### ログを Google Earth で可視化する方法

SD カード内の CSV ファイルを Google Earth に読み込むことができます。
`tools/logcsv2kml4earth.py` を使うと、指定フォルダにある複数の CSV をまとめて KML に変換できます。

### 目的地の追加（destinations.csv）

SD カードのトップディレクトリに `destinations.csv` を作成し、1 行に 1 目的地を
**名前（英語）, 緯度, 経度** のコンマ区切りで記述します。ヘッダー行は不要です。

```
KASAOKA03,34.495000,133.495000
TESTPOINT,35.412300,136.123413
```

* 名前は設定画面の Destination にそのまま表示されるので、画面幅に収まる短い英字が無難です。
* 緯度・経度は 10 進度（DD）。南緯・西経は負の値。
* `#` で始まる行と空行は無視されます。
* **内蔵の目的地（PLATHOME / N_PILON / S_PILON / TAKESHIMA）の後ろに追加されます。**
  同じ名前を書いても内蔵側は上書きされず、両方が並びます。
* 内蔵 4 件と合わせて最大 100 件（`MAX_DESTINATIONS`）。
* 読み込みは起動時の 1 回のみ。編集したら PONS を再起動してください。
* **次のいずれかに当てはまる行は捨てられます。** 打ち間違いが「(0,0) の目的地」として
  静かに登録されると、選んだときに誘導がギニア湾を指すためです。
  * コンマが足りない / 名前・緯度・経度のどれかが空
  * 緯度が ±90、経度が ±180 の範囲外
  * `0,0`（数値でない文字列も `0` になるため、ここで一緒に弾いています）
* 読み込み結果は `log.txt` に残ります（`DESTINATIONS: 6 added, 1 ignored` のような行）。
  **書いたはずの目的地が出ないときはここを見てください。**
* 配布 SD には `KASAOKA03` / `KASAOKA21` / `SHIRAHAMA34` / `SHIRAHAMA16` / `KARASU30` / `KARASU12` を初期登録済みです。

### パイロン座標の変更（override_pilon_coordinate.csv）

パイロンの座標は毎年変わり得ますが、大会直前にファームウェアを再ビルドするのは現実的ではありません。
SD カードのトップディレクトリに **`override_pilon_coordinate.csv`** を置くと、起動時にその値で上書きします。

```
# name,latitude,longitude
PLATHOME,35.294222,136.254333
N_PILON,35.377878,136.189907
S_PILON,35.274220,136.136183
PILON_1KM,35.297961,136.243624
```

* `#` で始まる行と空行は無視されます。
* 使える名前は `PLATHOME` / `N_PILON` / `S_PILON` / `PILON_1KM` / `TAKESHIMA` の 5 つ。
  **書いた地点だけが上書き**され、書かなかった地点はファームウェアの既定値のままです。
* `TAKESHIMA` は島そのものなので通常は書く必要がありません（仕組み上は指定できます）。
* 緯度・経度は 10 進度（DD）。緯度 ±90、経度 ±180 の範囲外や `0,0` は打ち間違いとみなして無視します。
* 適用結果は `log.txt` に記録されます（`PILON OVERRIDE S_PILON 35.274220 136.136183` のような行）。

**適用されたことの確認方法**：設定画面 → `Map data detail >` を開くと、`OSM(ODbL)` の内訳と
`FLSH` の一覧の間に、実際に使われている座標が表示されます。

```
COURSE SD OVERRIDE        ← 上書きが効いていればマゼンタで OVERRIDE、既定なら灰色で built-in
 PLA   35.294222, 136.254333
 NPIL  35.377878, 136.189907
 SPIL  35.274220, 136.136183
 1KM   35.297961, 136.243624
 TAKE  35.296584, 136.178054
```

上書きした座標は次の 2 つに同時に反映されます。

1. 設定画面で選べる内蔵目的地（`PLATHOME` / `N_PILON` / `S_PILON` / `TAKESHIMA`）
2. 地図上に描かれるパイロンのアイコンと、プラットホームからの基準線

なお **Auto 10km モードの折り返し判定はパイロン座標を使いません。**
「選択中の目的地（通常は PLATHOME）からの距離」で判定するので、影響するのは `PLATHOME` の座標だけです。

恒久的な変更としては [navdata.h](navdata.h) の `#define`（`PLA_*` / `PILON_NORTH_*` /
`PILON_SOUTH_*` / `PILON_1KM_*` / `TAKESHIMA_*`）を直してビルドし直すのが正しい手順です。
SD での上書きは、ビルドが間に合わない場合の運用手段という位置づけです。

### 地図データ

日本地図および琵琶湖周辺（沖島・竹生島・多景島など）の地形は、
**OpenStreetMap から生成したベクタ地図をファームウェアの FLASH に内蔵**しているため、
SD カードが無くても表示されます（`src/flashdata/vectormap_data.cpp`、`tools/vectormap/build_vectormap.py` で生成）。

* v6 の途中（0.93）で、Google Map API の bmp タイルを SD カードから読む方式は**廃止**しました。
  SD の読み出し待ちが無くなり、拡大率によらず描画が軽くなっています。
* 設定画面の `Map data detail >` で、FLASH 内蔵地図と SD (`mapdata.csv`) から読み込んだ地図の一覧を確認できます。
* Map data © OpenStreetMap contributors（ODbL 1.0）

#### 追加地図（独自地図）の作り方

独自地図とは、SD カードから読み込んだ緯度経度の列を地図（線）として表示する機能のことです。色の指定が可能。

1. Google Earth で PATH を作成し KML ファイルをダウンロード。**PATH の名前は英語で登録**してください。
2. `tools/kml_to_mapcsv.py` で KML から `mapdata.csv` を生成。
3. `mapdata.csv` を SD カードのトップディレクトリに配置。

**PATH 名の 1 文字目で線の色が決まります**：`r`=RED / `o`=ORANGE / `g`=GRAY / `m`=MAGENTA / `c`=CYAN / `b`=BLUE。
該当色がない場合は黒。例：`b_river` と指定すれば青色の線になります。

### WAV 音声ファイルの変更

16kHz、Unsigned 8bit PCM、メタ情報なしの WAV ファイルが再生できます。
書き出しには Audacity を推奨します。また設定から品質・ディザリングを「無し」にしてください。
これをしないとノイズが入ります。ファイル長さは関係ありません。

SD カードの `wav/` に置く、使用ファイル名は次のとおりです。

| 分類 | ファイル名 |
|---|---|
| ナビゲーション | `track.wav` / `course_left.wav` / `course_right.wav` / `destination_change.wav` / `destination_toofar.wav` / `fixed.wav` |
| 姿勢（ESKF） | `bank_warning.wav`（バンク角警告）/ `guide_eskf_setting.wav`（IMU/ESKF 画面に入ったときの注意案内）/ `eskf_apply_done.wav`（較正完了）/ `roll_check.wav`・`pitch_check.wav`（待機中のロール・ピッチのズレ）/ `change_setroll_caution.wav`（SET ROLL を 0 以外にしたときの警告） |
| 無線（PONS Link） | `sender_mode.wav` / `receiver_mode.wav` / `link_no_signal.wav` / `link_no_module.wav` / `link_dup_sender.wav` / `link_override_dest.wav` / `link_setting_changed.wav` / `battery_low_sender.wav`（機体の電池低下を受信側で知らせる） |
| その他 | `battery_low.wav` / `opening.wav` |
| ネタ | `matane.wav` / `arigato.wav` / `baibai.wav` / `makenna.wav` / `tsuyoi.wav` |

## 着水（水没）後の処理

1. 分解して取れる水分をすべて拭き取り、ネジのサビを除去する。
2. バッテリー端子と TFT 端子を取り外し、可能な範囲で拭いた後エタノール洗浄する。
   バッテリーはテープと回路部分を分解洗浄し、テープ保護して戻す。
3. 乾燥剤を入れたジップロックで TFT 内部などの水分を抜く（湿度 20% で 2〜3 日放置推奨）。
4. DIP スイッチは内部で錆が発生し接触不良になる恐れがあるため交換推奨。
   GNSS バックアップのリチウム二次ボタン電池は腐食するので、交換を推奨。
5. バッテリーは基板部分をクリーンナップして保護しなおし。異常な電圧値の履歴がなければ再利用可。
