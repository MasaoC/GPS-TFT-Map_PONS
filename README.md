# PONS 概要/Abstract
 * 人力飛行機のパイロットが使いやすいことを目標とした航法装置（ナビゲーションシステム）です。琵琶湖上空を飛行するパイロットの支援をしています。Arduinoを使用し、TFTにGNSSマップや位置・速度・方位の情報を表示します。琵琶湖での鳥人間コンテスト用に特化しています。GPS/GNSS navigation for human-powered aircraft specialized for the Japan International Birdman at Biwako, Japan.
 * 大阪大学albatrossにて使用実績あり（2024追走ボート: v3, 2025追走ボート: v4, 2025機体搭載「白夜」: v5, 2026追走ボート: v6, 2026機体搭載「陽還」: v6 β）。2025年大会優勝。
   * **v7 はまだ実戦投入していません。**基板製作中で、実結線試験もこれからです。
 * 3Dプリントケース及び基板データ(KiCad)あり。ケースは、PLA_LWが軽量化でオススメです。
 * 最新のソフトウェアバージョンは **0.960**（Build 20260905）です。
 * **v7 から、機体とボートを結ぶテレメトリ無線「PONS Link」を搭載しました。**同じ機体を 3 台つくり、
   設定で送信機（機体 1 台）と受信機（ボート／プラットフォーム 2 台）を切り替えます。
   パイロットに出ている航法画面を、ボート側でそのまま再現できます（後述）。
   * **飛行ログの冗長化。** 機体が水没・ロストしてもデータを失いません。受信側は姿勢・風まで
     `received/` に記録するので、機体の SD が失われても ESKF の解析ができます。
   * **風の共有。** ボートの PONS 単体では風を推定できません（対気速度が測れないため）。
     機体で推定した風速・風向をダウンリンクすることで、**アシストするボートマンが風の状況を把握できます。**
   * **トリム量の共有。** 機体のピッチは刻々と変動しますが、その**平均値＝トリム量**は
     平均対気速度に対応します。これをダウンリンクすることで、
     **ボートマンが的確なエレベータートリム量を指示できます。**
 * PONSデバイスの使い方や画面の見方などの詳細は、docsフォルダに説明書（PDF）があります。画面写真付きで説明されているため、READMEより詳しい情報が載っています。**ただし現在のPDFは Software 0.916 版**で、0.93 以降の地図のベクタ化・0.94 の姿勢表示は反映されていません。
 * PONS for HPA = Pilot Oriented Navigation System for Human-powered aircraft = 人力飛行機用パイロット向けナビゲーションシステム
 * 地図データは OpenStreetMap から生成した**ベクタ地図をファームウェアに内蔵**しています（`src/flashdata/vectormap_data.cpp`）。SDカードが無くても地図が出ます。
   * v6 の途中（0.93）で、Google Map API の bmp タイルをSDカードから読む方式は**廃止**しました。SDの読み出し待ちが無くなり、拡大率によらず描画が軽くなっています。
   * Google Earth で作ったPATHを `mapdata.csv` としてSDに置けば、内蔵地図に**追加**で重ねられます（後述）。
 * 日本地図・琵琶湖（沖島・竹生島・多景島）などは、プログラムに事前登録されています。パイロン座標は2025ルールに合わせてありますが、現実のパイロン位置はズレることがあるようです。

# スペック (v7)
 * TFT: 2.8インチ 1000ニト。スイッチによる輝度調整可能。
 * GNSS位置精度: 1.5m、速度精度: 0.05m/s、更新レート: 2Hz、Cold start 23秒
 * 気圧センサー MS5611 搭載。気圧を2HzでSDカードへ記録。
 * モーションセンサー BNO085 **標準搭載**（v6 では 2 個中 1 個の β 試験版でした）。
   GNSS速度を援用した姿勢推定（ESKF）でピッチ・ロールを表示。
 * **無線 PONS Link 搭載**：920MHz LoRa（E220-900T22S(JP)、技適取得済・免許不要）。
   1Hz でテレメトリを送信。実測到達距離 **350m**（要求 200m の 1.75 倍）。
   既定は BW500kHz / SF8 で、1 回の送信は 98.4ms・平均 4.3mA。設定画面でチャンネル(CH0-12)と SF(7-11)を変更できます。
 * バッテリー: 860mAh。USB Micro-Bで充電（5V1Aで十分、空から満充電まで2〜3時間）。
 * FLASH 16MB（W25Q128）。ベクタ地図・起動ロゴ・フォントを内蔵。

 * 重量・バッテリー持続時間は **v7 実機での計測待ち**です。参考値（v6 β版）は 62.4g / 高輝度 約3時間 / 低輝度 約12時間。
   PONS Link は受信モードで常用すると +8.2mA（低輝度で 1 時間ぶん短くなる計算）、送信モードは +4.3mA です（SF8・1Hz）。
   受信モードのスリープは今後の実装予定で、実装すれば 8.2mA より下がります。

## v7での主な変更点（v6から）
 * **PONS Link（機体⇄ボート テレメトリ無線）を追加。**920MHz LoRa。詳細は [docs/pons_link.md](docs/pons_link.md)。
   基板到着後の立ち上げ試験手順は [docs/pons_link_bringup.md](docs/pons_link_bringup.md) にあります。
 * **BNO085 を標準搭載**にし、接続を i2c から **SPI** へ変更。v6 では BNO085 と気圧計が i2c を共用しており、
   BNO085 のクロックストレッチでバスがロックすると気圧計も道連れになる故障モードがありました。
   SPI にはクロックストレッチが存在しないので構造的に解消します（設定で i2c へ戻すことも可能）。
 * **FLASH を 16MB** に拡張。

# ハードウェアの自作
 工夫して外注費を節約すれば１個あたり1万円と10時間程度の作業時間で作れそうですが、時短と確実性を優先しJLCにてPCBAでの発注を強く勧めます。PCBAを使うと１個あたりの材料費は約2万円です。電子工作（PCBAとリフロー含む）経験者でないと苦戦すると思いますが、各自の責任で自作する場合は次の手順で自作できます。

 1. JLCPCB に基板を3種類、発注します。
    * 発注する際は、Kicad のJLCPCBのプラグインを使います。productionフォルダに発注に必要なzipファイル等が生成されます。kicadフォルダに3つプロジェクトがあります。
    * mainboard は PCBA Standardで両面発注をお勧めします。手で実装するには困難なパーツが多いです。これが一番高額で1枚あたり約1.4万円になりますが、片面発注かつExtended部品を減らせば1枚あたり約5千円に減らせます。(作業時間が増えます...)
    * GNSSboard_SAM-M10Q は Economyで発注し自身で実装ができます。節約できます。ただしSAM-M10Qはリフローが必要です。
    * kicadフォルダの、FPC もJLCPCBで発注してください。ガーバー出力時には、必ずStiffenerも出力してください。
 2. Digikey・マルツ・秋月電商 で必要な部品の発注
    * JLCPCBのPCBAでは実装できない部品を発注します。**部品と注文番号の一覧は下の表**を参照してください。
    * Digikeyにて、TFT、スイッチ、コネクタ、ネジ、スピーカー などを発注します。
    * マルツにて、LoRaモジュール、860mAh電池、LoRaアンテナ を発注します。
    * 秋月電商にて、リチウム２次電池とショットキーダイオードを発注します。
 3. 基板が到着したら、残りの部分実装
    * mainboard、U12 E220-900T22S(JP) は、技適対応パーツがJLCにないため手実装してください。
      アンテナ(TX915-FPC-4510)は IPEX コネクタへ接続し、**カーボンや金属の陰にならない位置**へ固定します。
    * mainboard、U6,U7 CUS-12TB Switch は、定格電流の都合でJLCPCBにないパーツのため手実装してください。
    * GNSSboard_SAM-M10Q のパーツ(リチウム２次電池,GNSSモジュール、Capacitor,Resistor)を全て手実装してください。その際、SAM-M10Qは最初に**リフロー**してください。
 4. case_3Dmodel にあるケースを3Dプリントします。
 5. mainboardにリチウム電池(860mAh)を接続します。mainboardをプラネジでケースに固定し、mainboardとGNSSboard_SAM-M10QをFPCで繋ぎます。GNSSboardを隙間に固定します。アンテナを右側面の適当な部分に固定します。

## 姿勢推定（ESKF）
 BNO085 内蔵の姿勢推定は、加速度計が測る「比力」を鉛直とみなすため次の2つで系統的に誤ります。

 * **定常旋回中はロールを過小評価する**（協調旋回では比力の横成分が厳密に0になり、加速度計にバンクが見えない）
 * **加減速中はピッチがずれる**

 そこで GNSS の速度を観測に入れた自前の姿勢推定（誤差状態カルマンフィルター＝ESKF）を実装しました。
 対地加速度が分かると比力から遠心力・加減速分を差し引けるので、真の重力方向が求まります。
 車載実測での単位前後加速度あたりのピッチ誤差は **BNO085 4.4〜5.6 → ESKF 0.2〜0.5 deg/(m/s²)**。
 傾斜台での絶対精度は **-0.46〜-0.63度**、直交軸への漏れは 0.6度以下でした。

 ## Roll/Pitch/Yaw 機能の一括ON/OFF
 IMU/ESKF 画面の `Roll/Pitch/Yaw func` を OFF にすると、姿勢に関する機能が全て止まり、
 見た目も動作も ESKF 導入前と同じ状態に戻ります（設定はSDに保存されます）。対象は次のとおり。

 * 表示：平均ピッチ / P / R / Rtrim / 風の矢印と風速 / ESKFヨー / 自機アイコンの機首向き / 偏流点線
 * 警報：バンク角警告、待機中のロール・ピッチチェック、マウント外れ検出
 * 処理：直進中のロール自動トリム、風推定、`imu_replaydata/` への記録

 ESKF の計算自体は止めません（2ページ目の診断表示を生かすためと、ONに戻した瞬間から使えるようにするため）。

 ## 風の推定
 「ピッチ0度で7.0m/sで飛ぶ」という設計前提からピッチ→対気速度を引き、
 `風ベクトル = 対地速度ベクトル - 対気速度ベクトル` で求めます（対気速度の向き＝機首方位と仮定）。
 対気速度の換算表は機体依存なので `settings.h` の `AIRSPEED_*` で変更できます
 （既定：ピッチ+5度で5.8m/s、0度で7.0m/s、-4度で9.0m/s、間は線形補間、範囲外はクランプ）。

 * **直進中しか更新しません。** 旋回中の人力飛行機は横滑りが大きく、横滑り角 beta があると
   風速の誤差が `対気速度 × sin(beta)` になります（beta=30度なら3.5m/s）。旋回中は直前の値を保持します。
 * 表示されるまでに**直進が累計10秒**必要です（`WIND_LPF_SEC`）。
 * ヨー精度の95%値が10度未満のときだけ表示されます。条件を満たさない間もその値（`Y95`）は常に見えます。

 * **ヨーは対象外です。** 対気速度センサーが無いため風によるカニ角を原理的に補正できません。
   またヨーは水平加速度がある間しか可観測にならないので、等速直進が続くと精度が落ちます。
   信頼できないと判定した間はグレー表示にし、自機アイコンも機首方向へ回しません。

# 取り扱い上の注意
 * **リチウム電池内蔵のため高温禁止。** 真夏の車内・ダッシュボードへの放置禁止。高温密閉環境での充電は発火の恐れあり。落下や踏みつけなど強い衝撃を与えないこと。
 * **防水ではない。** 雨ざらしにしないこと。多少の水滴は許容だが拭き取ること。
 * **天面付近に金属・カーボン・金属フィルムを配置しないこと。** GNSSアンテナが天面にあるため、信号を受信できず使用不能になる。取り付け位置・固定方法・フェアリング材質に注意。
 * **偏光サングラス禁止**（画面が見えなくなる）。偏光でないサングラスはOK。
 * リチウム電池入りのため廃棄しないこと。不要になったら開発者へ返却してください。

# 電池・充電
 * `USB` 表示 = USB接続中でUSBから給電。充電完了は右上の赤LED消灯で確認。
 * 緑 `XX%` = 3.8V以上（50%以上）。マゼンタ = 3.8V未満。赤 = 3.5V以下（約12%以下、充電推奨）。
   * 4.2V=100%、3.4V=0% として電圧をそのまま%表示。高輝度モードでは充電直後でも100%を切るが正常。
 * 赤表示から20分程度で過放電保護が働き電源が落ちる。**その後も電源ONで放置すると保護回路がFailし電池が恒久的に使用不能になる**（この場合は充電を試みず電池交換）。
 * 電圧低下の目安: 高輝度 -0.17〜-0.2V/h、低輝度 -0.06V/h。
 * 右上LEDが点滅 = バッテリー接続不良・エラー。左上LEDの赤常時点灯 = 不具合発生（開発者にコンタクト）。赤点滅 = GNSS信号ロスト。

# PONS Link（機体⇄ボート テレメトリ無線）

 同じファームウェアの PONS を **3 台**つくり、SDカードの設定で役割を決めます。

 | 置き場所 | モード | 役割 |
 |---|---|---|
 | 機体 | TX | パイロットの航法装置。これが本番 |
 | 追走ボート | RX | 機体の画面を再現する。ボートマンが見る |
 | プラットフォーム | RX → 途中で OFF | **予備機**。機体の PONS が壊れた／電池切れのとき TX へ切り替えて載せ替える |

 目的は **パイロットに出ている航法画面をボート側でそのまま再現すること**です。
 地図・対地速度・高度・姿勢・風・平均ピッチまで、送信側の画面がそのまま映ります。
 コース警報やバンク角警告も、受信側が**受け取った値から自分で計算し直して**鳴らすので、
 機体側と同じタイミングで同じ音が出ます。

 これによって次の 3 つが得られます。

 1. **飛行ログの冗長化。** 機体の水没・ロストでデータを失いません。受信側は姿勢・風まで
    `received/` に記録するので、機体の SD が失われても ESKF の解析ができます。
 2. **風の共有。** ボートの PONS 単体では風を推定できません。機体で推定した風速・風向を
    受け取ることで、**アシストするボートマンが風の状況を把握できます。**
 3. **トリム量の共有。** 機体のピッチは変動しますが、その**平均値＝トリム量**は平均対気速度に
    対応します。これを見て**ボートマンが的確なエレベータートリム量を指示できます。**

 プラットフォーム機は機体が離れると当然ロストします。**これは想定どおり**で、ロストを画面と音声の
 両方で知らせたあと、人が OFF にする運用です。予備機である以上、電波が来ているかどうかは
 常にはっきり分かるほうがよいと考え、自動で静かにする仕掛けは入れていません。

 * **通信は下り一方向だけ**で、ボートから機体へ返すものは何もありません。
   受信側の不具合が飛行中の機体へ波及する経路が**原理的に存在しません**。
   大会レギュレーション上も「操作には使えない」ことを設計で示せます。
 * **受信が10秒途切れると**「RECEIVER MODE. NO SIGNAL.」を表示し、自機の情報表示へ戻ります。
   このとき**バリオを含めて全機能が動きます**。万一受信機モードのまま離陸しても使えるようにするためです。
 * **受信モードは常に色付きの枠**を出します。数値の意味が「機体」と「自機」で入れ替わるため、
   どの画面にいても分かるようにしてあります。切り替わりは音でも知らせます。
 * 電池は `S50R40%` の形で**送信側と受信側の両方**を表示します。
 * 目的地とナビモードは**送信側に自動で合わせます**（RAM上のみ）。食い違うとコース警報だけが
   静かにずれるためです。上書きしたことは音声で知らせます。
 * **送信機が 2 台いる**（機体用とボート用の取り違え）と受信側が検出して警報します。
 * **受信したデータはリプレイできます。** リプレイ画面の `SOURCE` を `RECEIVED` に切り替えると、
   `received/` のログ（電源を入れるごとに 1 ファイル）を選べます。姿勢・風もそのまま再生され、
   再生中は `REPLAY RX` と表示されます。なお受信モード中はルートの飛行 CSV に**ボート自身の**
   データが記録されているので、画面に出ていなかったボート自身の画面もあとから再生できます。
 * **ボート自身の位置**を明るい緑の小さな点で地図に重ねます（受信中のみ）。地図は機体を中心に
   描かれるため、そのままではボートが地図上に存在しないためです。2m/s 以上で進んでいるときは
   進行方向へ短い線が伸びます。ボート自身の航法には v6 以前の機体を併用してください。
 * 地図の左上に**アンテナ本数（0〜3本）**を出します。ロスト時は 0 本の上に赤い×が重なります。
   本数は「感度限界からの余裕」で決めているので、SF を変えても意味が保たれます。

 ## 無線の設定
 | 項目 | 値 |
 |---|---|
 | モジュール | E220-900T22S(JP)（920MHz LoRa、技適取得済・免許不要） |
 | 帯域幅 / 拡散率 | 500kHz / **SF8**（設定で SF7〜SF11） |
 | チャンネル | CH0〜12（920.8〜923.2MHz） |
 | 送信出力 | 13dBm（20mW）。アンテナ 2dBi、EIRP 15dBm |
 | 送信周期 | 1Hz |
 | 1回の送信時間 | 98.4ms（SF8・65バイト。メーカーの送信時間計算表による） |
 | 消費電流 | 送信機 平均 4.3mA（瞬間 43mA）／受信機 8.2mA 連続（スリープは実装予定） |

 設定項目は `link_mode`（OFF / TX / RX）、`link_radio_ch`、`link_radio_prof`、`link_group` の 4 つです。
 `link_group` は同じ会場に別チームの PONS がいても取り違えないための識別子で、**既定は 0**。
 CH と SF が偶然一致すると他チームの機体を受信してしまうため、**0 以外を各機の SD に設定してください**
 （3 台とも同じ値）。グループ違いの電波を受けたときは「無信号」ではなく `GROUP n FOUND` と表示します。
 起動時に「送信機モード」「受信機モード」を**音声で読み上げます**。片方だけ読み上げると
 「何も言わない＝正常」と受け取られてしまうため、両方読み上げることで
 **無音が「無線OFF」を意味する**ようにしてあります。

 ## 実測（2026-09）
 | 条件 | 設定 | 到達距離 |
 |---|---|---|
 | 芝生（凹凸あり） | 500k SF5 | 約 100 m |
 | 同上 | 500k SF8 | 約 190 m |
 | **海辺・平坦なコンクリート・夜間** | **500k SF7** | **約 350 m** |

 * 環境雑音は熱雑音 +7dB（BW500kHz で約 −104dBm）。屋内外でほとんど変わりません。
 * **アンテナの置き方が拡散率より効きます。** 角度が 60°ずれると 6dB 失いますが、
   SF を 1 段上げても 2.5dB しか稼げません。アンテナは高く、偏波を揃えて設置してください。
 * **水面での挙動は未確認**です（試験はコンクリートと芝生のみ）。

 設計の詳細・データシートの落とし穴・電波法の扱いは [docs/pons_link.md](docs/pons_link.md) にまとめてあります。

# 機能 Detail.
 * 基本機能（画面の表示）
    * 画面上部：左に対地速度(m/s)。右の大きい枠は **平均ピッチ**（ラベル `Pavg`）。
      対地進路は地図を見れば分かるがピッチは他に得る手段が無いため、一番目立つ枠をこちらに使う。
      BNO085 非搭載機・姿勢機能OFF・平均が未収束のときは従来どおり真方位（ラベル `TT`）。
      対地速度は2.0m/s未満でグレー表示。左上に `GS` と `sAcc`（速度精度、色分け）。
    * 画面中央：地図（ファームウェア内蔵のベクタ地図 ＋ SDの `mapdata.csv`）の表示、TTの針の表示。
      右上の枠が `Pavg` のときは、画面中央上部に真方位を `TT 232` の形で表示する。
      * 旋回角速度表示（3秒平均 deg/sec）。2.0deg/s超えで着色、左右端に表示。
      * 旋回すべき修正方向の表示（赤矢印）。コースズレ15°以上で表示・点滅。
      * コース警報Arc：向かうべき方位(TC=True Course)への赤線円弧。10〜60秒放置で音声警報。
      * 過去の航跡は緑色の線で引かれる。最大500地点（約25km分）を表示。
      * 琵琶湖付近にいる場合、タケシマ・北パイロン・南パイロンに向けて自動で線が引かれる。パイロンが表示される。折り返し目安の10.975km円が描かれる。
      * NORTH UP / TRACK UP 切替対応。
      * 姿勢表示（BNO085搭載機のみ）：左下に上から順に
        **風ベクトルの矢印** → `W 1.5m/s`（風速）→ `Y95 4°`（ヨー精度の95%値）→
        `P`（瞬時ピッチ）→ `R`（ロール）→ `Rtrim`（自動ロールトリムの累積補正量）。
        平均ピッチはヘッダー右の大きい枠へ移したので、ここには出ません。
        * ロールがバンク角警告のしきい値（4度）を超えると**赤**。
        * ロールまたはピッチの絶対値が10度以上だと**グレー**（設置ミスを疑うべき値）。赤より優先。
        * `Rtrim` は累積が1.5度以上でオレンジ、3.0度以上で赤。
        * 風の矢印は**風が吹いていく方向**を指し、地図と向きが揃う。長さは固定で強さは色で表す
          （2m/s以下=緑 / 4m/s以下=青 / 超=紫）。
        * ヨーが著しく信頼できるとき（95%値<10度）、機首の先に**偏流角を示す点線**が出る。
        * 自機アイコンは、ESKFのヨーで機首を向けているとき**黒**、対地進路を向けているだけのとき**グレー**。
        * 較正が必要なときは `ESKF CALIBRATION REQUIRED!` を赤字で、
          ESKFが未収束のときは `ESKF Not ready` を表示。
      * 30度範囲表示：針の先の三角形（薄い線）が過去の針路から左右15度の範囲を示す。15度を超えるたびに三角形が更新され、警告音+「トラック」音声が鳴り8秒間点滅する。
    * 画面下部：時刻（JST）と 最大GS（過去5分・累計）と発生時刻。
      緯度・経度は v0.94 で削除した（飛行中に読む場面が無いため）。sAcc は左上へ移動。
    * 画面下部2：目的地コース(Magnetic Course)/目的地までの距離（km、直線距離）/ 捕捉衛星数（10以上で緑）/ 電池残量(%)
    * 画面最下部：目的地モード（FLY INTO / FLY AWAY / 10K INTO / 10K AWAY）/ 目的地名 / SD認識表示（正常=緑、エラー=赤）
    * 状態表示：`Acc: XXm`（水平位置精度1σ、10m以上のとき表示）、`Scanning GNSS/GPS Signal`（起動直後）、`Weak GNSS/GPS Signal`（衛星数0）、`No GNSS connection !!`（GNSS通信不可＝要再起動）
 * ロガー：緯度/経度/対地速度/時刻をSDカードへ保存（GPS位置捕捉時、1秒に2回）。気圧データも記録。
 * バリオメーター(MS5611)：昇降計。設定画面でボリューム0にすると無音・非表示。デッドバンドは±0.25m/s（BNO085+MS5611 の KF 融合時。MS5611 単独では±0.6m/s）。BNO085 が無い個体は精度が不十分なため無効、β版のみ使用可。
 * 設定画面（NAV画面でスイッチ長押しで入る。各行の右端の丸⚫︎が設定状態を示す。
   **緑**＝本番推奨設定、**赤**＝本番では不可（デモ/リプレイが有効など）、**オレンジ**＝本番でも許容だが既定から外れている。
   本番前に赤が無いことを確認すること）
    * 目的地の設定（PLATHOME, N_PILON, S_PILON, TAKESHIMA が本体登録済み。SDカードで追加可能。SDには SHIRAHAMA16 / SHIRAHAMA34 / KASAOKA03 / KASAOKA21 / BUSHITSU 等を初期登録済み。）
    * 向かうIntoモードか、離れるAwayモードか、目的地から10kmをひたすら往復する Auto10km モード(大会用）の選択
    * ボリューム / バリオメーターボリュームの調整
    * NORTH UP（北が上） / TRACK UP（進行方向が上） の設定
    * 地図の拡大率（Map scale）の変更。NAV画面ではボタンのダブルクリックでも変更可能（誤操作防止のためシングルクリックでは変わらない）。通常使用する zoom11 のときアイコンが緑、それ以外は赤。
    * デモモード（琵琶湖でそれっぽいデータを表示）
    * リプレイモード（SDカードに保存された**飛行CSVをそのまま再生**）。
      v5までのようにPythonでNMEAへ変換する必要はありません。列名で解釈するのでv5〜v6のログがそのまま使えます。
      静止区間を飛ばして再生する PLAY FLIGHT ONLY、再生速度 x1 / x2 / x20、
      再生元を切り替える SOURCE（FLIGHT = 自機のログ / RECEIVED = 無線で受けた機体のログ）の切替があります。
      **一覧の並びはファイル名順ではなく、SDカードへ書き込まれた順（ディレクトリの登録順）です。**
      過去大会のログなど上に出しておきたいものは、カードへ**最初にコピー**してください。
      設定用のCSVはルート直下にあり、リプレイ一覧は `data/` と `received/` しか見ないので、
      誤って選ぶ経路がそもそもありません。万一、飛行ログでないCSVを掴んだ場合は、
      音を鳴らして再生を取り消し、通常のGPSに戻ります。
    * GPSのコンステレーション表示（受信中衛星・受信したUBXフレーム）
    * 地図データ情報一覧表示 (FLASH + SD mapdata.csv)
    * SDカード内のファイル表示
    * バリオメーターの詳細（KFパラメーターの実行時調整）
    * IMU / ESKF 画面（BNO085搭載機のみ。2ページ構成。短押し=カーソル移動、長押し=実行）
      * 1ページ目は飛行前の点検手順の順に並べてある
        1. `SET PITCH`：「いま機体のピッチは何度か」の申告値（-3.5〜+2.0度、0.5度刻み）
        2. `SET ROLL`：同じくロールの申告値（±3.0度、既定0）。通常は0のままにする。
           横風でウィングロー保持のまま較正せざるを得ないときだけ使う。0以外はオレンジ表示＋音声で警告。
        3. `APPLY`：上の申告値で機体ゼロ点を較正。本番プラットホーム（-3.5度）でもその値を
           申告すれば正しく較正できる。**ボタンを離してから1秒後に実行される**
           （スイッチを押す力でマウント上のデバイスが傾くため）。飛行中は実行できない。
        4. `Roll/Pitch/Yaw func`：姿勢に関する機能の一括ON/OFF（後述）
      * 各行の右端に状態の丸が出る。画面右上の丸が緑にならない原因をここで辿れる。
        緑の条件は「ESKFが収束」「Roll/Pitch/Yaw funcがON」「Roll trim during flightがON」
        「自動トリムの累積が1.5度未満」の4つ。較正が必要なときは赤。
      * 2ページ目：センサー生値とESKFの内部状態（診断用）と、調整項目
        `Roll trim during flight` / `Wind estimate` のON/OFF（既定はどちらもON）
    * 設定はSDカードに保存・次回起動時に自動読込（DEMO/REPLAYモードは保存されない）。NAV画面のscale（拡大率）も保存される。
    * 画面下部にバッテリーの目安持続時間とCPU温度を表示。CPU55度（外気温35度）までは動作確認済み。2026年大会ではCPU最大48度。

# 警告音・警報
 * 旋回率 警告音：旋回率が2deg/sを超えるとピピと高音（v6では音程固定）。2.0m/s以下では鳴らない。
 * 航路(TRACK)警報：左右15°範囲を超えて航路が変わるとChime音+「Track！」音声。
 * 目的地自動更新音：Auto 10kmモードで10K AWAY↔10K INTO切替時に4Chime+音声。切替時に1回のみ。
 * コース警報：針路のズレが10〜60秒放置されると4Chime+「針路、右(左)に旋回」音声。コース警報Arcがピンク線(TC)に到達すると鳴る。
   * 15°未満のズレでは鳴らない。15°で60秒、90°以上で10秒放置が条件。修正操作中は鳴らない。前回警報から30秒以内は再警報しない。GSが2m/s以下でも鳴らない。
 * 電圧低下警報：3.5V未満で音声案内（60秒に1回）。この警告のみ強制的に最低音量60で鳴る。
 * 目的地確認：目的地まで100km以上あると120秒に1回、確認を促す音声。
 * **無線（PONS Link）関連**（v7〜）
   * 起動時に「送信機モード」「受信機モード」を読み上げ。無線OFFなら無音。
   * ミラー ⇄ NO SIGNAL の切り替わりを音で通知。復帰は短い和音、喪失は音声。
   * 目的地を送信側に合わせて自動変更したとき、音声で通知。
   * 送信機が2台いることを検出したとき、低音3回＋音声（設定ミスは飛ぶ前に気づく必要があるため）。
   * 無線モジュールが応答しないとき、音声。SDカードが無くても代替トーンが鳴ります。
 * **バンク角警告**（BNO085搭載機のみ）：ロールの絶対値が4度を超えた状態が1秒以上続くと音声警報。
   2026年大会の実測（45分）では3回鳴る計算です（継続条件を付けないと31回鳴ってしまいます）。
   * 誤警報の連発を防ぐため、一度鳴ったら**ロールが3度未満に戻り、かつ10秒（音声の再生時間）経つまで**再警報しません。
     センサーのズレで4度超過が続いている場合は、時間が経っても鳴りません。
     起動時も「発報済み」の状態から始まるので、電源投入時点で既に4度を超えていても鳴りません。
   * **待機中（静止・対地1m/s以下）は別建てで見張ります。** SET ROLL / SET PITCH からのズレが
     3度を超えた状態が60秒続くと音声で知らせます（2分に1回上限）。自動ロールトリムは対地3m/s超で
     しか働かず地上では動かないため、マウントのズレを直せる唯一のタイミングを別の仕組みで補います。
   * **マウントから外すと検出します。** ロールかピッチが30度（右バンクのみ40度）を超えると
     「手に持って外した」とみなし、次に APPLY するまで地図と設定画面に赤で警告を出します。
     この状態はSDに保存され、電源を切って充電しても保持されます。
   * 同じ理由で **Roll trim during flight**（直進中のロール自動トリム、2ページ目）があります。
     直進が60秒続くごとに評価し、**2回続けて同じ向きに0.5度以上**のズレが出たときだけ
     0.5度ずつゼロへ寄せます（累積上限5度）。2回の一致を要求するのは、60秒窓の平均ロールが
     実測でstd 0.27度ばらつき、1回だけの判定ではノイズで補正してしまうためです。
     補正量は `log.txt` に記録されます。旋回中は一切働かないので、真のバンクは消えません。
   * どちらも設定画面でOFFにできます。OFFにすると IMU / ESKF 行の丸がオレンジになります。

# 目的地の追加方法（destinations.csv）
 SDカードのトップディレクトリに `destinations.csv` を作成し、1行に1目的地を
 **名前（英語）, 緯度, 経度** のコンマ区切りで記述します。ヘッダー行は不要です。

```
KASAOKA03,34.495000,133.495000
TESTPOINT,35.412300,136.123413
```

 * 名前は設定画面の Destination にそのまま表示されるので、画面幅に収まる短い英字が無難です。
 * 緯度・経度は10進度（DD）。南緯・西経は負の値。
 * **内蔵の目的地（PLATHOME / N_PILON / S_PILON / TAKESHIMA）の後ろに追加されます。**
   同じ名前を書いても内蔵側は上書きされず、両方が並びます。
 * 内蔵4件と合わせて最大 100 件（`MAX_DESTINATIONS`）。
 * 読み込みは起動時の1回のみ。編集したらPONSを再起動してください。
 * 行が壊れている（コンマが足りない等）場合、その行は無視されます。

# パイロン座標の変更（override_pilon_coordinate.csv）
 パイロンの座標は毎年変わり得ますが、大会直前にファームウェアを再ビルドするのは現実的ではありません。
 SDカードのトップディレクトリに **`override_pilon_coordinate.csv`** を置くと、
 起動時にその値で上書きします。ファームウェアの変更は不要です。

```
# name,latitude,longitude
PLATHOME,35.294222,136.254333
N_PILON,35.377878,136.189907
S_PILON,35.274220,136.136183
PILON_1KM,35.297961,136.243624
```

 * `#` で始まる行と空行は無視されます。
 * 使える名前は `PLATHOME` / `N_PILON` / `S_PILON` / `PILON_1KM` / `TAKESHIMA` の5つ。
   **書いた地点だけが上書き**され、書かなかった地点はファームウェアの既定値のままです。
 * `TAKESHIMA` は島そのものなので通常は書く必要がありません（仕組み上は指定できます）。
 * 緯度・経度は10進度（DD）。緯度 ±90、経度 ±180 の範囲外や `0,0` は打ち間違いとみなして無視します。
 * 適用結果は `log.txt` に記録されます（`PILON OVERRIDE S_PILON 35.274220 136.136183` のような行）。

 **適用されたことの確認方法**：設定画面 → `Map data >` を開くと、`OSM(ODbL)` の内訳と
 `FLSH` の一覧の間に、実際に使われている座標が表示されます。

```
COURSE SD OVERRIDE        ← 上書きが効いていればマゼンタで OVERRIDE、既定なら灰色で built-in
 PLA   35.294222, 136.254333
 NPIL  35.377878, 136.189907
 SPIL  35.274220, 136.136183
 1KM   35.297961, 136.243624
 TAKE  35.296584, 136.178054
```

 上書きした座標は次の2つに同時に反映されます。

 1. 設定画面で選べる内蔵目的地（`PLATHOME` / `N_PILON` / `S_PILON` / `TAKESHIMA`）
 2. 地図上に描かれるパイロンのアイコンと、プラットホームからの基準線

 なお **Auto 10km モードの折り返し判定はパイロン座標を使いません。**
 「選択中の目的地（通常は PLATHOME）からの距離」で判定するので、影響するのは `PLATHOME` の座標だけです。

 恒久的な変更としては [navdata.h](navdata.h) の `#define`（`PLA_*` / `PILON_NORTH_*` /
 `PILON_SOUTH_*` / `PILON_1KM_*` / `TAKESHIMA_*`）を直してビルドし直すのが正しい手順です。
 SDでの上書きは、ビルドが間に合わない場合の運用手段という位置づけです。

# 追加地図（独自地図）の作り方
 1. Google EarthでPATHを作成しKMLファイルをダウンロード。PATHの名前は英語で登録。
 2. `kml_to_mapcsv.py` でKMLから `mapdata.csv` を生成。
 3. `mapdata.csv` をSDカードのトップディレクトリに配置。
 * PATH名の1文字目で線の色が決まる: `r`=RED, `o`=ORANGE, `g`=GRAY, `m`=MAGENTA, `c`=CYAN, `b`=BLUE

# WAV音声ファイルの変更
 16kHz、Unsigned 8bit PCM、メタ情報なしのWAVファイルに対応。Audacity推奨。
 使用ファイル名: `track.wav`, `course_left.wav`, `course_right.wav`, `destination_change.wav`, `battery_low.wav`, `destination_toofar.wav`, `opening.wav`, `fixed.wav`, `matane.wav`, `arigato.wav`, `baibai.wav`
 BNO085搭載機のみ: `bank_warning.wav`（バンク角警告）, `guide_eskf_setting.wav`（IMU/ESKF画面に入ったときの注意案内）, `eskf_apply_done.wav`（較正完了）, `roll_check.wav` / `pitch_check.wav`（待機中のロール・ピッチのズレ）, `change_setroll_caution.wav`（SET ROLL を0以外にしたときの警告）

# SDカードのログ記録項目
 **SDカードの使い分け**（v7〜）

 | 場所 | 中身 |
 |---|---|
 | ルート直下 | **設定ファイルだけ**（`settings.txt` / `mapdata.csv` / `destinations.csv` / `override_pilon_coordinate.csv` / `logo.bmp` / `wav/`） |
 | `data/` | 自機の飛行CSV。**過去大会のデータもここに置きます** |
 | `received/` | 無線で受け取った機体のログ（受信モードのときだけ） |

 リプレイ一覧は `data/` と `received/` しか見ません。設定用のCSVを誤って再生対象にしてしまう経路が構造的にありません。

 > **v6以前のカードから移行する場合**：ルート直下にある飛行CSVを `data/` フォルダへ移動してください。
 > 移動しないとリプレイ一覧に出てきません。

 * `data/`フォルダのCSV（例：`data/2026-03-26_1519.csv`）
   `latitude, longitude, gs, TrueTrack, GNSS_Altitude, KF_Altitude, KF_Vspeed, pressure, voltage, numsat, date, time`
   * `GNSS_Altitude` はGNSSのみ。`KF_*` はKalman filterによる推定（MS5611+BNO085+GNSS）。
 * `imu_replaydata/`フォルダ（例：`imu_replaydata/20260324.txt`）：β版のみ、5Hz。
   `time, roll, pitch, yaw, pitch_avg, roll_trim, yaw_acc95, wind_mps, wind_dir`
   （ESKFの結果＝**画面に出ていた値そのもの**）
   * リプレイ時にこのファイルを読んで、そのとき画面に何が出ていたかを再現します。
   * 列名で解釈するので、後から列を足しても古いファイルが読めなくなることはありません。
 * `imuraw/`フォルダ（例：`imuraw/20260324.bin`）：β版のみ。生IMUの28バイト固定長バイナリ。
   ジャイロ・加速度（各50Hz）、地磁気（10Hz）、GNSS速度（2Hz）。PC側の解析は `tools/imulog/` を参照。
 * `euler/`フォルダ：**0.93以前**の形式（`time, roll, pitch, yaw`、BNO085由来）。現在は書き出しません。
   過去のログをリプレイするために読み込みだけ対応しています（`imu_replaydata/` が無い日はこちらを探します）。
 * `received/`フォルダ：**受信モードのときだけ**、無線で受け取ったテレメトリを記録します（v7〜）。
   列は自機のフライトCSVと揃えてあるので、既存のリプレイ機能と解析ツールがそのまま使えます。
   * **自機のGNSSは混ぜません。** 無線で得た情報だけを置きます。
   * これによりフライトログが二重化されます。機体が着水してSDが読めなくなっても、
     ボート側に同じ航跡が残ります。
 * `/log.txt`：起動からの秒数、電圧、センサー類の初期化結果やGNSS精度などのイベントログ。
   * 無線が有効なときは **60秒ごとに通信レポート**（受信数・取りこぼし・RSSI）も記録します。

# 大会本番での使い方（Auto 10km モード）
 * 目的地はパイロンではなく **PLATHOME** を選択し、Navigation Mode を **Auto 10km** にする。
 * 自動で FLY AWAY（表示は `10K AWAY`）で始まる。プラットホーム上や上昇中はプラットホームから離れる方角（南東）を指すが正常で、数秒飛べば北西方面の指示に変わる。
 * このモードはパイロンへは誘導せず、**プラットホームから離れる最短距離の方角（マゼンタ線=TC）** に誘導する設計。風は考慮していない。
 * パイロンに向かいたい場合は、画面上の北パイロン・南パイロンへの線とTrue Track(TT)を見てパイロット自身が判断する。2025ルールではプラットホームから各パイロンへのTCはそれぞれ **318°** と **258°**（旧版に載っていた磁方位 326°/266° から偏角8°を引いた値）。
 * 目的地から 10.475km 離れると自動更新音が鳴り `10K INTO` に切替。以降はパイロンを旋回したかに関係なくプラットホームへ戻る警告が出るので、**目視で折り返しを終えるまではコース警報を無視する**。
 * 復路で目的地から 1.5km 以内に入ると再び `10K AWAY` に切替。同様に警告を無視して目視で1kmパイロンを探して旋回する。
 * 実際のパイロン位置は目安の 10.975km 円からズレる（2025大会では5km通過で膨らんだ）。6km過ぎたあたりから目視で探すこと。
 * 目的地の `N_PILON` / `S_PILON` は、飛行中に急遽反対側のパイロンへ向かう場合に FLY INTO で直接誘導するためのもの（主にボート側での操作を想定）。

# 使用者（パイロット/ボート）向け留意事項
 * **TFでは目的地の設定を間違えやすい。** 逆に設定すると飛行中に逆向きの旋回指示が出る。風向き変化で逆向きに飛ぶ場合はPONSの設定も変更すること。
   * 例：笠岡の南向きなら `KASAOKA21`+FLY AWAY または `KASAOKA03`+FLY INTO。白浜の北向きなら `SHIRAHAMA16`+FLY INTO または `SHIRAHAMA34`+FLY AWAY。
 * **方位はすべて真方位（True）です。** v0.94 で磁方位を廃止しました。機体に磁気コンパスを載せない方針になったため、磁方位と真方位が混在する意味が無くなったからです。
   * 画面上部の `TT`（True Track）、フッターの `TC`（True Course）、地図上のコンパス(N/E/S/W)、SDログの `TrueTrack`、ESKF のヨー角、すべて真方位で統一されています。
   * v0.93以前の表示（`MT` / `MC`）は真方位に偏角+8度を加えた磁方位でした。過去のログや資料と見比べるときは **8度ずれる**ことに注意してください。
   * なお BNO085 内蔵の地磁気センサーは磁北基準のため、ESKF が初期ヨーに使う際は `ESKF_MAG_DECLINATION_DEG`(-8.0°) で真北へ変換しています。ここだけは偏角補正が残ります。
 * **方位の精度は対地速度に依存する。** 移動速度が遅いと方位が大きく変化しやすい。徒歩ではばらつくが、ジョギング(3m/s)以上で安定する。
 * **航路(TRACK)警報が鳴っても、すぐに画面を注視しないこと。** 警告音は航路変化＝姿勢変化を知らせている。まずバンクなど機体姿勢の安定が最優先。姿勢が落ち着いてから修正方向・修正量の確認に使う。
 * 稼働時は捕捉衛星数が10sats以上（緑色）、`sAcc: 0.2m/s` 以下になっていることを確認するとよい。

# 着水（水没）後の処理
 1. 分解して取れる水分をすべて拭き取り、ネジのサビを除去する。
 2. バッテリー端子とTFT端子を取り外し、可能な範囲で拭いた後エタノール洗浄する。バッテリーはテープと回路部分を分解洗浄し、テープ保護して戻す。
 3. 乾燥剤を入れたジップロックでTFT内部などの水分を抜く（湿度20%で2〜3日放置推奨）。
 4. DIPスイッチは内部で錆が発生し接触不良になる恐れがあるため交換推奨。
