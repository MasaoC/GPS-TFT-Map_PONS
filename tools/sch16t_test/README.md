# SCH16T-K01-10 単独テスト（Raspberry Pi Pico 2）

PONS 本体から**完全に独立**した立ち上げ用スケッチ。
`sch16t_test.ino` を Pico 2 に焼いて、シリアル（115200）から 1 文字コマンドで操作する。

目的は 3 つ。

1. SafeSPI2 の 48bit フレームで会話できることを確認する
2. 初期化シーケンス（リセット → 設定 → EOI → 検証）を通す
3. **BNO085 と同じ土俵の数値を実測する** — 静止バイアス・ノイズ・`|a|/g` のスケール誤差・実 ODR

---

## 配線

| SCH16T | Pico 2 | 備考 |
|---|---|---|
| MISO | GP16 | SPI0 RX |
| CS | GP17 | スケッチが手動で叩く |
| SCK | GP18 | SPI0 SCK |
| MOSI | GP19 | SPI0 TX |
| EXTRESN | GP20 | Low でリセット。内部プルアップあり |
| DRY_SYNC | GP21 | **入力にする。出力にしないこと**（SYNC 入力との兼用ピン） |
| 3V3 | 3V3(OUT) | V3P3 と VDDIO の両方へ |
| GND | GND | |

`TA9` / `TA8` は `kicad/IMU_murata/` のブレイクアウト上で GND に落ちている想定
（データシート: *"Connect to ground for default '0' address"*）。
**未確認なら最初に `a` で走査する。**

配線は短くすること。長いジャンパだと 10MHz で落ちる。スケッチは 1MHz で始まる。

**v7 本体では J7（8pin FPC）経由で繋がる。** ブレイクアウトの J1 とピン順が一致しているので
1:1 ケーブルでよい。本体側の GPIO は
`CS=41 / SCK=42 / MOSI=43 / MISO=44 / EXTRESN=45 / DRY=46`（SPI1 の正規割り当て）。

| pin | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| | +3V3 | RESET | MOSI | CS | SCK | SYNC | MISO | GND |

**ブレイクアウトの R2（CS–GND の 4.7k）は実装しない。** CS は負論理なので、
プルダウンすると MCU が駆動していない間セレクト状態になる。R1（EXTRESN プルアップ）は実装する。

## ビルド

```sh
"/Applications/Arduino IDE.app/Contents/Resources/app/lib/backend/resources/arduino-cli" \
  compile -b rp2040:rp2040:rpipico2 --build-path /tmp/sch16tbuild tools/sch16t_test
```

書き込みは Arduino IDE から（ボード **Raspberry Pi Pico 2**）。

## 手順

### 0. 起動メッセージ

電源を入れると、**SPI を叩く前に**フレーム組み立ての自己テストが走る。

```
[self] フレーム組み立て 10 件 OK（Murata の事前計算値と一致）
```

ここが NG なら CRC かビット位置を壊している。**配線を見るのは時間の無駄なので、
先にスケッチを直す。** 期待値は Murata の BSD コードにある事前計算フレームの写し。
守れるのは「将来の編集による退行」だけで、元の読み方の誤りは検出できない。

### 1. 会話の確立

`z` を打つ。

- **全部 0x0000** … MISO が来ていない。配線・電源・CS を疑う
- **全部 0xFFFF** … MISO が Hi-Z のままプルアップに引かれている。CS が効いていない
- `crc OK` が出る … フレーム層は成立している

次に `t`。`SYS_TEST`（0x37）への書き込み／読み返しが全パターン一致すれば、
**フレーム層・CS・CRC がすべて成立している**ことの証明になる
（データシート Table 84 がこの手順を疎通確認として指定している）。

次に `i`。**`COMP_ID = 0x0023` なら SCH16T-K01**（Table 86）。`ASIC_ID` はシリコンの
リビジョンなので品種判定には使わない。部品は K01 で確定なのでスケッチは
`1600` / `3200` LSB 固定だが、`COMP_ID` は毎回見て違えば警告を出す（`i` / `r` / `m` / `h`）。

★★ **他品種はジャイロの感度だけが 16 倍違い、加速度は共通。**
だから `m` の 1g 検証では**原理的に検出できない**（`|a|/g` は 1.000 に乗る）。
ジャイロのバイアスとノイズが 1/16 に小さく出る ＝ **判断材料が都合のいい方向へ外れる。**
警告が出たら数値を使わず `G` で感度そのものを測る（根拠は下の「PX4 との相違点」）。

応答が無ければ `a` で TA を走査する。応答フレームの `SA` が要求の `TA` と
一致するかも見ている（別個体が答えていないかの確認）。

### 2. 初期化

`r`（または `R`）。`[init] SUCCESS` と `STAT_SUM = 0xFFFF (all OK)` が目標。

`STAT_SUM` の 0 のビットが異常箇所。`s` で個別レジスタを見る。
**ステータスは 2 周読まないと初期化中のラッチが残る**ので、スケッチはそうしてある。

★ **ID とシリアルの読みは CRC と CE だけで判定する。** `S1:S0` は「センサーの測定状態」で
**EOI の前は 11（初期化中）**なので、そこで弾くと起動直後の ID 読みが毎回
「フレームが壊れている」になる。`check_comp_id()` も EOI の後に置いてある。

### 3. 静止性能（本題）

水平な机に置いて動かさず `M`（60 秒）。出てくる数値と期待値:

| 項目 | データシート typ | BNO085 実測（比較対象） |
|---|---|---|
| ジャイロ バイアス | XY ±0.1 / Z ±0.01 °/s | 申告精度 0 のまま・ZRO ドリフトあり |
| ジャイロ ノイズ密度 | XY 0.0004 °/s/√Hz | — |
| 加速度 オフセット | ±0.01 m/s² | — |
| **`\|a\|/g`** | 1.000 に乗るはず | **0.985〜0.992（約 −1%）** |
| 加速度 ノイズ | — | σ = 0.0008 g（2Hz LPF 後） |

`|a|` はノルムなので**回転不変**。傾いて置いてあってもスケール誤差の比較に使える
（BNO085 側の値も同じ方法で出したもの。→ `memory/vertical-g-estimation.md`）。
★ **ただしこれが確かめているのは加速度の感度だけ。** 加速度の LSB は品種に依らないので、
`|a|/g` が 1.000 に乗ってもジャイロの裏付けには一切ならない。

ノイズ密度の欄は `sd/sqrt(fc)`（`fc` は LPF の公称カットオフ）の概算。
**`fs/2` を帯域に使ってはいけない** — 68Hz LPF を 500Hz で読むと `fs/2` は 250Hz だが
ノイズが通っているのは 68Hz 前後なので、密度が 35% ほど小さく出る。
実 ENBW は `fc` の 1.0〜1.6 倍なので真値はこの 0.8〜1.0 倍。桁が合っているかだけを見る。
`f` でフィルターを変えて sd が帯域の平方根で動くかを確認すると、測れていることの裏が取れる。

出力の冒頭に品種・感度・LPF・dec・SPI クロック・TA が全部書かれるので、
**ログだけ残しておけば後から条件が再現できる。**

★ **読み出しレートが足りないとノイズを過大評価する。**
データシート §5.5 Table 16 に LPF ごとの「最小推奨読み出しレート」がある
（LPF0 68Hz → 500Hz、LPF1 30Hz → 200Hz、LPF2 13Hz → 150Hz）。
これを下回るとフィルターの阻止域のノイズが折り返して帯域内に入る。
スケッチは実測レートをこの値と比べて警告を出す。出たら `k` で SPI を速くするか
`f` でフィルターを下げる。**バイアスと 1g スケール誤差は折り返しの影響を受けない。**

### 3.5 ジャイロ感度の実測（`G`）

★ **ジャイロのスケールを端から端まで確かめられる唯一の手段。**
1g 検証は加速度の感度しか見ていないので、`LSB_PER_DPS`・DYN ビット・20bit の符号拡張の
どれが間違っていても通ってしまう。他品種が挿さっている場合もここでしか出ない。

1. 基板を机に平らに置く（Z 軸が鉛直）
2. `G` → 案内が出たら何かキーを押す → 静止 1 秒でバイアスを取る
3. **ゆっくり**きっちり 90°（または 360°）回して止める
4. もう一度キーを押す

生の LSB を時間積分した値 `[LSB·s]` を回した角度で割れば、そのまま `LSB/(°/s)`。
角度を実測する必要はない（机の角に押し当てて 90°、一周で 360°）。
回した軸の「÷90°」か「÷360°」の列が **1600 近辺なら正しい**（K01・DYN=`010`）。
16 倍ずれていたら K01 ではない部品が挿さっている。`i` で `COMP_ID` を確認する。

最大レートが ±300°/s に近いときは速すぎる（飽和の疑い）のでやり直す。

### 4. ODR

`d`。設定どおりの周期（既定の dec=738 なら 1355µs）で DRY が立つこと。

**DRY は「出力レジスタ更新 → 最初の読み出し」の間だけ High** なので、
読まずに放置するとパルスが出ない。スケッチは読みながら数えている。

★★ **読み出しが ODR より遅いと、この値は ODR ではなく読み出しレートになる。**
更新ごとに 1 パルスではなく、読むごとに 1 パルスになるため。
`dec=NONE`(11.8kHz) や 5900Hz は 1MHz SPI では原理的に追いつかないので、
「期待値」と食い違っても故障ではない。
`DRY 回数 ≒ 読み出し回数` になったらスケッチが明示的に警告を出す。
出たら `k` で SPI を速くするか `e` で dec を落として測り直す。

`d` は初期化後でないと意味が無い（`DRY_DRV_EN` が必要）ので、未初期化だと断る。

### 5. ログ取り

`v` で CSV が流れる。ヘッダは

```
t_us,gx_dps,gy_dps,gz_dps,ax_mps2,ay_mps2,az_mps2,temp_c,ok
```

ターミナルのログ機能でファイルへ落とせば、そのまま Python で解析できる。
PONS 側の `tools/imulog/` の解析と突き合わせるならこの形式で揃える。

### 6. 温度ドリフト

電源投入直後から `M` を 10 分おきに繰り返し、温度（出力の最後）とジャイロバイアスを並べる。
BNO085 で問題になったのはここ（ZRO の温度ドリフトが GRV に効く）。

## 検証状況（2026-10-01 / 2026-10-05 に再確認）

**フルデータシート（Doc.No.11624 Rev.6, 65 ページ）で全件照合済み。推測で書いた箇所は無い。**

データシート §6.6 Table 27 には**実フレームの 16 進値**が載っている。
スケッチの `crc8_frame()` / `req_read()` / `reg_write()` / `build_filt()` を
そのままホストでコンパイルして突き合わせた結果:

| 照合先 | 件数 | 結果 |
|---|---|---|
| データシート Table 27 の 48bit フレーム | 41 | **全一致** |
| [smplboards-SCH16T](https://github.com/HTY2003/smplboards-SCH16T) の読み出しフレーム（48bit 全ビット） | 38 | **全一致** |
| 同・書き込みフレームの上位 40bit（`REQ_SET_*` と `REQ_SOFTRESET`） | 9 | **全一致**（2026-10-05 再照合） |

このうち代表 10 件は `selftest_frames()` に焼いて**起動時に自動照合**する。
守れるのは将来の編集による退行だけ（同じ出典から持ってきた値なので、
元の読み方の誤りは検出できない）。

先駆者のライブラリは Murata の C コード例からの移植で、CRC8・フレーム組み立て・
`SPI48_DATA_INT32`・ダミーフレーム・SPI mode 0 / 10MHz・EXTRESN の 2ms リセットまで
こちらと同一だった。フィールドマスクも一致している（`ERROR_FIELD_MASK = 0x001E00000000`
＝ ステータスビットが `[36:33]`）。

確定した内容:

| 項目 | 値 | 出典 |
|---|---|---|
| フレーム | `TA[47:38]`（上位 2bit が CS、下位 8bit がレジスタ）/ `RW[37]` / **`FT[35]`** / `DATA[27:8]` / `CRC8[7:0]` | §6.2 Table 21 |
| `FT` bit35 | **Frame Type**。次の MISO フレーム幅（1 = SPI48BF）。PX4 が常時 1 にしていたビットの正体 | §6.2 Table 21 |
| CRC8 | 多項式 0x2F（Koopman 0x97）・初期値 0xFF・XOR out なし・bit 47〜8 が対象 | §6.5 Table 25 |
| 応答 | **1 フレーム遅れる。** 「ダミー読みで前フレームの応答を受け取る」と明記 | §6.5 / Table 84 |
| ステータス | `[36]IDS [35]CE [34:33]S1:S0`。S は 00=正常 01=エラー 10=飽和 11=初期化中 | §6.4 Table 22-24 |
| 待ち時間 | NVM 読み **32ms** / EN_SENSOR 後 **215ms** / EOI 後 **3ms** | §5.2 |
| 感度（20bit） | RATE `'010'`=1600 LSB/(°/s)（K01）、ACC12 `'001'`=3200 LSB/(m/s²)、ACC3 `'000'`=1600、温度 100 LSB/°C | Table 63-65 |
| 品種判定 | **`COMP_ID` = 0x0023 が SCH16T-K01。** `ASIC_ID` はシリコンのリビジョンで品種判定には使えない | Table 85/86 |
| 温度 | 16bit 幅。20bit フィールドの**上位に詰まっている**ので `>>4` してから /100 | PX4 と Murata 由来ライブラリの両方が `SPI48_DATA_INT32(x) >> 4`。コメントも同文 |
| ステータスレジスタ | すべて 16bit で、20bit フィールドの**下位に詰まっている**（だから 0xFFFF と比較できる） | PX4 の `SPI48_DATA_UINT16` + `!= 0xFFFF` |
| レジスタ幅 | CTRL_FILT_\* 9bit / CTRL_RATE・CTRL_ACC12 15bit / CTRL_ACC3 3bit → **ベタ書きで潰せる非ゼロのリセット値ビットが無い** | PX4 の `Murata_SCH16T_registers.hpp` |
| SCK | 既定モードで **0.095〜10.5MHz**（下限がある）。25.5MHz は `MISO_HI_SPD=1` が必要 | Table 12 |

### 先駆者・PX4 との相違点（こちらが正しいと判断した箇所）

**`CTRL_USER_IF` は read-modify-write が必要。**
リセット値が 0 ではない（`FTREE_TDEL=2b10` / `MISO_SR_CTRL=1` / `DRY_SR_CTRL=1` = **0x200C**）。
PX4 は `DRY_DRV_EN`(0x0020) を素で書くので `MISO_SR_CTRL` と `DRY_SR_CTRL` を 0 に落とす
（データシートがその側を *"This option is not supported by Murata"* と明記している）。
ついでに `FTREE_TDEL` も 2.5ms → 0.078ms に変わる。
Murata 由来ライブラリの `setDRY()` は読んでから書いており、こちらもそれに合わせた（`set_dry()`）。

**PX4 の定数名は紛らわしいが値は正しい。** `RATE_RANGE_300 = 0b001` は実際には
±327.68 °/s（測定レンジ ±300）で、感度 1600 LSB/(°/s)。`ACC12_RANGE_80 = 0b001` は
±163.84 m/s²（測定レンジ ±80）で 3200 LSB/(m/s²)。値としては既定＝最も広いレンジで正しい。
なお **`'000'` は CTRL_RATE / CTRL_ACC12 では "Undefined" で書いてはいけない。**

**RATE の DYN には `'010'` を書く（`'001'` ではない）。**
両者は同じレンジだが、Murata 由来ライブラリは 1600 LSB に `'010'` を書き、逆変換
（`convertBitfieldToRateSens`）では `'001'` を未定義（0）にしている。`'010'` なら
「書いた値 → 感度」が 1 対 1 になり、`verify_sensitivity_readback()` の照合が成立する。
PX4 は `'001'` を書いて実機で動いているので、どちらでも動く。

**ベタ書きの検証は「潰していない」ことを保証しない。**
`want == got` でも、0 を書いて 0 が読めたなら非ゼロのリセット値を潰していても一致する。
幸い PX4 のヘッダのレジスタ幅から、ベタ書きしている 6 本には潰せる非ゼロのリセット値
ビットが無いと確認できた。該当するのは `CTRL_USER_IF`（対処済み）と `CTRL_ST`（未使用）だけ。

**48bit は 1 回の `SPI.transfer(tx, rx, 6)` で送る。`transfer16()` を 3 回ではない。**
arduino-pico 4.5.1 の `transfer16()` は 1 ワードごとに戻るので**ワード間で SCK が止まる**。
6 バイトの `transfer()` なら TX FIFO（8 段）へ先に積むので 48bit 連続する。

**品種が違うとジャイロ感度だけが 16 倍変わり、加速度は変わらない。**
Murata 由来ライブラリは `SCH16T_K10` クラスで `convertRateSensToBitfield` だけを上書きし
（`100/200/400` ↔ `1600/3200/6400`）、加速度側は上書きしていない。PX4 も `probe()` の
リビジョン判定でジャイロだけスケールを変えている（加速度は両方 `1/3200`）。
使うのは K01 で確定なので分岐は入れていないが、**1g 検証ではこの違いを検出できない**ため
`COMP_ID` の確認は残した。違っていたら `G` の実回転で測る。

### まだ入れていないもの

- **`CTRL_ST`（セルフテスト）。** ビット配置は判明した（Table 78。`RATE_STC_CTRL[11:9]` の
  リセット値が `3b111` など 0 でないビットがある）が、連続セルフテストの解釈に踏み込むので
  単独テストの段階では触らない。ここも read-modify-write が必要。
- `CTRL_*_FLAG_*`（飽和フラグのフィルター設定）。既定 0 のまま。
