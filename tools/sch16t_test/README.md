# SCH16T-K01-10 単独テスト（Raspberry Pi Pico 2）

PONS 本体から**完全に独立**した立ち上げ用スケッチ。
`sch16t_test.ino` を Pico 2 に焼いて、シリアル（115200）から 1 文字コマンドで操作する。

目的は 3 つ。

1. SafeSPI2 の 48bit フレームで会話できることを確認する
2. 初期化シーケンス（リセット → 設定 → EOI → 検証）を通す
3. **BNO085 と同じ土俵の数値を実測する** — 静止バイアス・ノイズ・`|a|/g` のスケール誤差・実 ODR

---

## 配線

| SCH16T | Pico 2 | 備考 |
|---|---|---|
| MISO | GP16 | SPI0 RX |
| CS | GP17 | スケッチが手動で叩く |
| SCK | GP18 | SPI0 SCK |
| MOSI | GP19 | SPI0 TX |
| EXTRESN | GP20 | Low でリセット。内部プルアップあり |
| DRY_SYNC | GP21 | **入力にする。出力にしないこと**（SYNC 入力との兼用ピン） |
| 3V3 | 3V3(OUT) | V3P3 と VDDIO の両方へ |
| GND | GND | |

`TA9` / `TA8` は `kicad/IMU_murata/` のブレイクアウト上で GND に落ちている想定
（データシート: *"Connect to ground for default '0' address"*）。
**未確認なら最初に `a` で走査する。**

配線は短くすること。長いジャンパだと 10MHz で落ちる。スケッチは 1MHz で始まる。

## ビルド

```sh
"/Applications/Arduino IDE.app/Contents/Resources/app/lib/backend/resources/arduino-cli" \
  compile -b rp2040:rp2040:rpipico2 --build-path /tmp/sch16tbuild tools/sch16t_test
```

書き込みは Arduino IDE から（ボード **Raspberry Pi Pico 2**）。

## コマンド

| | |
|---|---|
| `h` | ヘルプと現在の設定 |
| `a` | TA (TA9:TA8) を走査。**応答しないときまずこれ** |
| `i` | ID と設定レジスタを読む |
| `t` | `SYS_TEST` に書いて読み返す（**データシート推奨の疎通確認**） |
| `r` / `R` | 初期化（ソフト / EXTRESN ハードリセット） |
| `s` | ステータス全ダンプ＋フレーム統計 |
| `m` / `M` | 静止測定 10 秒 / 60 秒 |
| `d` | DRY_SYNC で実 ODR を測る |
| `c` | 連続表示（人が読む形式） |
| `v` | CSV 出力（ログ取り用） |
| `p` | `*_1`（補間）と `*_2`（デシメーション）の生値比較 |
| `k` | SPI クロック 1→2→5→10MHz |
| `f` | フィルター 68→30→13Hz |
| `e` | デシメーション 738→1475→2950→5900→none Hz |
| `z` | 1 フレームだけ生で投げて中身を見る（配線確認） |

## 手順

### 1. 会話の確立

`z` を打つ。

- **全部 0x0000** … MISO が来ていない。配線・電源・CS を疑う
- **全部 0xFFFF** … MISO が Hi-Z のままプルアップに引かれている。CS が効いていない
- `crc OK` が出る … フレーム層は成立している

次に `t`。`SYS_TEST`（0x37）への書き込み／読み返しが全パターン一致すれば、
**フレーム層・CS・CRC がすべて成立している**ことの証明になる
（データシート Table 84 がこの手順を疎通確認として指定している）。

次に `i`。**`COMP_ID = 0x0023` なら SCH16T-K01**（データシート Table 86）。
感度は 1600 LSB/(°/s) と 3200 LSB/(m/s²)。
`ASIC_ID` はシリコンのリビジョンなので品種判定には使わない。
**COMP_ID が違ったら感度も違う可能性があるので、`m` の 1g 検証で必ず裏を取る。**

応答が無ければ `a` で TA を走査する。応答フレームの `SA` が要求の `TA` と
一致するかも見ている（別個体が答えていないかの確認）。

### 2. 初期化

`r`（または `R`）。`[init] SUCCESS` と `STAT_SUM = 0xFFFF (all OK)` が目標。

`STAT_SUM` の 0 のビットが異常箇所。`s` で個別レジスタを見る。
**ステータスは 2 周読まないと初期化中のラッチが残る**ので、スケッチはそうしてある。

### 3. 静止性能（本題）

水平な机に置いて動かさず `M`（60 秒）。出てくる数値と期待値:

| 項目 | データシート typ | BNO085 実測（比較対象） |
|---|---|---|
| ジャイロ バイアス | XY ±0.1 / Z ±0.01 °/s | 申告精度 0 のまま・ZRO ドリフトあり |
| ジャイロ ノイズ密度 | XY 0.0004 °/s/√Hz | — |
| 加速度 オフセット | ±0.01 m/s² | — |
| **`\|a\|/g`** | 1.000 に乗るはず | **0.985〜0.992（約 −1%）** |
| 加速度 ノイズ | — | σ = 0.0008 g（2Hz LPF 後） |

`|a|` はノルムなので**回転不変**。傾いて置いてあってもスケール誤差の比較に使える
（BNO085 側の値も同じ方法で出したもの。→ `memory/vertical-g-estimation.md`）。

ノイズ密度の欄は `sd/sqrt(fs/2)` の概算。真の帯域はフィルター設定次第なので、
桁が合っているかだけを見る。`f` でフィルターを変えて、
sd が帯域の平方根で動くかを確認すると測れていることの裏が取れる。

★ **読み出しレートが足りないとノイズを過大評価する。**
データシート §5.5 Table 16 に LPF ごとの「最小推奨読み出しレート」がある
（LPF0 68Hz → 500Hz、LPF1 30Hz → 200Hz、LPF2 13Hz → 150Hz）。
これを下回るとフィルターの阻止域のノイズが折り返して帯域内に入る。
スケッチは実測レートをこの値と比べて警告を出す。出たら `k` で SPI を速くするか
`f` でフィルターを下げる。**バイアスと 1g スケール誤差は折り返しの影響を受けない。**

### 4. ODR

`d`。設定どおりの周期（既定の dec=738 なら 1355µs）で DRY が立つこと。

**DRY は「出力レジスタ更新 → 最初の読み出し」の間だけ High** なので、
読まずに放置するとパルスが出ない。スケッチは読みながら数えている。

### 5. ログ取り

`v` で CSV が流れる。ヘッダは

```
t_us,gx_dps,gy_dps,gz_dps,ax_mps2,ay_mps2,az_mps2,temp_c,ok
```

ターミナルのログ機能でファイルへ落とせば、そのまま Python で解析できる。
PONS 側の `tools/imulog/` の解析と突き合わせるならこの形式で揃える。

### 6. 温度ドリフト

電源投入直後から `M` を 10 分おきに繰り返し、温度（出力の最後）とジャイロバイアスを並べる。
BNO085 で問題になったのはここ（ZRO の温度ドリフトが GRV に効く）。

## 検証状況（2026-10-01）

**フルデータシート（Doc.No.11624 Rev.6, 65 ページ）で全件照合済み。推測で書いた箇所は無い。**

データシート §6.6 Table 27 には**実フレームの 16 進値**が載っている。
スケッチの `crc8_frame()` / `req_read()` / `reg_write()` / `build_filt()` を
そのままホストでコンパイルして突き合わせた結果:

| 照合先 | 件数 | 結果 |
|---|---|---|
| データシート Table 27 の 48bit フレーム | 41 | **全一致** |
| [smplboards-SCH16T](https://github.com/HTY2003/smplboards-SCH16T) の事前計算フレーム | 38 | **全一致** |

先駆者のライブラリは Murata の C コード例からの移植で、CRC8・フレーム組み立て・
`SPI48_DATA_INT32`・ダミーフレーム・SPI mode 0 / 10MHz・EXTRESN の 2ms リセットまで
こちらと同一だった。フィールドマスクも一致している（`ERROR_FIELD_MASK = 0x001E00000000`
＝ ステータスビットが `[36:33]`）。

確定した内容:

| 項目 | 値 | 出典 |
|---|---|---|
| フレーム | `TA[47:38]`（上位 2bit が CS、下位 8bit がレジスタ）/ `RW[37]` / **`FT[35]`** / `DATA[27:8]` / `CRC8[7:0]` | §6.2 Table 21 |
| `FT` bit35 | **Frame Type**。次の MISO フレーム幅（1 = SPI48BF）。PX4 が常時 1 にしていたビットの正体 | §6.2 Table 21 |
| CRC8 | 多項式 0x2F（Koopman 0x97）・初期値 0xFF・XOR out なし・bit 47〜8 が対象 | §6.5 Table 25 |
| 応答 | **1 フレーム遅れる。** 「ダミー読みで前フレームの応答を受け取る」と明記 | §6.5 / Table 84 |
| ステータス | `[36]IDS [35]CE [34:33]S1:S0`。S は 00=正常 01=エラー 10=飽和 11=初期化中 | §6.4 Table 22-24 |
| 待ち時間 | NVM 読み **32ms** / EN_SENSOR 後 **215ms** / EOI 後 **3ms** | §5.2 |
| 感度（20bit） | RATE `'001'`=1600 LSB/(°/s)、ACC12 `'001'`=3200 LSB/(m/s²)、ACC3 `'000'`=1600、温度 100 LSB/°C | Table 63-65 |
| 品種判定 | **`COMP_ID` = 0x0023 が SCH16T-K01。** `ASIC_ID` はシリコンのリビジョンで品種判定には使えない | Table 85/86 |
| SCK | 既定モードで **0.095〜10.5MHz**（下限がある）。25.5MHz は `MISO_HI_SPD=1` が必要 | Table 12 |

### 先駆者・PX4 との相違点（こちらが正しいと判断した箇所）

**`CTRL_USER_IF` は read-modify-write が必要。**
このレジスタはリセット値が 0 ではない（`FTREE_TDEL=2b10` / `MISO_SR_CTRL=1` / `DRY_SR_CTRL=1`、
つまり **0x200C**）。PX4 は `DRY_DRV_EN`(0x0020) を素で書いているので、
`MISO_SR_CTRL` と `DRY_SR_CTRL` を 0 に落としてしまう。データシートはその側を
*"This option is not supported by Murata"* と明記している。
ついでに `FTREE_TDEL` も 2.5ms → 0.078ms に変わる。

Murata の C コード例由来のライブラリ（`setDRY()`）は正しく読んでから書いており、
このスケッチもそちらに合わせた（`set_dry()`）。

**PX4 の定数名は紛らわしいが値は正しい。** `RATE_RANGE_300 = 0b001` は実際には
±327.68 °/s（測定レンジ ±300）で、感度 1600 LSB/(°/s)。`ACC12_RANGE_80 = 0b001` は
±163.84 m/s²（測定レンジ ±80）で 3200 LSB/(m/s²)。値としては既定＝最も広いレンジで正しい。
なお **`'000'` は CTRL_RATE / CTRL_ACC12 では "Undefined" で書いてはいけない。**

### まだ入れていないもの

- **`CTRL_ST`（セルフテスト）。** ビット配置は判明した（Table 78。`RATE_STC_CTRL[11:9]` の
  リセット値が `3b111` など 0 でないビットがある）が、連続セルフテストの解釈に踏み込むので
  単独テストの段階では触らない。ここも read-modify-write が必要。
- `CTRL_*_FLAG_*`（飽和フラグのフィルター設定）。既定 0 のまま。
