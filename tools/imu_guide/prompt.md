# IMU/ESKF 画面の入口の案内画像 — 作り方

IMU/ESKF 画面に入るたびに必ず通る、較正（APPLY）前の案内 3 枚の原本。
1 枚ごとに音声が流れる（`GPS_TFT_map.ino` の `IMU_GUIDE_WAV[]`。順番で 1 対 1）。

| ファイル | 中身 | 流れる音声 |
|---|---|---|
| `imu_guide_1.svg` | SET PITCH ＝ 地面の傾き | `guide_eskf_pitch.wav` |
| `imu_guide_2.svg` | SET ROLL ＝ 機体の左右の傾き | `guide_eskf_roll.wav` |
| `imu_guide_3.svg` | 本体の向き ＝ 進行方向（較正で直せない） | `guide_eskf_heading.wav` |
| （抜けて較正の画面へ） | | `guide_eskf_apply.wav` |

## 差し替えの手順

1. 下の「指示文」を、SVG を書ける対話型の AI（ChatGPT / Claude / Gemini など）に貼る。
   **画像生成ではなく SVG のコードで受け取ること**（画像生成は日本語を崩し、縮小すると漢字が潰れる）。
2. 返ってきた SVG をそれぞれ `imu_guide_1.svg` 〜 `_3.svg` として保存する。
3. `python3 tools/gen_guide_flash.py --render`（Chrome で等倍の PNG にし、
   `src/flashdata/imu_guide_data.cpp` を作り直す）。
4. `imu_guide_*.png` を開いて、文字の崩れ・はみ出しを目で確かめる。
   **Mac の Chrome はヒラギノで描く。** AI の画面（Noto Sans JP など）で収まっていても、
   ヒラギノだと横に広がってはみ出すことがある（2026-11-07 の仮画像で実際に起きた）。

いまの 3 枚は Claude が下の指示文どおりに SVG を手で書いたもの（2026-11-07）。
Gemini にも作らせたが、機体が軽飛行機の形になる・指定に無い小さな注記を足す・
見出しの揃えが 1 枚ごとに違う、で採らなかった。直すときは SVG を直接書き換えるのが早い。

描いてみて分かったこと（指示文にも反映済み）:
- **14° 程度の角度は、弧の線だと細い縦線にしか見えない。** 扇形を塗る。
- **「スイッチを押すと較正の画面へ」は 14 文字 = 224px** で、三角形と並べると入らない。
- **ヒラギノの「°」は全角幅。** 「3° の」と空白を入れると間延びするので詰めて書く。

---

## 指示文（ここから下を貼る）

```text
# 依頼：小型液晶に表示する説明画像を 3 枚、SVG で作ってください

## 目的
人力飛行機に載せる航法装置の画面に出す、3 枚続きの説明画像です。
姿勢センサーの「較正（APPLY）」をする前に、パイロットや地上係が次の 3 点を確かめるよう促します。
1 枚に 1 項目ずつ出し、スイッチを押すと次の 1 枚へ進みます。各ページを出している間、
その項目を読み上げる音声が流れます。
  1/3：SET PITCH を地面の傾きに合わせる
  2/3：SET ROLL を機体の左右の傾きに合わせる
  3/3：装置本体を進行方向（機首方向）へまっすぐ向けて固定する
3/3 は較正では直せません（向きがずれると風の推定が狂い、後から直す手段がない）。
3 枚の中でいちばん強く注意を引くようにしてください。

## 出力
- SVG のコードを 3 つ返してください。1 枚ごとに 1 つのコードブロックにし、
  直前にファイル名（imu_guide_1.svg / imu_guide_2.svg / imu_guide_3.svg）を書く。ほかの説明は不要。
- 画像（PNG / JPEG）ではなく、SVG のコード（テキスト）で返す。
- それぞれ <svg width="240" height="320" viewBox="0 0 240 320" xmlns="http://www.w3.org/2000/svg">
- 表示先は 2.8 インチ・240×320 ピクセル（縦長）のカラー液晶です。この SVG を等倍
  （1 ピクセル＝1 ピクセル）で画像にして表示します。拡大・縮小はしません。
- 文字はアウトライン化せず <text> で書く。
  font-family="'Hiragino Sans','Noto Sans JP',sans-serif" font-weight="700"
- 使わないもの：外部ファイル・画像・Web フォントの読み込み、フィルタ（ぼかし・影）、
  グラデーション、半透明、写真風の表現、ロゴ・実在の機体や製品に似せた絵。
- 縦・横の線は整数座標に置き、太さは 2 か 4（偶数）。2 未満の線は使わない。
- ✔ ✖ ▶ などの記号は文字（フォント）ではなく、線や多角形で描く。
- 3 枚とも同じ枠組み（見出し帯・見出しの揃え方・下端の案内・余白・色づかい・機体の描き方）にそろえる。

## 見る状況（デザインの前提）
- 屋外（湖畔のプラットホーム、直射日光の下）で、腕を伸ばした距離から見ます。
- 画面はとても小さい（1 ピクセル ≈ 0.18mm）。細い線・薄い色・小さな飾りは見えません。
- 文字の大きさは最小 14px。指定より小さくしないこと。
- 背景は白。装置のほかの画面も白地に黒文字なので、それに合わせます。
- 左右の端から 4px 以内（x<4、x>236）に文字や線を置かない。
- 実機ではヒラギノで描かれ、文字の幅が見積もりより広がることがある。各行の幅は
  「全角 1 文字 ＝ 文字サイズ、半角英数 1 文字 ＝ 文字サイズの 0.65 倍」で見積もり、
  220px 以内に収める。

## 使ってよい色（これ以外は使わない）
- 背景：#FFFFFF
- 文字・主な線：#000000
- 補足の文字・補助線：#7B797B
- 見出しの帯：#0000FF（帯の上の文字は #FFFFFF）
- 正しい例（✔）：#007D00
- 注意・誤った例（✖）：#FF0000
- 角度を示す弧：#FFB600（文字には使わない。白地では読みにくいため）

## 3 枚に共通の枠組み（y は上端からのピクセル）
- 見出し帯：y=0〜35 を #0000FF で塗る。白の 18px で、左に「APPLY の前に確認」、右端に「1/3」（2 枚目は「2/3」、3 枚目は「3/3」）。
- 本文：y=40〜289。各ページの最初の 2 行（項目名と「＝ …」）は左寄せ（x=12）。
- 下端：y=292 に #7B797B の 2px の横線。y=296〜319 に案内の文（16px 黒）と、その右に黒で塗った
  右向きの三角形。文の最後の字と三角形の間は 12px 以上あける（近いと 1 つの矢印に見える）。
    1 枚目・2 枚目：「スイッチを押すと次へ」
    3 枚目：「スイッチで較正の画面へ」

## 機体の描き方（3 枚で共通）
人力飛行機の簡単なシルエット。細い胴体、左右に非常に長い直線の主翼（翼幅は胴体長の 2 倍以上）、
後ろに小さな尾翼。車輪・風防などの細部は描かない。主な線は黒 4px。実在の機体に似せない。

## 1 枚目（imu_guide_1.svg）：SET PITCH
- y=44〜：「SET PITCH」（24px 黒）
- その下：「＝ 地面の傾き」（20px 黒）
- y=100〜212 に図（x=10〜230 を広く使う）：横から見た機体。
  地面（黒 4px の線）が右下がりに傾き、その上に機体が乗っている。機首は右。
  機体の機首の先で、地面から右へ水平の補助線（#7B797B の破線）を引き、地面との間の角度を
  #FFB600 の塗りつぶした扇形（半径 50px 以上）で示す。弧の線だけだと細くて見えない。
  傾きは見やすいように 14° 程度に誇張してよい。台は地面の線の下を #7B797B で塗る。
- y=220〜286 に 3 行：
  「地面の傾きと同じか確認」（18px 黒）
  「例：台の上は −3.5°」（16px #7B797B）
  「　　平地は 0°」（16px #7B797B。「台の上」と頭をそろえる）

## 2 枚目（imu_guide_2.svg）：SET ROLL
- y=44〜：「SET ROLL」（24px 黒）
- その下：「＝ 機体の左右の傾き」（20px 黒）
- y=100〜200 に図（x=10〜230）：正面から見た機体。
  中央に胴体（小さな円か楕円）、左右へまっすぐ長く伸びた主翼（水平。上反角を付けない）。
  下に水平の補助線（#7B797B）。翼が水平なことが一目で分かるように。
- y=208〜286 に 4 行：
  「ふつうは 0°」（20px 黒）
  「翼を水平にして較正する」（18px 黒）
  「片翼を下げたまま較正する」（14px #7B797B）
  「ときだけ、その角度を入れる」（14px #7B797B）

## 3 枚目（imu_guide_3.svg）：本体の向き（いちばん重要）
- y=44〜：「本体の向き ＝ 進行方向」（20px 黒）
- その下：「この向きは較正で直せない」（18px #FF0000）
- y=98〜190 に図を 2 つ横に並べる（左 x=8〜116、右 x=124〜232）。
  どちらも機体を真上から見たシルエット（機首が上）。
  胴体の前寄り（操縦席）に、装置を表す小さな横長の長方形（約 16×7px、黒で塗る）と、
  その装置の「前」を示す矢印（黒 2px、長さ 約 24px）を描く。
    左の図：装置と矢印が胴体の向きとぴったり同じ。図の左上に緑（#007D00）の ✔。
    右の図：装置と矢印が胴体の向きから 20〜25° 回っている（誇張してよい）。
           胴体の中心線を #7B797B の破線で前へ延ばし、矢印との間の角度を #FFB600 の
           塗りつぶした帯の扇形（装置にかからない半径 10〜28px）で示す。
           図の左上に赤（#FF0000）の ✖。
- y=196〜286 に 4 行（中央ぞろえ）：
  「まっすぐ向けて固定する」（18px 黒）
  「ずれは横風と見分けがつかず」（16px 黒）
  「風の推定が狂う」（16px 黒）
  「3°のずれで約 0.4m/s」（14px #7B797B）

## 守ること
- 文言は上の指定どおりにする。言い換え・追加・英訳をしない（「SET PITCH」「SET ROLL」「APPLY」
  は装置の画面のメニュー名と同じ綴りなので変えない）。図の中に説明の文字を足さない。
- 文字が枠からはみ出す・図と重なる・14px 未満になる、のどれも起こさない。
  入らないときは、図の方を小さくする。

## 返す前に自分で確かめること（3 枚それぞれ）
1. すべての文字列が指定と一字一句同じか。指定に無い文字を足していないか
2. どの文字も 14px 以上か、各行が 220px 以内か、ほかと重なっていないか
3. 色が上の 7 色だけか
4. 線の太さが 2 以上か、グラデーション・影・半透明を使っていないか
5. 見出し帯・見出しの揃え方・下端の案内・機体の描き方が 3 枚でそろっているか
```
