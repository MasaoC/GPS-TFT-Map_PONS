# attitude.cpp の数学を PC 上で検証する

`attitude.cpp`（機上の姿勢 ESKF）を実機に焼かずに検証するためのハーネス。
**`attitude.cpp` を変更したら必ず実行すること。** 移植ミス・符号ミスはここで捕まる。

```sh
cd tools/attitude_test
make            # 3 本ぜんぶビルドして実行する
```

## テストの中身

| | 何を見るか |
|---|---|
| `main.cpp` → `test` | **協調旋回**。合成データを流し、真のバンク角 20 度を復元できるか（許容 1.5 度） |
| `yaw_test.cpp` → `yaw_test` | **水平化・航跡ヨー・待機中の維持**（0.983 で GRV/RV 依存を外したときに追加） |
| `dead_test.cpp` → `dead_test` | **IMU 断線・未接続**。安全側（`ready=false`）に倒れるか |

`yaw_test` が見ているもの:

- **A** 加速度だけで水平化できるか（GRV なし）。上方向が測った比力と平行か。
  ヨー未設定のあいだ `yaw_acc95` が 180 度に張り付くか（表示が灰色になる条件）
- **C** ヨー未設定のあいだ GNSS 速度観測を**通さない**か
  （通すとヨー誤差がロール・ピッチへ転嫁される）
- **B** GNSS 航跡でヨーを入れると、要求方位に一致し **ロール・ピッチが動かない**か
- **D** 待機中の維持 — 0.2deg/s のジャイロオフセットで 10 分静止させてもロールが保たれるか、
  静止中に機体を傾け直したら追従するか、学習したバイアスがクランプで頭打ちになるか

旧 `decl_test.cpp`（地磁気偏角の符号）は 0.983 で**対象そのものが無くなった**ので
`yaw_test.cpp` に置き換えた（初期ヨーに地磁気を使わなくなった）。

## 仕組みと、間違えやすいところ

- `Arduino.h` は実機ヘッダの最小スタブ。`attitude.cpp` を無改造でコンパイルするために置いてある。

- ★★ **`settings.h` はこのディレクトリにもあるが、実際には使われていない。**
  `attitude.cpp` の `#include "settings.h"` は引用符形式なので、コンパイラはまず
  **attitude.cpp 自身のディレクトリ（リポジトリ直下）** を見る。Makefile の `-I.` はその後。
  （2026-10-01 に `#error` を仕込んで確認。発火しなかった）
  つまり**テストは実機と同じ定数で走っている** — それ自体は望ましい。
  **定数を変えたいときは直下の `settings.h` を直すこと。** ここを編集しても効果は無い。

- ★ **合成データはセンサー座標で渡すこと。** `attitude.cpp` はセンサー座標を受け取り、
  出力の段でマウント回転（`attitude.h` の `imu_body_euler_rad`）を掛ける。
  `main.cpp` の `body_to_sensor()` がその変換。
  以前はここで機体座標のまま流し込み、出力側の `pitch+90` で辻褄を合わせていたため、
  マウントを変えるたびにテストが偽の FAIL を出した（2026-09-22 に廃止）。
  **いまは出力ロールがそのまま機体バンク。** 式を写し取って引き算しないこと。

- PC 側の同等品は [`tools/imulog/eskf.py`](../imulog/eskf.py)。
  **同じ数式の二重実装なので、片方を直したらもう片方も必ず合わせること**（CLAUDE.md の約束）。
  0.983 では水平化（`level_toward_gravity`）・航跡ヨー（`set_heading`）・
  待機中の再水平化とバイアス学習まで両方に入れてある。

## 期待される出力（0.983 時点）

```
--- 協調旋回（旋回中のバンク復元）---
真のバンク角 : 20.00 deg
ESKF 出力ロール     : 19.34 deg  (誤差 -0.66)
結果: PASS — C++ 版も真のバンクを復元した
```

★ 誤差 0.66 度は 0.982 の 0.15 度より大きい。**これは合成データ特有の過渡**で、
このシナリオは「静止 → 直後に 25.6deg/s の旋回開始」という、ヨーを注入した瞬間に
いちばん荒い機動が始まる作り方になっている。実機の離陸は直進なので、
旋回の前に直線を 10 秒挟むと誤差は **0.00 度**になる（2026-10-01 に確認）。
許容 1.5 度に対して余裕があるのでシナリオは変えていない。
