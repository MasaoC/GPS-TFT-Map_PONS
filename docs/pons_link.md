# PONS Link — 機体⇄ボート テレメトリ・ダウンリンク

同一ファームウェアの PONS を 3 台つくり、設定で役割を決める。

| 役割 | 台数 | 置き場所 |
|---|---|---|
| 送信機 (TX) | 1 | 機体 |
| 受信機 (RX) | 2 | 追走ボート／プラットフォーム |

目的は、**パイロットに出ている航法画面をボート側でそのまま再現すること**。
通信は**下り一方向のみ**で、受信側から機体へ返すものは何も無い。

---

## 1. 役割とモード

設定ファイルの `link_mode` で決める（`OFF` / `TX` / `RX`）。3 択のトグルなので
**「送受同時 ON」を表現できない**。取り違えは起動時の音声で気づく。

- `TX` — 従来どおり自機を表示しつつ、1Hz でテレメトリを送信する
- `RX` — 受信したテレメトリで画面をミラー表示する。送信はしない
- `OFF` — 無線を使わない

**起動時に TX / RX のどちらも音声で読み上げる。** 片方だけ読み上げる案だと
「何も言わない＝正常」と受け取られ、無線が OFF になっていることに気づけない。
両方読み上げれば**無音が「OFF」を意味する**ようになり、3 状態が音だけで判別できる。

### 送信機の重複検出

送信機が 2 台同時にいるのは異常事態（機体用とボート用の取り違え等）。
**`seq` の逆行**で検出する。送信機が 1 台なら `seq` は必ず増えるので、
減る・止まるのは 2 台いる証拠になる。10 秒以内に 3 回たまったら警告する
（送信機の再起動でも 1 回だけ起きるため、間隔が空いたら数え直す）。

> 送信元 ID を載せて比較する案は却下した。既定値が 3 台とも同じになるため、
> 「設定を触っていない 2 台がどちらも TX」という**一番ありそうな誤設定で
> 黙って失敗する**。運用に依存しない `seq` のほうが確実。

**検出できるのは受信機だけ。** 送信機は送信の合間スリープしていて受信できない。

## 2. 無線とハードウェア

モジュールは **E220-900T22S(JP)**（920MHz LoRa、技適取得済・免許不要）。
RP2350 から UART で直結する。

| 信号 | RP2350 | 備考 |
|---|---|---|
| UART1 TX → E220 RXD | GPIO8 | |
| UART1 RX ← E220 TXD | GPIO9 | |
| E220 AUX → RP | GPIO30 | 状態通知。100nF を GND へ |
| E220 M0 + M1（結線） | GPIO35 *or* GPIO41 | 0Ω で選択。BNO085 のバス構成と排他 |
| E220 VDD | +3V3 直結 | **VCC は開放**（排他利用）。10µF + 100nF |
| E220 ANT | — | IPEX コネクタを使用 |

- **M0 と M1 は結線して GPIO 1 本で駆動する。** 使うのは mode 0（通常送受信）と
  mode 3（Config/DeepSleep）の 2 つだけなので、データシート 5.3 が明示的に許している。
  WOR は使わない。
- **M0/M1 はモジュール内部で 80kΩ プルアップ**されている。外部プルアップ不要で、
  フローティングでも mode 3 に落ちるため電源投入時に勝手に送信することはない。
- **ピーク電流は 43mA ではなく約 150mA。** 43mA は送信時の平均で、モジュール内部の
  ピーク給電はこれに達する。3.3V レギュレータの余裕とバルクコンデンサを確保すること。

### 無線パラメータ

| 項目 | 値 |
|---|---|
| 帯域幅 | 500 kHz |
| 拡散率 | **SF8（既定）**。設定で SF7〜SF11 |
| チャンネル | **CH0〜12（920.8〜923.2MHz）に限る** |
| 送信出力 | 13dBm（20mW） |
| 送信方法 | **トランスペアレント（固定送信にしないこと → §6）** |

`link_radio_prof` は `0=SF7 / 1=SF8 / 2=SF9 / 3=SF10 / 4=SF11`。
SF を 1 段上げると 2.5dB 強くなるが、**送信時間＝送信電流が倍々に増える**。

**CH13 以上を使ってはいけない。** CH0〜12 は 1 回の送信ごとの休止が 50ms 固定で、
400ms 制限も「休止＝送信時間の 10 倍」も 1 時間 360 秒の総量制限もかからない。
CH13〜30 はこれらが全部かかり、サブパケット長も 32B に強制される。

## 3. タイミングと省電力

本体は低輝度で約 72mA、電池は 860mAh。

- **送信は 1Hz。連射しない。** 1 回落ちても実用上困らず、連射は送信電流と
  電波占有時間を素直に倍にするだけ。
- **送信機は送信直後に mode 3（2.5µA）へ落とす。** UART へ流し込んだあと
  モード切替してよい（モジュールは送信を完了してから寝る）。時刻合わせが不要。
- **受信機は常時 mode 0（8.2mA）。** 本体 72mA に対して 11%、電池持ちで 1 時間の差
  しかないので、位相同期・取得フェーズ・間欠スキャンといった仕掛けは持たない。
  受信機に残るのは「10 秒受信が無ければ NO SIGNAL」という単純なタイムアウトだけ。
- **キャリアセンスで送信が待たされたら、遅らせずにそのスロットを捨てる。**

### 上りの通信を持たない理由

ACK や KEEPALIVE を持つと、受信機 2 台ぶんの衝突回避、送信機側の受信待機、
状態機械の分岐がすべて必要になる。得られるのは「受信機がいない間の送信電力の
節約」だけで、送信は SF8 で 3.6〜5.5mA しかない。**払うコストに見合わない。**

安全上も、上りが無ければ**受信機側の不具合が飛行中の機体へ波及する経路が
原理的に存在しない**。大会レギュレーション上も説明しやすい。

## 4. UART と電波に載せるもの

| | |
|---|---|
| 通常運用 (mode 0) | **115200 8N1** |
| 設定時 (mode 3) | **9600 8N1 固定**（レジスタ設定に関わらず） |

**9600 では `write()` が Core0 を 37.5ms 止める**（68 バイト、ハード FIFO 32B、
arduino-pico に送信バッファは無い）。115200 なら 3.1ms。マップ描画 64ms と
合わせて許容できないため 115200 を使う。

**★ 1 回の `write()` にまとめて渡すこと。分割して書かない。**
E220 は「一定時間データが来ない」ことをパケットの区切りとみなす
（115200bps で >2ms、9600bps で >5ms）。途中で途切れると
**1 回のテレメトリが 2 回の電波発射に分裂**し、占有時間も電力も倍になる。
`write()` はブロックするので、まとめて渡す限り隙間はできない。

### ペイロード

`LinkTelem`（65 バイト、`lora_link/link_proto.h`）。位置・速度・高度・気圧・姿勢・
風・電圧などを詰めたもの。異物の排除は **magic + ver + CRC16** で行う。

**ペイロードを増やすと受信窓と送信電流の両方に直接効く。安易に足さないこと。**

`status` に載せるのは**「受信側からは知りようがない、送信機自身の健康状態」だけ**
（SD エラー・IMU エラー・トリム未適用・電池低下）。
飛行の警告（コース警告・バンク角警告・バリオ音）は**受信側がミラー値から自分で
再計算する**。計算が 1 本のままなので、送信側と受信側で挙動がずれる余地が無い。

## 5. 受信モードの画面と安全

- **どの画面にいても色付きの枠を出す。** 受信モードであることが常に分かるように。
- 地図の左上に役割アイコン（船／飛行機）。受信モードは点滅させる。
- 電池は `S50R40%` の形で**送信側と受信側の両方**を出す。
- **10 秒受信が無ければ**「RECEIVER MODE. NO SIGNAL.」のポップアップを出し、
  自機の情報表示へ戻る。3〜10 秒の間は点滅させて「切れかけ」を示す。
- **NO SIGNAL 中もバリオを含めて全機能が動く。** 万一受信機モードのまま
  離陸しても使えるようにするため。
- ミラー ⇄ NO SIGNAL の遷移は音で知らせる。画面の数値の意味が
  「機体」と「自機」で入れ替わる瞬間なので、見ていなくても気づけるようにする。
- **目的地とナビモードは送信側に合わせて自動で上書きする**（RAM 上のみ）。
  食い違うとコース警告だけが静かにずれる。上書きしたことは必ず音声で知らせる。

### ミラー中に止めること

**受信した機体の値を自機の推定へ入れてはいけない。**

- 自機のカルマン（`imu_kalman_gnss_update`）— 気圧基準と GNSS オフセットが壊れ、
  受信をやめた後まで残る
- `imu_replaydata/` の記録 — 受信した機体の日時のファイルに自機の姿勢を書いてしまう

## 6. E220 を扱う上での落とし穴

**★ 送信方法は必ずトランスペアレント（REG3 bit6 = 0）にすること。**
固定送信モードだと、モジュールは UART に来た先頭 3 バイトを
「宛先ADDH／宛先ADDL／チャンネル」として解釈する。すると環境ノイズ取得コマンド
`C0 C1 C2 C3 00 02` が**「宛先 0xC0C1・ch 0xC2 への送信データ」と誤解され、
コマンドが効かないどころか電波として出てしまう**。症状は「設定は完璧に入って
いるのに RSSI だけ永久に無応答、かつ AUX が Low に張り付く」。

我々の通信は同一チャンネルの全機が受け取るブロードキャストなので宛先指定は
元々不要で、トランスペアレントのほうが素直に合う（ヘッダ 3 バイトも消える）。

**書込みコマンド `0xC0` は不揮発メモリに保存されるので書換え寿命がある。**
設定は電源を切っても残るため、起動時はまず `0xC1` で読み返し、
一致していれば書かない。何度も変える用途では一時書込み `0xC2` を使う。

**AUX は未接続・モジュール不在だと入力が浮いて Low に見える。**
「ビジー」と誤読すると永久に待つので、内部プルアップを入れて
居ないときは High（アイドル）に見えるようにする。

**コマンドの応答を先頭決め打ちで読まないこと。**
受信データやモード切替時のゴミが応答の前に乗る（実測で 69 バイト観測）。
`C1 + アドレス + 長さ` の並びを**検索**して拾い、送信前には受信バッファを捨てる。

## 7. 電波法

- **E220-900T22S(JP) は技適取得済み**で免許不要。920.6〜928.0MHz、最大 13dBm(20mW)
- **アンテナ利得は 3dBi 以下**（EIRP が 16dBm を超えられないため）。
  使用する `TX915-FPC-4510` は 2dBi
- **CH0〜12 に限る**（→ §2）
- キャリアセンス（LBT）はモジュールが必須機能として実装しており無効化できない
- **ボートから機体へ「操作」を送る機能は作らない。** 上りの通信路そのものが
  存在しない（→ §3）ので、遠隔で変更する経路は物理的に作れない

## 8. 実測

| 条件 | 設定 | 到達距離 | 限界RSSI |
|---|---|---|---|
| 芝生（凹凸あり） | 500k SF5 | 約 100 m | −89 dBm |
| 同上 | 500k SF8 | 約 190 m | −99 dBm |
| **海辺・平坦なコンクリート・夜間** | **500k SF7** | **約 350 m** | −100〜−110 dBm |

- 環境雑音は**熱雑音 +7dB（BW500kHz で約 −104dBm）**。屋内外でほとんど変わらない
- **要求 200m を 1.75 倍で満たした**
- 限界 RSSI は「環境雑音 + SF の SNR 閾値」とおおむね一致する
- **1 回目と 2 回目の差（100m→350m）は SF では説明できない。**
  SF5→SF7 の利得は 5dB で距離にすると 1.3〜1.8 倍にしかならず、
  残りを説明するにはさらに 6〜17dB 相当が要る。
  設置条件（平坦なコンクリート／アンテナの置き方）か地点の雑音差か、その両方。
  **この 2 回のデータでは切り分けられない**

### アンテナは SF より効く

**アンテナの角度で RSSI が変動し、パケットロストが始まる**（実測）。
偏波ミスマッチの損失は 45°ずれで 3dB、60°で 6dB、80°で 15dB。
**SF を 1 段上げても 2.5dB** しか稼げない。

低いアンテナ同士では、ある距離から先は損失が距離の 2 乗ではなく **4 乗**で増える
（2 波地面反射）。受信電力は `(h1×h2)²` に比例するので、
**高さ 1m/1m → 2m/2m で +12dB、1m/1m → 3m/10m で +30dB**。
プラットフォームは 10m の高さがあるので、アンテナを最上部に出すだけで
最大の効果が無料で得られる。
