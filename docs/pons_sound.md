# PONS の音 — 仕様の要約

PONS の音は **3 系統**あり、**1 つのスピーカーで同時に鳴る**。
この文書はその 3 つの関係と、どれがどれを止めるのかだけを短くまとめたもの。
音声ファイルの一覧は §9、音声を持たない音は §10 にある。
どんなときに何が鳴るかの説明は [../README.md](../README.md) の「警告音・警報」にもある。

実装は [../src/sound.cpp](../src/sound.cpp)、キューは [../mysd.h](../mysd.h)。

---

## 1. 3 つの音

| 系統 | 何の音か | 出し方 |
|---|---|---|
| **WAV** | 「バッテリー低下」などの日本語音声 | SD の `wav/*.wav` を再生 |
| **トーン** | 操作音・警告のピピッ音 | Sin 波を指定の周波数・長さで |
| **バリオ** | 昇降計。上昇＝断続ビープ / 下降＝連続低音 | Sin 波を常時 |

**3 つとも 16kHz の割り込みの中で足し算して 1 本の PWM に出している。**
だから基本は**全部同時に鳴る**。止め合うのは下の 2 つの場合だけ。

## 2. どの Core が何をするか

```
Core0（画面・センサー・判断）              Core1（SD・音）
  enqueueTask(createPlayWavTask(...))  ──▶  タスクキュー ──▶ 再生開始
  update_vario()  ← バリオだけ Core0 が直接パラメータを書く
```

- **Core0 は「鳴らして」と頼むだけ。**実際に SD を読んで鳴らすのは Core1。
- キューは 40 本。溢れると**捨てられて二度と鳴らない**（USERLED が点灯して知らせる）。
- **バリオだけ例外**で、Core0 の `update_vario()` が 100ms ごとに周波数と断続周期を
  直接書き換える。キューを通らないので、キューが混んでいてもバリオは遅れない。
- 音を出す 16kHz の割り込みは（Core1 で登録しても）**Core0 で動く**。

## 3. 優先度

WAV とトーンは `priority`（数字が大きいほど優先）を持つ。実際に使っている値:

| 値 | 例 |
|---|---|
| 4 | 測位完了 `fixed.wav` |
| 3 | 目的地切替、バンク警告、ESKF 関連の案内 |
| 2 | コース逸脱 `course_left/right.wav`、無線モードの通知 |
| 1 | 電池低下、目的地が遠すぎる、操作音 |

優先度で止め合うのは **WAV 対 WAV** と **WAV 対 `solo_play` トーン**（§4）の 2 つだけ。
**通常のトーンとバリオは優先度で止まらない**（どちらも WAV と足し算されるだけなので、
潰し合わない）。

### WAV 対 WAV

```
新しい WAV を鳴らしたい
  ├ 同じファイルを再生中          → 何もしない（頭から鳴り直さない）
  ├ 再生中の方が高優先            → 新しい方を pending に置いて待つ
  └ 新しい方が同等以上            → 再生中を pending に退避して割り込む
                                     （終わったら pending の中で一番高いものを再生）
```

- pending は **2 件まで**。両方埋まっているときは、新しいほうが既存の最低優先度より
  高ければ入れ替え、そうでなければ**新しいほうを捨てる**。
- pending から復帰した WAV は**もう一度は退避されない**。
  退避すると必ず先頭から鳴り直すので、放っておくと冒頭の断片だけが繰り返される。

## 4. 同時に鳴るか、止まるか

| 組み合わせ | どうなる |
|---|---|
| WAV ＋ バリオ | **同時に鳴る** |
| トーン ＋ バリオ | **同時に鳴る** |
| WAV ＋ 通常トーン | **同時に鳴る**（優先度も見ない。短い操作音が音声を潰さないため） |
| WAV ＋ `solo_play` トーン | **排他**。下記 |

`solo_play` は「この音を先に聞かせてから音声を流したい」ときに使う。
コース逸脱警告が `ピピピ → course_left.wav` の順で鳴るのはこれ。
使っているのは **コース逸脱警告** と **Auto10km の折返し通知（往路→復路・復路→往路の両方）** だけ。
Auto10km の 2 つは**必ず同じ指定にすること。**片方だけ通常トーンにすると、同じ
「目的地が切り替わった」通知なのに一方は音声と重なって鳴り、聞き分けを誤る。

```
solo_play トーン中に WAV が来た
  ├ WAV の方が高優先  → トーンを一時停止 → WAV → トーン再開
  └ WAV が同等以下    → WAV を pending へ → トーン完走 → WAV
```

## 5. 音量

設定画面に **音量**（`sound_volume`）と **バリオ音量**（`vario_volume`）があり、独立している。

- `sound_volume = 0` … WAV とトーンが鳴らない。
  WAV はアンプも ON にしない（ポップノイズ防止）が、**トーンはアンプを ON にしてから
  無音を出す**（`startNextToneEntry()` が音量を見ていない）。実害はポップ音だけ
- `vario_volume = 0` … バリオが鳴らない
- `vario_inhibit = true` … バリオを完全に無効化。**SD の `settings.txt` でしか設定できず、
  設定画面からは変更できない**（バリオ非搭載機向け）

**`min_volume`（最低保証音量）** を指定した音は、`sound_volume` が小さくても
その値まで引き上げて鳴らす。

★ **これを付けてよいのは電池切れの警告だけ**（`battery_low.wav` と
`battery_low_sender.wav`、値は 60）。**持ち主が機体から離れていても電池切れに
気づけるように**という目的だけで入れた仕組みで、他の警告にも付けると
「音量を絞ったのに全部の警告が大音量で鳴る」ことになり、絞った意味が無くなる。

上昇音は下降音より小さく出る。小型スピーカーは高音の能率が高く、
同じ振幅だと上昇側だけうるさくなるため `VARIO_ASCEND_VOL_PCT` で絞ってある。

## 6. バリオの鳴り方

`update_vario()` が 100ms ごとに昇降率を見て決める。

```
上昇率 > デッドバンド   → 断続ビープ。速いほど高く、間隔が短い
下降率 > デッドバンド   → 連続低音。  速いほど低い
その間（デッドバンド内）→ 無音
```

実際の値（KF 融合時。デッドバンド ±0.25m/s）:

| 昇降率 | 上昇 | 下降 |
|---|---|---|
| 0.25 m/s | 804Hz　ON 120ms / OFF 2572ms | 554Hz 連続 |
| 0.5 m/s | 900Hz　ON 120ms / OFF 1280ms | 530Hz 連続 |
| 1.0 m/s | 1100Hz　ON 120ms / OFF 580ms | 480Hz 連続 |
| 1.5 m/s 以上 | 1300Hz　ON 120ms / OFF 346ms | 430Hz 連続 |

- **デッドバンドは 2 段階**。BNO085 と MS5611 が両方生きていれば ±0.25m/s、
  BNO085 が応答しなければ MS5611 単独にフォールバックして ±0.60m/s に広げる。
- **上昇・下降とも 1.5m/s で振り切り**（それ以上速くても音は変わらない）。
- **この定数は音と画面で共用している。**VSI のグレー線も同じデッドバンドを見るので、
  片方だけ変えると「線は出ているのに鳴らない」になる。

## 7. WAV ファイルの条件

**16kHz / 8bit unsigned PCM / モノラル / メタデータなし。**
先頭 44 バイトをヘッダとして読み飛ばすだけなので、これ以外の形式は雑音になる。

- 16KB（約 1 秒）ずつダブルバッファで SD から読む。SD が遅れると
  一瞬途切れるが、1 秒待っても埋まらなければ再生を打ち切る（無音で固まらない）。
- **SD が無いときに代わりのトーンを鳴らす経路があるのは一部だけ**。
  `good_sd()` を確認してから鳴らしているのは `opening` / `fixed` / `track` /
  `battery_low` / `eskf_calib_required` と、`link_*` 全部（`link_alert()` 経由）。
  **それ以外（`bank_warning` / `course_left,right` / `roll_check` / `pitch_check` /
  `destination_change` など）は SD が無くても WAV を要求する**ので、
  下の「ファイルが開けない」経路に落ちて 500Hz ×2 になる。
- **SD はあるがファイルが無い**場合も同じく 500Hz ×2。ただし
  **SD を故障扱いにはしない**（§9 の注意を参照）。

## 8. 触るときの注意

- **警報を描画関数の中に書かない。** その画面を出しているときしか鳴らなくなる。
  発報は `loop()` の最上位へ（[../CLAUDE.md](../CLAUDE.md)）。
- **同じ音を連続で積まない。** WAV は同一ファイルの再要求を弾くが、
  トーンは弾かないのでキューが埋まる。
- `enqueueTaskWithAbortCheck()` は**キューにある同じ種類のタスクを消してから**積む。
  4 音のトーン列などで、古い警告が残って二重に鳴るのを防ぐために使う。
  列の 1 音目だけをこれにして、2 音目以降は普通の `enqueueTask()` にする。

### 無線（PONS Link）

`link_*` はすべて `link_alert()` 経由なので **優先度 3 で固定**。
SD が無い機体では、それぞれに割り当てたトーンが代わりに鳴る。
最低音量を付けているのは `battery_low_sender.wav` だけ（上記の理由）。

| ファイル | 優先度 | min | いつ鳴るか | 内容 |
|---|:--:|:--:|---|---|
| `sender_mode.wav` | 2 | | 送信（TX）モードで起動した／TX へ切り替えた |パイロット用・送信モード|
| `receiver_mode.wav` | 2 | | 受信（RX）モードで起動した／RX へ切り替えた |観測用・受信モード|
| `link_no_signal.wav` | 3 | | 受信機で、機体からの電波が途絶えた |無線モジュールが応答しません|
| `link_dup_sender.wav` | 3 | | 受信機で、同じグループの送信機が 2 台いると判定した。**続いている間は 1 分ごとに繰り返す**（1 回きりだと聞き逃したら二度と鳴らないため） |送信機が２台あります|
| `link_no_module.wav` | 3 | | 無線モジュールが応答しない |受信が途切れました。自機の情報を表示します。|
| `link_setting_changed.wav` | 3 | | CH / SF / グループを変えたまま設定画面を出た |送信機と受信機の設定が一致していることを確認してください。|
| `link_override_dest.wav` | 3 | | 受信機で、機体側の目的地・ナビモードに自動で合わせた |警告。送信機に合わせるため目的地と誘導モードを自動で変更しました。|
| `link_ch_busy.wav` | 3 | | 送信前チェックで、同じチャンネルに他の送信機を見つけた |同じチャンネルに他に送信機がいます。設定を確認してください。|
| `link_ch_noisy.wav` | 3 | | 送信前チェックで、チャンネルの雑音が高かった |このチャンネルはノイズが多いです。チャンネル変更を検討してください。|
| `battery_low_sender.wav` | 3 | 60 | 受信機で、**送信機（機体）の**バッテリー低下を検知した |送信機側のバッテリーが低下しています。|

### 注意

- **ファイル名はコードに直接書いてある。**名前を変えると、その音声は二度と鳴らない。
- **ファイルが無いとき・壊れているときは無音にはならず、500Hz ×2 のエラー音が鳴る。**
  どのファイルで失敗したかは `log.txt` に残る。
  - `ERR wav missing: <名前>` … ファイルが無いだけ。**SD は正常扱いのまま**
  - `ERR wav open: <名前> (SD err 0xNN)` … カード側の異常。SD をエラー扱いにする
    （フッタの SD 表示が赤、USERLED 点滅、10 秒ごとに再初期化）
  - `ERR wav too small: <名前>` … 44 バイト以下。書き出しミス。SD は巻き込まない

  区別は SdFat のカード層エラーコードで行う。FAT 層の「そのパスが無い」は
  カード層のエラーにならないので、**0 のままなら「カードは応答している」**と分かる。
- 全 30 ファイルがコードから参照されていて、未使用のものは無い。

## 11. 音で知らせていない警告

画面には出るが**音は一切鳴らない**ものがある。飛行中は画面を注視できないので、
ここに挙がっているものは「見ていなければ気づけない」と考えること。

| 表示 | 状態 |
|---|---|
| `ESKF Not ready` | 姿勢推定がまだ収束していない（通常は数秒で消える） |
| `Rtrim` がオレンジ／赤 | 自動ロールトリムの累積が大きい（1.5°／3.0°） |
| `Acc: XXm` | 水平位置精度が 10m 以上 |

自動ロールトリムが適用された瞬間も、ログと設定保存だけで音は鳴らない。

**`ESKF CALIBRATION REQUIRED!` だけは例外で、音も鳴らす。**
姿勢表示・バンク角警告・自動ロールトリムがまとめて信用できなくなる状態で、
地上で気づかないまま飛ぶと取り返しがつかないため。
ただし **鳴るのは地上で静止しているときだけ**で、飛行中は鳴らさない
（飛行中に較正はできず、対処できない警告で注意をそらすほうが危険）。
画面表示のほうは 3 秒のうち 1 秒だけ点滅させ、万一飛行中にこの状態になっても
地図を隠し続けないようにしてある。あわせて **ヘッダーの `Pavg` に赤い横バーを重ねて**、
その数字が信用できないことを示す（GNSS 0 個で速度・方位が無効になるときと同じ見た目）。
