# SCH16T-K01-10 導入計画 — 変更が必要な箇所の洗い出し

BNO085 の加速度・ジャイロ精度に課題があるため、Murata **SCH16T-K01-10**（SPI）を導入し、
**設定で BNO085(I2C) / SCH16T(SPI) を選べる**ようにする。

この文書は**実装前の準備**。モジュールが届いたら
[tools/sch16t_test/](../tools/sch16t_test/) で単独テストを済ませ、そのあとここの順番で融合する。

**0.983 で §2.2（ESKF の GRV/RV 依存）と §2.3（バリオの GRV 依存）は先に片付けた。**
どちらも BNO085 のままで実ログによる無回帰確認ができたため、SCH16T が届く前にやっておいた。

- 単独テストのスケッチと手順 → [tools/sch16t_test/README.md](../tools/sch16t_test/README.md)
- 現状（BNO085 I2C）の立ち上げ記録 → [imu_i2c_bringup.md](imu_i2c_bringup.md)

## 0. 前提 — 「ドライバの差し替え」では済まない

2 つのセンサーは**出てくるものが違う**。

| | BNO085 | SCH16T-K01 |
|---|---|---|
| 生ジャイロ・加速度 | あり | あり（20bit, 1600 LSB/(°/s), 3200 LSB/(m/s²)） |
| 融合クォータニオン | **GRV / RV** | **無し** |
| 地磁気 | あり | **無し** |
| 動的校正（DCD）と申告精度 | あり | **無し** |
| 故障・飽和ステータス | quat の健全性のみ | **STAT_* が 10 本。CRC 付き 48bit フレーム** |
| ODR | レポートごとに要求 | 11.8kHz を間引いて 738Hz〜 |

**消えるものが 4 つある。うち 3 つは片付けた（1・2 は 0.983、3 は 0.984）。**

1. ~~**GRV** … バリオ KF の重力除去と姿勢 ESKF の初期化~~
   → **0.983 で依存を除去**（§2.2 / §2.3）。生の加速度から水平化する
2. ~~**RV** … ESKF の初期ヨー（磁北基準）~~
   → **0.983 で依存を除去**。GNSS 航跡から入れる。**精度も上がった**（磁気は 57.8 度ずれていた）
3. ~~**地磁気** … 生ログと比較表示に残るだけ~~
   → **0.984 で購読をやめた**。`IMULOG_ID_MAG`（0x03）は欠番（§2.4）
4. **DCD と申告精度** … 画面（IMU/ESKF 2/3 ページ）と長押し保存、EEPROM の保存記録。**未着手**

逆に**増えるもの**もあり、そちらは画面とログに出す先が必要になる
（STAT_SUM 系の故障ビット・飽和カウンタ・CRC エラー数・実 ODR）。

## 1. 抽象化の切り方 — **境界は 0.984 で入れた（ファイル分割は未了）**

`imu.cpp` は約 1900 行あり、うち大半は **BNO085 固有の「壊れやすい約束」**
（`sh2_close()`、i2c バス復旧、未使用ピンの park、レポート飢餓対策）。
これを SCH16T 側に持ち込みたくないので、**チップ依存を別ファイルに割る**ことを推奨する。

### 0.984 で入れたもの — [imu_sensor.h](../imu_sensor.h)

**ファイルはまだ割っていない。** 先に「境界」だけを作った。割るのは
ドライバを書くときで、そのとき `imu.cpp` から**印の付いた範囲を動かすだけ**になる。

1. **能力ビット** `imu_caps()` … そのチップから何が出るか
   （`IMU_CAP_QUAT` / `MAGYAW` / `MAG` / `LINACC` / `CAL` / `STATUS`）。
   **融合出力に触る画面とログを全部これで囲んだ**ので、SCH16T でビットを落とせば
   表示とログが自動的に縮退する。囲まないと「0 を本物として出す」ことになり、
   姿勢比較の行は **0 が「水平で北向き」というもっともらしい値**になる
2. **feed の口** `imu_feed_gyro()` / `imu_feed_accel()` …
   ドライバはこの 2 つを正しいレートで呼べばよい。中で姿勢 ESKF の伝播と
   バリオの蓄積へ配る。**SCH16T のドライバが書くべきチップ非依存のコードは無い**
3. 生ログの `imulog_push()` は**ドライバ側に残した**。レコードの `s_us` と `acc` が
   チップ固有で、境界へ移すと退避済みの過去ログとバイト互換でなくなる

### まだやっていない（ドライバと同時にやる）

```
imu.cpp          … バリオ KF（3状態）・GNSS 観測・ゲッター。★ チップ非依存にする
imu_bno08x.cpp   … 現 imu.cpp のチップ依存部を移動（新規）
imu_sch16t.cpp   … SCH16T ドライバ（新規。tools/sch16t_test のフレーム層を持ち込める）
```

- 上のファイル分割と `imu_drv_*`（`setup` / `service` / `alive` / `recover`）。
  **実体の無い宣言は置いていない**ので、宣言もドライバと同時に足す
- `settings.txt` の `imu_sensor` キー。**値が効かない設定を先に作ると嘘になる**ので
  ドライバと同時。いまは `IMU_SENSOR_DEFAULT`（ビルド時）だけで、SCH16T を選ぶと
  `#error` で止まる

★ 能力ビットと feed の口の**実際の定義は [imu_sensor.h](../imu_sensor.h) にある**。
ここに写すと必ず食い違う（0.984 の実装で `IMU_CAP_LINACC` が増えて番号がずれ、
この計画書の案だけが古いままになっていた）。

★ **`imu_service_if_due()` の役割が変わる。** BNO085 では
「読まないとレポートが溜まってジャイロが化ける」ための飢餓対策だが、
SCH16T は**こちらが SPI で取りに行く**方式なので飢餓が起きない
（読まなければ DRY が立ったままになるだけ）。
**ただし CLAUDE.md とコード中の飢餓対策コメントは消さないこと。** BNO085 に戻す可能性がある。

### 2.2 姿勢 ESKF — **0.983 で完了**

GRV / RV への依存は外した。**生のジャイロと加速度だけで初期化できる。**

| | 0.982 まで | 0.983 |
|---|---|---|
| 初期ロール・ピッチ | GRV の静止平均 | **静止中の平均加速度から水平化**（`level_toward_gravity`） |
| 初期ヨー | RV（地磁気）＋偏角補正 | **GNSS 航跡から注入**（`init_yaw_from_track`） |
| 待機中の維持 | 不要だった（GRV が常時重力基準） | **静止中の再水平化＋ジャイロバイアス学習** |
| 速度観測 | 初期化直後から | **ヨー設定までゲート** |

削除したもの: `attitude_on_grv()` / `attitude_on_rv()` / `apply_declination()` /
`ESKF_INIT_USE_RV` / `ESKF_RV_ACC_MAX_DEG` / `ESKF_MAG_DECLINATION_DEG` /
`ESKF_INIT_YAW_SIGMA_DEG`（→ `ESKF_YAW_UNKNOWN_SIGMA_DEG` と `ESKF_YAW_INIT_SIGMA_DEG` に分割）。
`attitude_yaw_from_mag()` は `attitude_get_yaw_source()` に置き換えた。

#### 実ログでの検証（20260930 の 52 分 + 20260818 の 5 セッション）

| 項目 | 結果 |
|---|---|
| 加速度水平化 vs GRV のロール・ピッチ | **差 0.05 度以内**（最大 0.4 度）。GRV は初期姿勢に何も足していなかった |
| 航跡ヨーの注入 | 要求方位に厳密一致。**ロール・ピッチの変化 0.0000 度** |
| 地磁気ヨー vs GNSS 航跡 | **57.8 度ずれ**（20260930・現マウント。BNO085 は「25 度以内」と申告） |
| eskf.py 新旧比較（現ファームのログ） | ロール・ピッチ差の中央はほぼ 0。ヨーは GNSS 航跡基準で**散らばりが改善**（s5: sd 23.8→13.3 度） |

★ **ヨーには両経路に共通の +14〜24 度の系統オフセットが残る。** 車載時の
デバイスの取り付けヨー角（車軸と平行でない）で説明がつき、**新旧で同じなので回帰ではない**。
機体では airframe に合わせて取り付けるので出ないはず。**実機で確認する項目。**

#### 残る挙動差（既知・許容と判断）

- **GNSS があるのに対地速度が 3m/s を超えない状態が続くと、ESKF に観測が 1 つも入らない。**
  0.982 までは測位が来た時点で観測が入っていた。ボートがアイドルで漂っているときなどに該当する。
  運用速度（追走ボートは 7〜8m/s）に乗れば自動的に解消する。**§6 の Phase 2 で消える。**
- **注入した航跡が間違っていれば（受信不良・取り付けヨー角）、その誤差はロール・ピッチにも回る。**
  σ=15 度ぶんは吸収するが、それ以上は収束待ちになる。`ESKF_YAW_INIT_ARM_FIXES=2` で
  単発の化けは弾いている。

### 2.3 バリオ KF — **0.983 で完了**

[imu.cpp:397 付近](../imu.cpp) の上方向の出どころを GRV から ESKF の姿勢へ移した。
**式は変えていない** — `attitude_get_up_sensor()` が返すのは回転行列の第 3 行で、
`compute_earth_z_accel()` が GRV から作っていた係数と同じもの。

実ログでの V/S の差:

| ログ | V/S 差 sd | \|max\| | \|差\|>0.1m/s | 高度差 \|max\| |
|---|---|---|---|---|
| **20260930 s1（52 分・トンネル込み）** | **0.021** | **0.432** | **0.81%** | **0.15 m** |
| 20260818 s1 | 0.025 | 0.176 | 1.02% | 0.12 m |
| 20260818 s2 | 0.012 | 0.073 | 0% | 0.02 m |
| 20260818 s3 | 0.060 | 0.319 | 8.99% | 0.26 m |

V/S 自体の sd は GRV 0.320 / ESKF 0.319 で同一（20260930）。
20260930 s1 だけ「静止中の再水平化＋バイアス学習」を入れた実装どおりで測り直してある
（入れる前は sd 0.030 / >0.1 が 1.66% / 高度差 0.33m だった。**維持ロジックが効いている**）。
20260818 の 3 件は維持ロジック無しの値なので、実装どおりならもう少し良くなる。

★ **最大差の 2 件はどちらも「その前後 3 秒に使える測位が 0 件」の瞬間だった。**
ESKF の観測は速度だけなので、GNSS が無い間ロール・ピッチには重力の錨が無い
（GRV には BNO085 内部の重力融合が常時あった）。傾き誤差 θ の a_k への効きは
g(1−cosθ) で θ=1 度 → 0.0015、5 度 → 0.037 m/s² と**二乗で効く**ので、
数度までなら無害。バリオ KF のバイアス状態もゆっくりした誤差を吸う。

#### 残る挙動差（既知・許容と判断）

- ~~ESKF が水平化できていないあいだ、バリオは気圧のみに劣化する~~
  ★★ **これは誤りだった。劣化ではなく「完全停止」で、2026-10-01 に実機で発覚した。**
  機序: **バリオ KF の初期 P は対角なので、predict を一度も通らないと P[1][0] が 0 の
  ままになる。気圧観測のゲインは K[1] = P[1][0]/S なので 0 で、速度状態が構造的に
  1 度も動かない。** 高度 kf_x[0] は K[0] で追従するため「センサーは生きているのに
  V/S だけ 0 で固まる」という見え方になった。既存の縮退経路は**高度にしか効かない。**
  しかも水平化は静止 2 秒が条件なので、**手持ちテストでは成立しない**
  （実ログ 38 秒で |ω| 中央 5.13deg/s、2 秒連続の静止区間が 1 つも無かった）。
  → **対策済み**（`up_lp_` による常時の重力方向＋「上方向が無くても predict は止めない」）。
  再発防止テストは `tools/attitude_test/yaw_test.cpp` の E。

  ★ 教訓として残す: **「観測だけで状態が動く」と思ってはいけない。**
  共分散の非対角は predict でしか作られないので、predict を止めると
  その状態は観測から切り離される。

**Phase 2（別途・任意）: ESKF に重力観測を足す。** → 詳細は §6。

★ **`KF_R` / `KF_Q_VEL` / `KF_Q_BIAS` の再測定は SCH16T へ切り替えるときに行う。**
0.983 の時点では重力除去の出どころが変わっただけで、上表のとおり V/S はほぼ同一なので
BNO085 のままなら再調整は不要と判断した（走行中の V/S sd も 0.263 → 0.263 で変化なし）。
SCH16T はノイズ特性が違うので、そのときに測り直す。

### 2.4 生 IMU ログ

[src/imulog.h](../src/imulog.h) の ID のうち **MAG / GAMERV / RV / LINACC が出なくなる**。
**MAG（0x03）は 0.984 で先に止めた**（地磁気は推定にも表示にも使っていないため）。

- 形式は変えず「出ない」だけにするのが安全。`decode_imulog.py` は種別ごとに分けているので空になるだけ
- ★★ **止めた ID を別の用途に再利用してはいけない。** 退避済みの過去ログ
  （〜2026-10-03）は id でレコードを解釈するので、別の意味を割り当てると
  **古いログが静かに誤デコードされる**。`src/imulog.h` に欠番として残してある
- ★ **BOOT レコードに「どちらのセンサーで録ったか」を残すこと。**
  でないと後から解析するときスケールも単位も判断できない。
  `s_us` の枠は `BUILDDATE` で埋まっているので、`acc` の枠か新 ID を使う

### 2.6 校正・EEPROM

- `imu.cpp` の `ImuCalRec`（EEPROM に DCD 保存記録）は SCH16T では不要
- `settings.txt` の `calib_date` の意味が変わる
- ★ **自前のジャイロ ZRO は 0.983 で入れた（実装済み・PC テスト済み）。
  ただし実機検証は SCH16T を載せてからでないとできない。**
  BNO085 は静止出力が厳密に 0 なので、学習しても `bg_ = 0` になって変化が見えない。
  **SCH16T に替えた瞬間に初めて意味を持ち、同時に必須になる。**
  フラッシュ保存はしない。
  `attitude.cpp` の `learn_gyro_bias()` が静止中に毎回測り直す（→ `settings.h` の
  `ESKF_BIAS_LEARN_SAMPLES`）。
  **保存しない理由**: SCH16T の offset drift velocity は ±0.01(deg/s)/min（0.5K/min 時）で、
  起動後の昇温（実測 CPU 20→36℃）で動く。焼いた定数は次の起動では合わない。
  一方 bias instability は 0.3〜0.5 deg/h しかないので、**その飛行の中では一度測れば
  最後まで有効**。毎回測り直すのが正しく、EEPROM を触らないので実装も軽い。

## 3. ハードウェア — **v7.1 基板で確定（2026-10-07）**

**SCH16T 実装時は BNO085 をセンサーごと基板から降ろす**（2026-10-01 決定）。
これでピンの競合が消えたので、空いた SPI1 の正規割り当てをそのまま使う。
**ネットリストから確認済みで、`settings.h` の `SCH16T_PIN_*` が正本。**

★ **基板の選択は `settings.h` の `PONS_BOARD`**（`PONS_BOARD_V7` / `PONS_BOARD_V71`）。
下の表と同じ対応がそこに 1 つだけ置いてあり、ピン定義と `IMU_SENSOR_DEFAULT` は
そこから分かれる。0.986 までは「新基板では〜」という散文の断り書きが
5 ファイル 20 箇所に散っていた。

| GPIO | ネット | 役割（v7.1） | v7 では |
|---|---|---|---|
| 41 | `SPI1_CS` | SCH16T の CS | E220 の M0/M1 |
| 42 | `SPI1_SCK` | SCK | i2c1 と 0Ω 連結（R46/R47 は消滅） |
| 43 | `SPI1_TX_MOSI` | MOSI | `IMU_I2C_SA0_PIN` |
| 44 | `SPI1_RX_MISO` | MISO | i2c1 と 0Ω 連結 |
| 45 | `SCH16T_RESET` | EXTRESN（負論理） | BNO_INT |
| 46 | `SCH16T_SYNC` | DRY_SYNC（入力） | BNO_NRST |
| 47 | `LORA_M01` | **E220 の M0+M1 を結線して 1 本で駆動** | BNO_PS0/WAKE |

- SCH16T は基板実装ではなく **J7（Molex 200528-0080, 8pin FPC）経由の外付け**。
  `kicad/IMU_murata/` のブレイクアウトと 1:1 ケーブルで繋がる

  arduino-pico では **`SPI1`**（`SPI` は spi0）。GPIO46 が SPI1_SCK の代替機能でもあるので
  **`SPI1.setSCK(42)` を明示する**

## 5. SCH16T の仕様（実装に必要な分）

**2026-10-01 にフルデータシート（Doc.No.11624 Rev.6, 65 ページ）で全件照合済み。**
検証の詳細と、PX4 / 先駆者ライブラリとの相違点は
[tools/sch16t_test/README.md](../tools/sch16t_test/README.md) の「検証状況」節にある。

| 項目 | 値 |
|---|---|
| SPI | mode 0（CPOL=0/CPHA=0）、48bit フレーム、SCK **0.095〜10.5MHz**（下限もある） |
| フレーム | `TA[47:38]`（上位 2bit=CS / 下位 8bit=レジスタ）`\| RW[37] \| FT[35] \| DATA[27:8] \| CRC8[7:0]` |
| CRC8 | 多項式 0x2F・初期値 0xFF・XOR out なし・bit 47〜8 が対象 |
| **応答** | **1 フレーム遅れて返る**（SafeSPI アウトオブフレーム）。先頭に捨てフレームが必要 |
| ステータス | 応答の [36]IDS [35]CE [34:33]S1:S0（00=正常 01=エラー 10=飽和 11=初期化中） |
| 感度（20bit 既定） | ジャイロ 1600 LSB/(°/s)、加速度 3200 LSB/(m/s²)、ACC3 1600、温度 100 LSB/°C |
| レンジ | ±327.68 °/s、±163.84 m/s²（ACC3 ±260 m/s²）。**設定 `'000'` は書いてはいけない** |
| ODR | 間引きなし 11.8kHz / 5.9k / 2.95k / 1.475k / **737.5Hz** |
| フィルター | LPF0 68Hz（既定）/ LPF1 30 / LPF2 13 / LPF3 280 / LPF4 370 / LPF5 235 / LPF7 バイパス |
| 初期化 | リセット → **32ms**（NVM）→ 設定 → `EN_SENSOR` → **215ms** → ステータス 1 周 → `EOI` → **3ms** → ステータス 2 周 → 検証 |
| 品種 ID | **`COMP_ID = 0x0023` が SCH16T-K01。** `ASIC_ID` はシリコンのリビジョンなので品種判定に使えない |
| 出力 | `*_1` = 補間（実効 ODR 極大・ジッタ<2.6µs）、`*_2` = デシメーション（DRY が紐づく）、`*_3` = 広レンジ補助加速度 |

### ★ 統合設計に効く 2 点（今回の照合で判明）

**(1) `EOI` を書くとソフトリセットと `SYS_TEST` 以外の R/W レジスタが全部ロックされる**（Table 80）。
リセットしない限り解除できず、ロック後に書くと `CE`（コマンドエラー）が立つ。

→ **設定画面からフィルターやレンジを実行中に変えることはできない。**
`imu_sensor` の切替を「起動時のみ有効」にする方針（§2.1）と同じ扱いにする。
逆に言えば **EOI を立てておけば設定が壊れない**ので、立てない選択はしないこと。

**(2) LPF ごとに「最小推奨読み出しレート」がある**（§5.5 Table 16）。
下回るとフィルター阻止域のノイズが折り返して帯域内に入る。

| LPF | カットオフ | 最小推奨読み出しレート |
|---|---|---|
| LPF2 | 13Hz | 150Hz |
| LPF1 | 30Hz | 200Hz |
| **LPF0（既定）** | **68Hz** | **500Hz** |
| LPF3/LPF5 | 280 / 235Hz | 1000Hz |
| LPF4 | 370Hz | 2000Hz |

→ **現状の BNO085 は 50Hz でレポートを要求している。同じ感覚で SCH16T を 50Hz で読むと
折り返す。** 選択肢は 3 つあり、実装前に決める必要がある。

1. **LPF2（13Hz）にして 150Hz 以上で読む** — HPA の運動帯域は 5Hz 以下なので帯域は足りる。
   Core0 の負荷は 150Hz × 8 フレーム。素直
2. LPF0 のまま 500Hz 以上で読み、ソフトで間引く — 帯域は広いが Core0 の負荷が増える
3. デシメーション出力（`*_2`）を DRY 割り込みで読む — ジッタ最小。ただし 737.5Hz が下限で、
   その全数を読むのは PONS には過剰

データシートが「水平検出・測位用の IMU」に推奨しているのは
**「既定設定（LPF0・補間出力）を最小推奨レートで読む」**＝ 選択肢 2。
ただし PONS の用途では 1 が妥当に見える。**単独テストで両方のノイズを実測して決める。**

### まだ触っていないもの

- **`CTRL_ST`（セルフテスト）** — ビット配置は判明済み（Table 78）。`RATE_STC_CTRL[11:9]` の
  リセット値が `3b111` など 0 でないビットがあるので、ここも read-modify-write が必要。
- `CTRL_*_FLAG_*`（飽和フラグのフィルター設定）— 既定 0 のまま。

### ★ 破ると静かに壊れる約束（SCH16T 側。CLAUDE.md に足す候補）

- **`CTRL_USER_IF` と `CTRL_ST` は read-modify-write すること。** リセット値が 0 でない
  ビットがある。`CTRL_USER_IF` を素で書くと `MISO_SR_CTRL` / `DRY_SR_CTRL` を 0 に落とし、
  データシートが *"not supported by Murata"* と書いている側の設定になる。
  **PX4 のドライバはこれを踏んでいる**ので、あちらを参考にするときは注意。
- **読み出しは 1 フレーム遅れる。** 先頭の捨てフレームを落とすと、
  全軸が 1 つ前のレジスタの値になる（`gx` に前回の何かが入る、という形で静かに壊れる）。
- **`DYN_*` に `'000'` を書かないこと**（CTRL_RATE / CTRL_ACC12 では "Undefined"）。
- **`DRY_SYNC` を出力にしないこと。** SYNC 入力との兼用ピン。
- **`EOI` 後は設定を変えられない。** 変えたければリセットからやり直す。

### 期待される改善（比較の基準）

| 項目 | BNO085 実測 | SCH16T データシート typ |
|---|---|---|
| `\|a\|/g` | 0.985〜0.992（約 −1%） | 1.000 に乗るはず |
| 加速度ノイズ | σ = 0.0008 g（2Hz LPF 後） | オフセット ±0.01 m/s² |
| ジャイロ | 申告精度 0 のまま・ZRO 温度ドリフト | オフセット XY ±0.1 / Z ±0.01 °/s、ノイズ密度 XY 0.0004 °/s/√Hz |

BNO085 側の数値は `tools/imulog/` の解析より
（→ `memory/vertical-g-estimation.md`）。`|a|` はノルムなので回転不変で、
マウント角のずれに依らずスケール誤差を比較できる。

## 6. Phase 2 — ESKF に重力観測（levelling update）★ **0.984 で完了・実機検証済み**

0.983 で GRV を外したときに**残した穴**を埋める作業。**両センサー共通で効く**ので
SCH16T より先にやった（BNO085 が載っているうちなら GRV を参照値にして検証できる）。

### 6.1 なぜ必要だったか

ESKF の観測は **GNSS 速度だけ**（`H = [0 I 0 0]`）なので、ロール・ピッチは
`d(dv)/dt = −[Rf]×dθ` の結合を通して*間接的に*しか拘束されない。
つまり **GNSS が無い間、重力の錨が 1 つも無い**（BNO085 の GRV が内部で担っていた）。
`eskf.py` の `gnss_cutoff` で測ると GNSS 断 2 分で 2〜4 度ずれ、
**バンク警報のしきい値 4 度**（`BANK_WARN_DEG`）に届く。誤警報にも見逃しにも効く。

同時に消えた穴が 2 つ:

1. トンネル等の GNSS 断（0.983 のバリオ V/S 差の最大値 2 件は、どちらも
   「前後 3 秒に測位 0 件」の瞬間だった）
2. 「GNSS はあるのに対地速度が 3m/s に届かない」と観測ゼロ（§2.2 の残存挙動差）

### 6.2 何をしたか

準定常のとき、比力をワールドへ回した `f_w` は `(0,0,g)` になるはずなので、
**その水平 2 成分を期待値 0 の観測として入れる**（2Hz）。実体は `attitude.cpp` の
`level_update()`、定数は `settings.h` の `ESKF_LEVEL_*`。

★ **ゲートが本体。** 無条件に入れると協調旋回でバンクを過小評価し、GRV と同じ
間違い＝ ESKF が存在する理由を壊す。主ゲートは**旋回レート**で、`|f| ≒ g` は
粗い健全性チェックにしか使わない（5 度バンクの `|f|-g` は 0.0375 m/s² で、
加速度計のスケール誤差 0.098 m/s² に埋もれる）。**導出と数値はすべて
`settings.h` の `ESKF_LEVEL_*` のコメントにある**（ここには書き写さない）。

60 秒ログに `gobs=` で累計回数が出る。**0 のままならゲートが閉じている。**

### 6.3 検証結果

| 検証 | 結果 |
|---|---|
| **実機 2 時間（2026-10-03 走行）GNSS 断時の \|誤差\|** | 中央 **21.3° → 1.3°** / **74.9° → 1.8°** |
| 同・ゲート開口率（実機 `gobs=` 実測） | 走行中 **58〜61%** / 静止中 **97%** |
| オフライン（20260818 s1、短い窓） | 中央 5.04° → 2.44° |
| 協調旋回 20 度（`main.cpp`、真値既知） | **19.34° で Phase 2 前と完全に同一** |
| 5 度バンク相当の旋回レートで観測が入るか（`yaw_test` F2） | **30 秒で 0 回** |
| 直進・静止で観測が入るか（F1） | 10 秒で 20 回（2Hz どおり） |
| GNSS 無しでロール・ピッチの錨になるか（F3） | 0.5°/s のオフセットで 2 分、ロール変化 **0.00°** |
| GNSS 常時のときの姿勢変化 | 中央 0.21〜0.29°。**旋回レートで層別しても一様**＝ゲート漏れなし |

★ **「静止中の再水平化」(0.983) は残した。** 役割が違う:

- 再水平化（相補フィルタ・50Hz・時定数 1 秒）… 待機中の維持。同ブロックの
  `reset_covariance` が毎サンプル P を戻すので `level_update` が溜めた情報はどうせ
  捨てられる。実効の引き戻しはこちらが担う
- `level_update`（正式な観測・2Hz）… 飛行中と GNSS 断中の錨

1 つに統合するのは、待機中の挙動（`yaw_test` の D1/D2）を再検証してからにする。

### 6.4 実装時に踏んだもの（記録）

- **ヨーレートの更新をゲートより後ろに置いていた。** ゲートが 1 サンプル前（20ms 前）の
  値で判定し、**旋回の入り口で観測が 1 回漏れた**（F2 が捕まえた）。伝播の直後・
  ゲートの直前へ移した
- **`f_w` が下向きのときのガードが無かった。** H は `f_w ≒ (0,0,+g)` のまわりで
  線形化してあるので、下向きだと符号が逆になり補正が誤差を広げる。`fw[2] < 0.5g` で弾く
- **`bg_` が学習クランプを超える。** `level_update` が相関経由で `bg_` を微調整するため
  （実測 +0.003 deg/s）。クランプは「学習器が書く値」に対するものなので正常。
  D3 の判定を実態に合わせた
