## 1. センサー特性と移行概要

BNO085（I2C）から SCH16T-K01（SPI）への移行により、センサーの出力特性とソフトウェアの役割が根本的に変わります。

| 項目 | BNO085（v7 以前） | SCH16T-K01（v7.1） | 改善度 |
|---|---|---|---|
| 出力データ | 加速度・角速度・融合クォータニオン・地磁気 | 高精度生加速度・生角速度（20bit）のみ | — |
| 姿勢計算 | センサー内蔵（GRV / RV） | **機上マイコン（RP2350）の ESKF で全計算** | 協調旋回バンク誤差解消 |
| 方位基準 | 地磁気（機体環境で最大 50° 超の誤差） | **GNSS 航跡（真方位）** による発進時注入 | 磁気偏角補正も不要 |
| スケール誤差 \|a\|/g | 0.985〜0.992（約 −1%） | **0.9992（−0.08%）** | **約 12 倍高精度** |
| 加速度ノイズ密度 | 0.00057 g/√Hz | **0.00012 g/√Hz** | **約 4.7 倍低ノイズ** |
| 通信インターフェース | I2C（フリーズ対策が必要だった） | **ハードウェア SPI1（48bit SafeSPI, CRC8）** | 213万フレームエラーゼロ |

## 2. ソフトウェア・アーキテクチャ（抽象化設計）

センサー固有処理と航法アルゴリズムを明確に分離しています。

```
[ SCH16T ドライバ (imu_sch16t.cpp) ]  ──▶ SPI1 (48bit SafeSPI, 250Hz)
        │ 生ジャイロ / 生加速度 (imu_feed_gyro / imu_feed_accel)
        ▼
[ 共通 IMU 抽象化層 (imu.cpp / imu_sensor.h) ]
        ├─▶ 姿勢推定 ESKF (attitude.cpp: 250Hz 伝播, 2Hz GNSS 観測, 2Hz 重力観測)
        ├─▶ バリオメーター KF (imu.cpp: MS5611 気圧 + SCH16T 垂直加速度融合)
        └─▶ 生 IMU ログバッファ (imulog.cpp: 62.5Hz デシメーション記録)
```

### 主要インターフェース (`imu_sensor.h`)
- **能力ビット (`imu_caps()`)**: チップが持つ機能をビット表現。SCH16T では融合出力・地磁気ビットを落とし、画面やログが未サポート機能を安全にバイパス・縮退表示。
- **データ供給 (`imu_feed_gyro()` / `imu_feed_accel()`)**: ドライバが定期取得した角速度 [rad/s]・加速度 [m/s²] を渡す。
- **状態管理 (`imu_drv_*`)**: `setup`, `poll`, `service_if_due`, `present`, `alive` の 5 つの関数でドライバを制御。

## 3. ハードウェア結線とピンアサイン (v7.1)

SCH16T はメイン基板へ直実装せず、IMU フレキ基板（`kicad/IMU_murata/`）をコネクタ J6（Molex 200528-0080）経由で外付け接続します。

| GPIO | ネット名 | SCH16T 信号 | 役割・注意点 |
|---|---|---|---|
| **GPIO41** | `SPI1_CS` | CSB | チップセレクト（通常 High、アクセス時 Low） |
| **GPIO42** | `SPI1_SCK` | SCL | ハードウェア SPI1 クロック（`SPI1.setSCK(42)` を明示） |
| **GPIO43** | `SPI1_TX_MOSI` | MOSI | コマンド送信 |
| **GPIO44** | `SPI1_RX_MISO` | MISO | レスポンス受信 |
| **GPIO45** | `SCH16T_RESET` | EXTRESN | ハードウェアリセット（負論理。通常 High） |
| **GPIO46** | `SCH16T_SYNC` | DRY_SYNC | データ準備完了入力（DRY）。**絶対に出力設定にしないこと** |

> [!IMPORTANT]
> フレキの先端金端子（J3）と本体コネクタ（J6）は**ピン番号が逆順（J6-n ↔ J3-(9-n)）**になります。テスターで J6-8 と J3-1 (+3V3)、J6-1 と J3-8 (GND) の導通を必ず確認してください。

## 4. SCH16T SPI 通信仕様とパラメータ選定根拠

### 4.1 通信仕様
- **モード**: SPI Mode 0 (CPOL=0, CPHA=0)。クロックは 1〜8MHz（本体運用 5MHz）。
- **フレーム構成**: 48bit 固定長（SafeSPI）。
  `TA[47:38] | RW[37] | FT[35] | DATA[27:8] (20bit) | CRC8[7:0]`
- **CRC8**: 多項式 `0x2F`、初期値 `0xFF`、XOR out `0x00`。bit 47〜8 が計算対象。
- **SafeSPI アウトオブフレーム応答**: 送信したコマンドの応答データは**次のフレームで 1 回遅れて返る**。読み出しの先頭には捨てフレーム（ダミー送信）が必要。
- **品種識別**: `COMP_ID = 0x0023`（ASIC_ID はシリコンリビジョンのため品種判定に使えない）。

### 4.2 フィルター・レート選定の物理的根拠
単独テスト実測により、**LPF2（13Hz）＋ デシメーション DEC5（737.5Hz）＋ ポーリング 250Hz** を確定採用しました。

| カットオフ | sd X/Y/Z [°/s] | ノイズ密度 [°/s/√Hz] | 最小推奨読み出しレート | 特性 |
|---|---|---|---|---|
| 68Hz (LPF0) | 0.045 / 0.087 / 0.022 | 0.0055〜0.0106 | 500Hz | 環境振動ノイズが支配的、軸間不均一 |
| 30Hz (LPF1) | 0.012 / 0.013 / 0.012 | 0.0021〜0.0024 | 200Hz | 白色ノイズ床に到達 |
| **13Hz (LPF2)** | **0.008 / 0.007 / 0.008** | **0.0021〜0.0023** | **150Hz** | **sd がさらに 31% 最小化、実機描画停止に余裕** |

- **選定根拠**:
  地図描画はタイル 1 枚で 40〜100ms Core0 を占有します。LPF1（200Hz 最小レート）では描画停止時の余裕がゼロになりますが、LPF2（150Hz 最小レート）であれば平均 200Hz 以上を維持でき、折り返し歪み（エイリアシング）を完全に回避できます。
- **群遅延**:
  13Hz の群遅延（約 12ms）は、GNSS NAV-PVT の遅延（50〜100ms）に対して小さく、むしろジャイロを遅らせることで GNSS との相対遅延が縮まるため航法上きわめて好都合です。

### 4.3 破ると静かに壊れる実装上の注意点
1. **`CTRL_USER_IF` と `CTRL_ST` は read-modify-write 必須**: リセット値に 1 のビットが存在するため、素の代入を行うとサポート外のモードに落ちる。
2. **`EOI`（End of Initialization）後の設定ロック**: `EOI` 書き込み後はソフトリセット以外のレジスタ書き換えが拒否される（実行中の動的変更不可）。
3. **`DYN_*` に `'000'` を書かないこと**: Undefined となりチップが未定義動作に陥る。

## 5. 姿勢推定 ESKF・バリオ KF への統合

### 5.1 姿勢 ESKF の初期化と維持
- **初期水平化**: 静止 2 秒間の平均比力から初期ロール・ピッチを決定。
- **初期ヨー注入**: 発進滑走時（対地速度 > 3.0m/s）の最初の GNSS 航跡（True Track）から真方位を直接注入。
- **重力観測（レベリングアップデート）**:
  準定常状態において、比力の水平成分が 0 であるべき観測として 2Hz で ESKF に更新を投入。
  - **旋回レートを主ゲートとする根拠**: 人力機の 5° バンク旋回時、比力ノルムの変化はわずか $0.0375\text{ m/s}^2$ で加速度計スケール誤差に埋もれますが、旋回レートなら $6.14^\circ/\text{s}$ ありジャイロゼロ点に対して 20〜60 倍の十分な S/N 比を確保できます。
  - **効果**: GNSS 途絶時でもロール・ピッチの長期ドリフトを防止（実機走行試験で誤差中央値 21.3° → 1.3° に抑制確認）。
- **オンライン・ジャイロバイアス学習（ZRO）**:
  静止中に 250Hz で角速度ゼロ点を継続学習。
  - **Flash/EEPROM に保存しない理由**: SCH16T のオフセットドリフト速度は $\pm 0.01(^\circ/\text{s})/\text{min}$（昇温時）あり、前回フライトの定数は次回合わない。一方バイアス不安定性は $0.3\sim 0.5^\circ/\text{h}$ と極めて小さいため、フライト開始時に都度ゼロ点を測るのが物理的に最も正確。

### 5.2 バリオメーター KF と制御理論上の教訓
- 気圧センサー（MS5611）の高度観測と、SCH16T の垂直軸加速度（ESKF 姿勢により地球座標系 Z 軸へ変換）をカルマンフィルターで融合。デッドバンドは SCH16T 稼働時 **±0.25m/s**。
- **重要な教訓（predict 停止による状態切り離しバグの防止）**:
  カルマンフィルターの共分散行列 $P$ の非対角成分（高度と垂直速度の相関）は predict ステップでしか生成されません。水平化完了前であっても predict を止めてはならず、止めると気圧観測ゲイン $K[1] = P[1][0]/S$ が 0 に張り付いて速度状態が永久に動かなくなります（`up_lp_` により常時 predict を通す構造で対策済み）。

### 5.3 生ログ（imulog）の間引き
250Hz の全サンプル記録は SD カードの帯域を圧迫するため、`SCH16T_IMULOG_DECIM = 4` により **62.5Hz** に間引いてバイナリログ（`imuraw/`）へ記録します。
