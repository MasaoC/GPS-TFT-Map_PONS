## 1. チップの仕様と決めごと

データシートは Doc.No.11624 Rev.6（フル版・65 ページ、社外秘）。下の値は全件照合済み。

| 項目 | 値 |
|---|---|
| SPI | mode 0、48bit フレーム、SCK **0.095〜10.5MHz**（下限もある）。本体は SPI1・5MHz |
| フレーム | `TA[47:38]`（上位 2bit = CS、下位 8bit = レジスタ）`\| RW[37] \| FT[35] \| DATA[27:8] \| CRC8[7:0]`。`FT` は次の MISO フレーム幅（1 = 48bit） |
| CRC8 | 多項式 0x2F・初期値 0xFF・XOR out なし・bit 47〜8 が対象 |
| **応答** | **1 フレーム遅れて返る**。先頭に捨てフレームが要る |
| ステータス | 応答の `[36]IDS [35]CE [34:33]S1:S0`（00 正常 / 01 エラー / 10 飽和 / 11 初期化中） |
| 感度（20bit） | ジャイロ 1600 LSB/(°/s)（DYN `'010'`）、加速度 3200 LSB/(m/s²)、ACC3 1600、温度 100 LSB/°C（20bit の上位に詰まっているので `>>4`） |
| レンジ | ±327.68 °/s、±163.84 m/s²。**DYN に `'000'` を書かない**（CTRL_RATE / CTRL_ACC12 では未定義） |
| ODR | 間引きなし 11.8kHz / 5.9k / 2.95k / 1.475k / **737.5Hz**（実測 721.5Hz、−2.1%） |
| フィルター | LPF0 68Hz（既定）/ LPF1 30 / **LPF2 13** / LPF3 280 / LPF4 370 / LPF5 235 / LPF7 バイパス |
| 初期化 | リセット → NVM **32ms** → 設定 → `EN_SENSOR` → **215ms** → ステータス 1 周 → `EOI` → **3ms** → ステータス 2 周 → 確認 |
| 品種 | **`COMP_ID` = 0x0023 が K01。** `ASIC_ID` はシリコンの版で品種判定に使えない。他品種はジャイロの感度だけが 16 倍違う |
| 出力 | `*_1` 補間 / **`*_2` 間引き（使っている）** / `*_3` 広レンジの補助加速度。間引き出力は FIFO ではなく、読まなければ上書きされる |

### 1.1 設定: LPF2（13Hz）＋ 間引き 737.5Hz、読み出し 250Hz（最低 150Hz）

LPF ごとに「最小推奨読み出しレート」がある（データシート §5.5 Table 16）。下回ると阻止域のノイズが折り返して帯域に入る。

| LPF | カットオフ | 最小読み出し |
|---|---|---|
| LPF2 | 13Hz | **150Hz** |
| LPF1 | 30Hz | 200Hz |
| LPF0 | 68Hz | 500Hz |

単独テストで 3 点を各 60 秒測ったジャイロのノイズ:

| | 68Hz | 30Hz | 13Hz |
|---|---|---|---|
| sd X / Y / Z [°/s] | 0.0455 / 0.0870 / 0.0225 | 0.0116 / 0.0132 / 0.0122 | 0.0080 / 0.0075 / 0.0082 |
| 密度 [°/s/√Hz] | 0.0055 / 0.0106 / 0.0027 | 0.0021 / 0.0024 / 0.0022 | 0.0022 / 0.0021 / 0.0023 |

- 68Hz の超過分は環境の振動（30Hz へ落とすと白色の予測より 4〜7 倍落ち、軸のばらつきも消えた）。13Hz と 30Hz は密度が一致し、
  ここがセンサーの床（約 0.0022 °/s/√Hz）。
- **LPF2 にした決め手は最小読み出しが 150Hz で済むこと。** 地図の描き直しで Core0 が止まっても余裕がある（LPF1 の 200Hz では無い）。
- 群遅延の差（13Hz と 30Hz で 7〜21ms）は効かない。GNSS の NAV-PVT はそれより大きく遅れて届き、ジャイロが遅れるほど相対遅延は縮む。
- **`EOI` を書くとソフトリセットと `SYS_TEST` 以外のレジスタがロックされる**（Table 80）。実行中に LPF やレンジは変えられないので、
  IMU まわりに実行時の設定項目は作らない（`settings.txt` に `imu_sensor` キーを置かないのも同じ理由。基板が決まればセンサーも決まる）。

### 1.2 単独テストでの実測（2026-10-14、Pico 2 ＋ ブレイクアウト）

チップとフレーム層の話なので、ここで裏付いたものは本体で測り直さなくてよい。

| 項目 | 実測 | 備考 |
|---|---|---|
| `SYS_TEST` 疎通 | 5 パターン全一致 | フレーム層・CS・CRC・配線とも正常 |
| 応答の遅れ | ちょうど 1 フレーム | |
| `COMP_ID` / `ASIC_ID` | 0x0023 / 0x21 | K01。PX4 の K01 REV_1 と一致 |
| `CTRL_USER_IF` のリセット値 | 0x200C | データシートどおり（§4 の罠） |
| ジャイロ感度（実回転 360°） | 1599.3 LSB/(°/s) | 0.04% |
| `\|a\|/g` | 0.99916〜0.99926（−0.08%） | BNO085（−1%）の約 12 倍良い。**乗り換えの一番の根拠** |
| 加速度ノイズ密度 | 0.00012 g/√Hz | BNO085 の 1/4.7 |

| ジャイロノイズ密度 | 0.0022 °/s/√Hz | typ の 5.5 倍だが用途に十分（環境の振動か 3V3 の雑音の可能性。追っていない） |
| 実 ODR | 721.5Hz（設定 737.5Hz） | 2 回で 721.0 / 722.0 |
| 通信品質 | 不良 0 / 約 213 万フレーム @1MHz | |

## 2. ファームの作り

| ファイル | 中身 |
|---|---|
| [imu_sch16t.cpp](../imu_sch16t.cpp) | **チップ依存はここだけ。** SPI1 の 48bit フレーム・初期化・タイマー割り込みでの読み出しとリングバッファ・復旧 |
| [imu_sensor.h](../imu_sensor.h) | チップと推定の境界。feed の口（`imu_feed_gyro` / `imu_feed_accel`）と `imu_drv_*`（setup / poll / service_if_due / present / alive） |
| [imu.cpp](../imu.cpp) | バリオの KF と推定側のゲッター（チップ非依存） |
| [attitude.cpp](../attitude.cpp) | 姿勢 ESKF（`tools/imulog/eskf.py` と二重実装） |

- **feed の順番**: 同じ時刻に読んだ組は `imu_feed_accel()` を先に呼ぶ（ESKF はジャイロの到着で伝播し、手元の加速度を使う）。
- **読み出しはタイマー割り込み**（`SCH16T_READ_IN_IRQ`）。Core0 のアラームが 4ms ごとに読んでリング（512ms 分）へ積み、`loop()` が古い順に推定へ渡す。
  割り込みの優先度は最低のまま（音声の 16kHz の割り込みを待たせると 250Hz のうなりになる）。スレッド側で SPI1 を使うのは `sch_init()`（起動と復旧）
  だけで、`try_recovery()` が割り込みを止めてから呼ぶ。
  - 60 秒ログ: `gapmax=` 読み出しの間隔（ふだん 4ms）、`drain=` Core0 が受け取りに来られなかった最長、`ovf=` リングが一杯で読めなかった回数。
  - 長い処理（地図のレコードごと・航跡の点ごと・面の塗りの 16 行ごと・E220 の AUX 待ちなど）の中でも `imu_service_if_due()` を呼ぶ。
    1 秒受け取らないと「途絶」と判定して生きているチップをリセットしに行く（v7 で起きた）。`imu_drv_poll()` の冒頭に、呼び出し間隔が空いた回の判定を見送るガードもある。
  - ポーリング（`SCH16T_READ_IN_IRQ` 0）では描き直しの間（70〜90ms）のサンプルが抜ける（11/11 の生ログで時間の 16〜19%）。
  - `IMU_POLL_INTERVAL_US` は SCH16T では 4ms 固定。33Hz などへ下げると LPF2 の 150Hz を割って折り返す。
- **CPU の負担**: 1 サンプル 7 フレームで約 246µs（5MHz）、250Hz で Core0 の約 6%。SPI のクロックを上げても大差ない（フレームあたりの固定の手間が支配的）。
  効くのはフレーム数で、温度は毎回読まない（`SCH16T_TEMP_EVERY`）。
- **見つからない・黙った**: CRC の合うフレームが 50ms 来なければ居ないと見切る（`SCH16T_READY_NOFRAME_MS`）。v7.1 は SCH16T を必ずつなぐ前提で、
  見つからないのも途中で黙ったのも IMU の欠け（本番前チェックの `IMU`）。
- **ESKF**（[attitude.cpp](../attitude.cpp)。式と定数は settings.h の `ESKF_*`）
  - 初期のロール・ピッチは静止 2 秒の平均加速度から、ヨーは GNSS の航跡から（3m/s 以上を連続で。接地中なので横滑りが無い）。地磁気は使わない
    （BNO085 の地磁気ヨーは航跡から 57.8 度ずれていた）。
  - 待機中は静止の再水平化（時定数 1 秒）とジャイロバイアスの学習（5 秒ごと、上限 0.5°/s）。**バイアスはフラッシュに保存しない**
    （温度で動くが、1 回の飛行の中では一度測れば足りる。bias instability 0.3〜0.5 deg/h）。
  - dt は直前のサンプルとの実際の時間差（1 回読むと 1 サンプルで、まとめて届かない）。ゲインは `IMU_RATE_GYRO_HZ` = 250 で換算。
  - **重力観測（levelling update）**: 準定常のとき、ワールドへ回した比力の水平 2 成分を 0 の観測として 2Hz で入れる。GNSS が無い間の傾きの錨。
    **ゲートが本体**で、主は旋回レート（協調旋回でバンクを過小評価しないため）。`|f| ≒ g` は粗い確認だけ（5 度バンクの差は加速度の誤差に埋もれる）。
    2026-10-03 の走行 2 時間で、GNSS 断の傾きの誤差が中央 21.3° → 1.3°、協調旋回 20° の推定は変わらず。60 秒ログの `gobs=` が 0 のままならゲートが閉じている。
- **バリオ**: 上向きは ESKF の姿勢から（`attitude_get_up_sensor()`）。**上向きが無くても predict は止めない**
  （止めると KF の共分散の非対角が育たず、気圧の観測から V/S が一度も動かない。2026-10-01 に実機で踏んだ）。
- **生ログ**: `SCH16T_IMULOG_DECIM` = 1（250Hz。PC の ESKF を厳密に再現するため）、二重バッファ 584 レコード。60 秒ログの `raw ... drop=` が増えたら 2 に。
  レコードの `s_us` は読み出した時刻（v7 のログと違い、そのまま使える）。
- **マウント回転**（`IMU_MOUNT_Q*`）は v7.1 で測って v7 と同じ向き（§7）。変えたら `tools/imulog/decode_imulog.py` の `MOUNT_Q` も同じ値にする。

## 3. 配線（v7.1 / v7.2 本体）

ブレイクアウト（`kicad/IMU_murata`）はフレキ基板で、尾の先の金端子 J3 を本体の J6（Molex 200528-0080、8pin）へ直接挿す。

| | |
|---|---|
| ピン順 | ブレイクアウト J3: `1=+3V3 2=RESET 3=MOSI 4=CS 5=SCK 6=SYNC 7=MISO 8=GND`。本体 J6 は**逆順**（`1=GND … 8=+3V3`）で、挿すと **J6-n ↔ J3-(9-n)** が接する |
| 通電前 | 挿した状態で J6-8 と J3-1（+3V3）、J6-1 と J3-8（GND）の導通を確かめる。逆だと電源が逆に入る |
| 本体 GPIO | `CS=41 / SCK=42 / MOSI=43 / MISO=44 / EXTRESN=45 / DRY=46`（SPI1 の正規割り当て。`SPI1.setSCK(42)` を明示する。正本は settings.h の `SCH16T_PIN_*`） |
| ブレイクアウトの部品 | **R2（CS–GND 4.7k）は実装しない**（CS は負論理で、プルダウンすると駆動していない間セレクトになる）。R1（EXTRESN のプルアップ）は実装する。TA9 / TA8 は GND |

**GPIO42 / 44 を `INPUT_PULLUP` で停めないこと**（v7 の I2C の処置。v7.1 では SPI1 が死ぬ）。

## 4. 踏みそうな罠

- **★ リセット直後は「CRC は正しいがデータが 0」のフレームが返る。** 固定の待ちだけで進むと設定の書き込みが黙って捨てられる。
  `ASIC_ID` が 0x0000 / 0xFFFF 以外になるまで待つ（NVM を読み終えた証拠）。CRC では検出できない。実測はコールドで 1ms、再初期化で 0ms。
- **`CTRL_USER_IF` と `CTRL_ST` は read-modify-write。** リセット値が 0 でないビットがある（`CTRL_USER_IF` は 0x200C）。素で書くと
  `MISO_SR_CTRL` / `DRY_SR_CTRL` を 0 に落とし、データシートが "not supported by Murata" と書いている側になる。**PX4 のドライバはこれを踏んでいる。**
- **読み出しは 1 フレーム遅れる。** 捨てフレームを落とすと全軸が 1 つ前のレジスタの値になる（静かに壊れる）。
- **`EOI` 後は設定を変えられない**（§1.1）。変えるならリセットから。
- **`DRY_SYNC` を出力にしない**（SYNC 入力と兼用）。
- **ID・シリアルの読みは CRC と CE だけで判定する。** `S1:S0` は EOI の前は 11（初期化中）なので、そこで弾くと起動直後の ID 読みが毎回失敗する。
  `COMP_ID` の確認は EOI の後。
- **ODR は DRY の回数ではなく最短周期で見る。** DRY は「更新 → 最初の読み出し」の間だけ High なので、回数は必ず少なく出る（期待の 77% に見えた）。
  読み出しが ODR より遅いと、DRY の回数は読み出しの回数になる。
- **`RATE_DCNT`（0x11）/ `ACC_DCNT`（0x12）は「測定しているか」の判断に使えない**（初期化が成功していても 0 のままだった）。データレジスタを見る。
- **ジャイロの感度は 1g の検証では確かめられない。** 加速度の感度は品種共通なので、`|a|/g` が 1.000 でもジャイロが 16 倍ずれている可能性は消えない。
  実回転の積分（単独テストの `G`）だけが手段。
- **ODR より遅く読んでも壊れない。** 間引き出力は上書きされるだけで、読めるのは最新の正しい値 1 つ（単独テストの `c` は 5Hz で読んでも不良 0）。
  障害は「サンプルが減る」だけで、BNO085 のように溜まったレポートが化けることは構造的に無い。

## 5. 単独テスト（[tools/sch16t_test/](../tools/sch16t_test/)、Pico 2 単体）

本体から独立した立ち上げ用のスケッチ。**本体でうまくいかないときは、本体を疑う前にここへ戻る**（`z` → `t` → `i` → `r` で、
チップ・配線・フレーム層のどこが悪いかが分かる）。

**配線**（Pico 2）: MISO=GP16 / CS=GP17 / SCK=GP18 / MOSI=GP19 / EXTRESN=GP20 / DRY_SYNC=GP21（入力）/ 3V3(OUT) を V3P3 と VDDIO へ / GND。
配線は短く（長いジャンパだと 10MHz で落ちる。スケッチは 1MHz で始まる）。

**ビルド**: `arduino-cli compile -b rp2040:rp2040:rpipico2 --build-path /tmp/sch16tbuild tools/sch16t_test`（書き込みは IDE、ボード Raspberry Pi Pico 2）。
シリアル 115200 で 1 文字コマンド。

| | |
|---|---|
| `h` | ヘルプと現在の設定 |
| `z` | 1 フレームだけ生で投げる。全部 0x0000 = MISO が来ない、全部 0xFFFF = CS が効いていない、`crc OK` = フレーム層は成立 |
| `t` | `SYS_TEST` に書いて読み返す（データシートの疎通確認。全一致ならフレーム層・CS・CRC が成立） |
| `i` | ID と設定レジスタ。`COMP_ID` = 0x0023 で K01 |
| `a` | TA を走査（応答しないとき） |
| `r` / `R` | 初期化（ソフト / ハードリセット）。目標は `[init] SUCCESS` と `STAT_SUM = 0xFFFF` |
| `s` | ステータス全部とフレームの統計 |
| `m` / `M` | 静止測定 10 秒 / 60 秒（バイアス・ノイズ・`|a|/g`・温度。冒頭に条件が全部出るので、ログを残せば再現できる） |
| `G` | ジャイロ感度の実測（静止 1 秒 → ゆっくり 90° か 360° 回して止める。回した軸の列が 1600 付近なら正しい。±300°/s に近ければ速すぎ） |
| `d` | DRY で実 ODR を測る（初期化後だけ） |
| `c` / `v` | 連続表示 / CSV（`t_us,gx_dps,gy_dps,gz_dps,ax_mps2,ay_mps2,az_mps2,temp_c,ok`） |
| `p` | 補間と間引きの生値の比較 |
| `k` / `f` / `e` | SPI クロック 1→2→5→10MHz / フィルター 68→30→13Hz / 間引き 738→…→なし |

- 起動時に、SPI を叩く前にフレーム組み立ての自己テスト（Murata の事前計算値 10 件）が走る。NG ならスケッチを直す（配線を見ても無駄）。
- ノイズ密度は `sd / √fc`（`fc` は LPF の公称カットオフ）の概算。`fs/2` を帯域に使わない。読み出しが LPF の最小推奨を下回るとスケッチが警告する。
- フレーム組み立ては、データシート Table 27 の実フレーム 41 件・smplboards-SCH16T の 47 件と全一致（ホストでコンパイルして照合）。
- PX4 との違い（こちらが正しいと判断）: `CTRL_USER_IF` は read-modify-write（§4）、RATE の DYN は `'010'`（書いた値と感度が 1 対 1 になる。PX4 の `'001'`
  でも動く）、48bit は `SPI.transfer(tx, rx, 6)` を 1 回（`transfer16()` を 3 回だとワード間で SCK が止まる）。

## 6. 本体での確認の手順

| Step | 中身 | 状態 |
|---|---|---|
| 1 配線 | §3 | 済み |
| 2 焼く | 起動ログ（下の表）と起動画面のセンサー行 | 済み（2026-11-03） |
| 3 机の上 | 姿勢が 0 付近で `ready=1`、V/S が 0 付近、`raw GYR/ACC` が 250Hz、`gapmax` 4ms。マウント 3 点（水平・機首を真下・右翼を真下で IMU/ESKF 画面の `Accel raw`）、90 度回して ESKF も 90 度、静止の再水平化が 1 秒前後 | 済み（2026-11-13） |

起動ログ（`imu_sch16t.cpp`）:

| 行 | 意味 |
|---|---|
| `[IMU] SCH16T-K01 ready. chip responded in N ms` | 成功 |
| `[IMU] SCH16T: ASIC_ID unreadable (check J6 wiring / SPI1 pins)` | 配線か SPI1 のピン（50ms で見切る） |
| `[IMU] SCH16T COMP_ID 0x.... != K01 0x0023` | 別品種。使わない |
| `[IMU] SCH16T verify NG crc=.. dyn=.. filt=.. STAT_SUM=0x....` | 設定が入っていない（`crc=0` は確認の読み出しが化けた） |
| `[IMU] SCH16T init retry` | 1 回目が失敗。毎回出るなら電源の立ち上がりを疑う |
| `[IMU] SCH16T pins are UNSET — check settings.h` | `SCH16T_PIN_*` が UNSET |

## 8. 残っていること

- 健全性（CRC エラー・`STAT_*`・飽和）を 60 秒ログと画面へ出す（CRC エラーは数えているが出していない）。
- セルフテスト（`CTRL_ST`。read-modify-write が要る）と、飽和フラグのフィルター設定（`CTRL_*_FLAG_*`）は触っていない。
- ダイ温度は読んでいるが使っていない（`s_temp_c`）。ログへ出せば、昇温中にバイアスが動くかが見える。
