# PONS Link 立ち上げ試験手順（v7 基板到着後）

無線まわりは**まだ一度も実機で動かしていない**。ソフトはコンパイルが通っているだけで、
配線・レジスタ書込み・送受のどれも未検証。ここを飛ばして飛行試験へ進まないこと。

**無線以外にも未検証のものがある。**実機で最後に通したのは 0.944 で、そのあと
BNO085 の SPI 化・MS5611 の i2c0 分離・GNSS 設定の ACK 確認・SD のフォルダ構成変更が
入っている。フェーズ A にまとめたので、**無線より先にそこを通す**こと
（起動していないのか電波が飛んでいないのか、後から切り分けるのは高くつく）。

**原則：一度に 2 つ変えない。** 症状が出たときに、どちらが原因か分からなくなる。
`EasyE220-900T22/E220_PITFALLS.md` §4 に、前回それで詰まった実例がある。

必要なもの：PONS v7 を 2 台以上、テスター、USB シリアル（`Serial` のログを見る）、
巻尺かスマホの GPS（距離の確認用）。

---

## フェーズ A：無線以外で、実機初投入になるもの（30 分）

**ハードウェアで最後に確認したのは 0.944。**それ以降に無線以外でも大きく変わっており、
どれも v7 基板では一度も動かしていない。無線の前に、ここが通ることを先に確かめる。
無線が動かないときの切り分けが楽になる（「そもそも起動していない」を除外できる）。

確認はほぼ SD の `/log.txt` で足りる。**起動直後の 20 行ほどを読むだけ**で、
センサー 3 つと GNSS 設定の成否がすべて分かるようになっている。

### A-1 BNO085 が SPI で動くか（★ 0.950 で I2C から変更。一度も通電していない）

| # | 確認 | 合格 |
|---|---|---|
| A-1-1 | **JP1 が既定（1-2 = +3V3）** か。＝ PS1=1（SPI） | `settings.h` の `IMU_BUS_SPI` 有効と**一致**していること |
| A-1-2 | `log.txt` に `BNO085 init OK` | 失敗時は `BNO085 begin FAILED (SPI1) stage=…` が出る。**`stage` で切り分ける**（下記） |
| A-1-3 | `VARIO: BNO085+MS5611 Kalman fusion enabled` | 片方だけなら該当センサーが見えていない |
| A-1-4 | 60 秒ごとの `rate GRV=15.0 LACC=15.0 RV=5.0 MS5611=…` | 設定値より低ければ配信飢餓。バリオが暴れる原因になる |
| A-1-5 | `BNO085 enableReport aborted at … (slow bus)` が**出ない**こと | 出たら SPI の信号品質を疑う（配線長・GND） |
| A-1-6 | IMU 詳細画面でロール・ピッチが手の動きに追従するか | 符号と軸の向きも一緒に確認する |

**`begin FAILED` が出たときの読み方**

`stage=1(no-INT)` … H_INTN が一度もアサートされなかった。**SPI のデータ線はまだ無関係。**
BNO085 がそもそもブートしていないか、SPI モードで起動していない。疑う順は
**JP1(PS1) の位置 → 3V3 → NRST(GPIO46) → 半田**。
PS1=0 のまま PS0=1 だと **UART モード**で起動し、H_INTN は永久に来ない。

`stage=2(no-SHTP)` … INT は来たので**チップは生きていて SPI モードにいる**。
`sh2_open()` / `getProdIds()` が通らないので、**MISO/MOSI/SCK/CS の配線か接触**を疑う。
GPIO41=CS / 42=SCK / 43=MOSI / 44=MISO。MISO と MOSI の入れ違いが定番。

同じ行に `INT= RST= PS0=` の実測値も出る。正常なら RST=1、PS0 は 0（WAKE 保持）。

> **既知：基板に H_CSN(GPIO41) のプルアップが無い。**そのためソフトが
> NRST を打つ前に CS を HIGH で駆動している（`imu_bus_select_protocol()`）。
> これを外すと、リセット〜ブートの 400ms の間 CS が浮いて **BNO085 が起動しない**
> （v7 の初回通電で実際に踏んだ症状が `stage=1(no-INT)`）。
> **次の基板改訂で 10k プルアップを入れること。**

**わざと外して確かめる（ここが今回いちばん危ない変更）**

- **BNO085 を外して電源を入れる。** 画面が真っ暗のまま固まらず、**1.7 秒ほどで
  起動が進む**こと。固まるならライブラリの無限ループに落ちている
  （ライブラリの `sh2_*` は全オペレーションがタイムアウト無限なので、
  ソフト側の INT 生存確認だけが頼り）。
- 飛行中を模して、動作中に BNO085 の電源を抜く。`[IMU] BNO085 comm timeout` →
  1 分後に `[IMU] BNO085 recovery FAILED (no INT)` が出て、**地図が止まらない**こと。
- 戻すと `[IMU] BNO085 recovery OK` で復帰するか。
- **デバッグビルド（`RELEASE` を外す）でも起動が最後まで通るか。**
  そちらだけ `sh2_getMetadata()` を呼ぶので、通れば SPI が安定している証拠になる
  （`ACCEL meta range=… res=…` が出る）。ここで固まるなら信号品質が足りていない。

### A-2 MS5611（i2c0 単独・400kHz。v7 で BNO085 と分離）

| # | 確認 | 合格 |
|---|---|---|
| A-2-1 | `MS5611 init OK` | `MS5611 not found` なら i2c0(GPIO32/33) の配線 |
| A-2-2 | `MS5611 PROM CRC NG (calc n want m)` が**出ない**こと | 出たら係数が化けている。プルアップとバス長を疑う |
| A-2-3 | `Initial airdata: Temp=… Press=… Alt=…` が妥当な値か | 気温が室温、気圧が 1000hPa 前後 |
| A-2-4 | 机から持ち上げてバリオが鳴るか | 上昇=断続ビープ / 下降=連続低音 |

**わざと外して確かめる（気圧センサー 1 個の不調が音響警報を全停止させていた経路）**

- 動作中に MS5611 の SDA を外す。数秒で `MS5611 lost (I2C). airdata disabled, will retry`
  が出て、**その後もバンク角警告やコース警報が鳴り続ける**こと。
  鳴らなくなったらタスクキューが溢れている（この修正が効いていない）。
- 戻すと 30 秒以内に `MS5611 recovered` が出て、バリオが復活するか。

### A-3 GNSS の設定が通っているか（0.964 で追加。**起動直後の 1 行を見るだけ**）

| ログ | 意味 |
|---|---|
| `GNSS CFG OK 2Hz/PVT/SAT/DOP/Air1g (prt=ack)` | 5 つとも通った。正常 |
| `GNSS CFG NO ACK: RATE2HZ …` | 測位レートが 1Hz のまま。ログ密度も旋回角速度も半分になる |
| `GNSS CFG NO ACK: … AIRBORNE1G` | **動的モデルが地上のまま飛ぶ。**症状は「方位の追従が鈍い」だけで画面に出ない |

`prt=none` は正常なこともある（CFG-PRT の ACK は旧ボーレートで返るため）。

### A-4 SD のレイアウト変更（0.961 で `data/` `received/` へ整理）

- 飛行 CSV が **`data/YYYY-MM-DD_HHMM.csv`** にできるか（ルート直下ではない）
- リプレイ選択画面の `SOURCE` を切り替えて、`data/` と `received/` の両方が見えるか
- **WAV を 1 つリネームして起動する。** 500Hz×2 のエラー音が鳴り、
  `ERR wav missing: wav/….wav` がログに出て、**フッタの SD 表示が赤にならない**こと
  （赤くなるのは `ERR wav open: … (SD err 0xNN)` のとき＝本当にカードが怪しいとき）
- **デバッグビルドで `!!! SD access from Core0` がシリアルに出ない**こと
  （出たら Core1 専用の約束が破れている。SDIO バスハングの原因になる）

### A-5 画面が収まっているか（★ 実機でしか分からない。項目が増えている）

| # | 確認 |
|---|---|
| A-5-1 | **設定画面の `Save & Exit` が切れていないか。** 15 項目 × 16px = 240px でちょうど。長らく保留になっていた確認 |
| A-5-2 | WIRELESS 画面の `Return` が見えるか（`Preflight: re-run` を足して 1 行増えた） |
| A-5-3 | WIRELESS 画面の `SF      : 11  (600ms 60%)` と `Noise   : -104 dBm  mgn +15dB` の右端が切れていないか（どちらも今回追加した情報で行が伸びた） |

### A-6 警報まわり（0.963〜0.967 で動きが変わった）

- **地図画面以外でも警報が鳴るか。** 設定画面を出したままにして、コース警報・
  旋回音が鳴ること（0.965 で発報を `loop()` 最上位へ移した）。
- **設定画面を 3 分放置すると地図へ戻る**か。別れの音声が鳴り、
  `SETTING SCREEN TIMEOUT -> MAP (180s idle)` がログに出る。
- **ESKF 較正のやり直し要求。** マウントから外して戻すと
  `ESKF CALIBRATION REQUIRED!` が **3 秒に 1 秒だけ点滅**し、ヘッダの `Pavg` に
  **赤い横バー**が重なるか。地上で静止していれば 120 秒ごとに
  `eskf_calib_required.wav` が鳴り、`ESKF CALIBRATION REQUIRED (on ground)` が残る。
  **持ち歩いている間（静止していない）は鳴らない**こと。
- **音量 0 の確認。** 設定で音量を 0 にしても `battery_low.wav` は鳴る（最低保証音量 60）。
  一方で**無線の警告は鳴らなくなる**こと（0.965 で電池切れ以外から外した）。

## フェーズ 0：通電前（15 分）

モジュールを壊してからでは遅いので、電源を入れる前に済ませる。

| # | 確認 | 合格 |
|---|---|---|
| 0-1 | E220 の VDD と GND がショートしていないか | テスターで数 kΩ 以上 |
| 0-2 | **VCC（7番）が開放**か | 導通なし。VDD と繋いでいたら剥がす |
| 0-3 | M0/M1 が結線されて 1 本になっているか | 導通あり |
| 0-4 | M0/M1 が **GPIO35 か GPIO41 のどちらか**に繋がっているか | `IMU_BUS_SPI` 有効なら 35。0Ω（R50/R52）の実装と一致すること |
| 0-5 | AUX が GPIO30 に来ているか | 導通あり |
| 0-6 | TX/RX が交差しているか（RP の TX=GPIO8 → E220 の RXD） | 入れ替わりは一番よくある間違い |
| 0-7 | アンテナ（IPEX）が挿さっているか | **アンテナ無しで送信しない。** モジュールを壊す |

> 0-4 を間違えると、BNO085 の I2C クロック線を無線のモード切替で叩くことになる。

## フェーズ 1：モジュールが応答するか（1 台・10 分）

無線設定画面（設定 → WIRELESS）を開く。

1. `link_mode` を **OFF のまま**、電源投入。
2. 画面の `Module` を見る。

| 表示 | 意味 | 次にすること |
|---|---|---|
| `Module : OK` | 設定の書込みと読み返しが一致した。**配線は正しい** | フェーズ 2 へ |
| `Module : NO RESPONSE` | 応答なし | 下の切り分けへ |

### NO RESPONSE のときの切り分け

`e220_setup()` は「mode 3 へ入る → 9600 で読む → 書く → 読み返す」の順に動く。
どこで落ちているかは `Serial` のログと、次の順で切り分ける。

1. **AUX の実測。** テスターで GPIO30 を見る。アイドルなら 3.3V。
   0V に張り付いていたら、配線ミスかモジュール不在。
   ソフトは内部プルアップを入れてあるので、**未接続なら 3.3V に見える**はず。
   0V ならモジュールが繋がっていて、かつビジーだということ。
2. **M0/M1 の電圧。** 起動直後は mode 3（HIGH）のはず。
3. **TX/RX の入れ替わり。** 0-6 をもう一度。
4. 起動時の `LINK ERROR: radio module not responding` が SD のシステムログに出ているか。

## フェーズ 2：環境ノイズ（1 台・10 分）

**送信する前に、その場所が静かかを測る。** ここで雑音が高ければ、
あとで距離が出なくても地形のせいなのかノイズのせいなのか切り分けられる。

1. `link_mode` を **RX** にする。
2. 無線設定画面の `Noise` を読む。

| 値 | 判断 |
|---|---|
| −100 〜 −110 dBm | 正常。熱雑音 +数 dB で、実測どおり |
| −90 dBm 前後 | 何かが出ている。Wi-SUN スマートメーターなど。CH を変えて比べる |
| `---` | 取得できていない。**REG3 bit6 が 1（固定送信）になっている疑い**（→ 仕様書 §6） |

3. **CH を 0〜12 まで回して、一番静かな CH を控える。** 本番でその CH を使う。
   1 CH あたり数秒でよい。

> ★ このとき `Rx/Miss` が増えないことも確認する。増えるなら、
> 近くに別の PONS が送信している。

## フェーズ 2.5：送信前チェック（2 台以上・15 分）

**送信モードに入ると、送り始める前に 5 秒間チャンネルを聴く**（仕様書 §5）。
ここが正しく動くかを、電波が届く机の上で確かめる。

> **測り直したいときは WIRELESS 画面の `Preflight: re-run` を長押しする。**
> アンテナの向きや置き場所を変えながら何度も測るための入口で、
> CH を変えて戻す遠回りは不要。TX 以外では低い音（440Hz）で断られる。

1. フェーズ 2 で**一番静かだった CH** を選び、`link_mode` を **TX** にする。
   地図に `CHECKING CHANNEL... 5s` が出て、送信アイコンが**橙の弧 1 本**になるか。
   **赤い×が出たら NG**（点検中を「送れていない」と誤表示している）。
2. 5 秒後に**上昇 2 音**が鳴り、WIRELESS 画面が `Preflt : OK (-104 dBm)` になるか。
   直後から `Sent` が 1 秒ごとに増え始めるか。

| 結果 | 判断 |
|---|---|
| `OK` ＋ 上昇 2 音 | 正常 |
| `NOT MEASURED` ＋ 低い 2 音 | 雑音が取れていない。**REG3 の RSSI バイトを疑う**（→ フェーズ 2 の `---`） |
| `NOISY` | その CH は使わない。フェーズ 2 の測定と合っているか確かめる |

### わざと失敗させて、検出できることを確かめる

**★ ここが本番。**「送信機が 2 台いる」は、通常運転では受信機しか検出できない。
このチェックだけが送信機側でそれを確かめられるので、必ず動作を見ておくこと。

- **同じグループの送信機** … 3 台目を**同じ CH・SF・Group** で TX にしてから、
  本機を TX に切り替える。WIRELESS 画面が `Preflt : DUP SENDER -96dBm` になり
  `link_ch_busy.wav` が鳴るか。地図にも `ANOTHER SENDER` / `ON THIS CHANNEL !!`
  の 2 行が出るか。**確認したら必ず戻す。**
- **別グループの PONS** … 3 台目の Group だけ変えて同じことをする。
  `Preflt : PONS grp3 -96dBm` になるか。上と**別の表示になる**こと（対処が違うため）。
- **雑音の高い CH** … フェーズ 2 で −90dBm 前後だった CH を選んで TX にする。
  `NOISY` と `link_ch_noisy.wav` が出るか。

### 受信機側でも「送信機 2 台」を検出できることを確かめる

上は**送信機側**（飛ぶ前の点検）での検出。飛行中に検出できるのは**受信機だけ**なので、
そちらも見ておくこと。

1. 送信機 2 台を**同じ CH・SF・Group** で TX にし、3 台目を RX にする。
2. 受信機の地図に `DUP SENDER !! / 2 TX ON SAME CH/GROUP` の赤いポップアップが出るか。
   `link_dup_sender.wav` が鳴るか（聞き逃しても 1 分後にまた鳴る）。
3. `log.txt` に `LINK ERROR: another sender detected (seq went backwards N times)` が残るか。
   60 秒レポートの末尾が ` DUP_SENDER` になるか。
4. **送信機 1 台を止める。30 秒でポップアップが消えるか**
   （消えなければラッチが残っている＝再起動しないと確認できない状態に戻っている）。
- **設定変更で再実行** … TX のまま WIRELESS 画面で CH を変える。
  その場でチェックが走り直すか（`checking... 5s` に戻る）。
- **モジュール無応答** … E220 を**通電したまま外して** TX にする。1 秒以内に
  `NOT MEASURED` で終わり、**地図の更新が飛ばない**こと。
  ★ このとき `e220_alive()` はまだ OK のままである（照合は起動時にしか走らない）。
  つまり事前チェックを素通りして実際に測りに行く経路を通る。連続 2 回の失敗で
  打ち切る作りになっていないと、ここで Core0 が 2 秒止まって GNSS を取りこぼす。
  外したまま 30 秒ほど置くと、生存確認が効いて `Module : NO RESPONSE` になり、
  `link_no_module.wav` が鳴り、地図のアイコンが**赤い×**になるか。

### 落とし穴

- **警告が出ても送信は止まらない。** これは仕様（仕様書 §5）。
  警告のあと `Sent` が増え続けることを必ず確認する。増えないなら実装が誤って
  送信を止めている。予備機を緊急で載せ替える場面で送信が始まらないのが一番危険。
- 点検中は**送信していない**。この 5 秒間はボート側が `NO SIGNAL` のままでよい。

## フェーズ 3：2 台で送受（20 分）

**机の上、1〜2m 離して**行う。ここで動かなければ屋外へ出ても意味がない。

1. 1 台を **TX**、もう 1 台を **RX**。**CH・SF・Group の 3 つを全部そろえる**
   （1 つでも違うと受からない）。Group は既定 0 のままでもここでは動く。
2. TX 側の地図画面：飛行機アイコンの左に**電波の弧**が出て、**1 秒に 1 回膨らむ**か。
   膨らまない＝送れていない。無線設定画面の `Sent` が増えているかも見る。
3. RX 側の地図画面：**枠がティール**になり、**アンテナが 3 本**立つか。
4. RX 側の無線設定画面：

| 項目 | 期待 |
|---|---|
| `Signal` | 至近なので −40 〜 −60 dBm、`3/3` |
| `Rx/Miss` | Rx が 1 秒に 1 ずつ増える。**Miss は増えない** |
| `Sender` | `OK`（機体側の SD/IMU が正常なら） |

5. RX 側の画面が TX 側と**同じ値**になっているか（対地速度・高度・気圧・電圧）。
6. TX の電源を切る → **10 秒後**に「RECEIVER MODE. NO SIGNAL.」が出て、
   アンテナが**0 本＋赤い×**になり、枠が**赤**に変わるか。音声も鳴るか。
7. TX を戻す → 復帰音が鳴り、枠がティールに戻るか。

### ここで確認しておきたい落とし穴

- **無線設定画面を開いたまま** `Rx/Miss` が正常に増え続けるか。
  （環境ノイズの問い合わせと受信が同じ UART を共有しているため。
  ここが止まるなら受信バッファの扱いに問題が残っている）
- CH または SF を**片方だけ**変えて、**受からなくなる**ことを確認する。
  受かってしまうなら設定がモジュールに入っていない。
- **Group を片方だけ変える。** 受信側が `Signal : GROUP n FOUND` になることを確認する。
  ここが `searching...` のままなら、グループ違いを無信号と区別できていない
  （SD が飛んで 0 に戻った事故に気づけなくなる）。確認したら戻す。
- ★ **送信中に TX 側のモジュールだけを外す**（本体の電源は入れたまま）。
  一番危険な壊れ方の再現なので必ず見ておくこと。
  - 30 秒以内に TX 側が `Module : NO RESPONSE` になり、`link_no_module.wav` が鳴り、
    地図の電波アイコンが**赤い×**になるか。

## フェーズ 5：屋外・距離（半日）

**ここから先はアンテナの置き方が SF より効く。** 偏波が 60° ずれるだけで 6dB 落ちる
（SF を 1 段上げても 2.5dB）。まずアンテナの向きを決めてから距離を測ること。

1. **見通しの良い平坦な場所**で、両方のアンテナを**同じ向き**に立てる。
2. 50m ごとに離れながら、RX 側の `Signal`（10 秒平均）と `Rx/Miss` を記録する。
3. **アンテナを 90° 倒して**同じ地点で測り直す。落ち幅を記録する。
   → ケース設計でアンテナをどう固定すべきかの根拠になる。
4. パケットが落ち始めた距離と、そのときの RSSI を記録する。

| 記録する項目 |
|---|
| 距離 / `Signal`(10秒平均) / アンテナ本数 / `Rx/Miss` / アンテナの向き / 地面の様子 |

### 合格ライン

- **200m で `Miss` がほとんど増えない**こと（要求距離）
- 350m 付近で落ち始めるなら、前回の実測（海辺・SF7）と整合する

### SF8 か SF10 かの判断

先に基準を決めておく。**距離が足りているなら SF8 のまま**にする。

| 200m での結果 | 判断 |
|---|---|
| `Miss` がほぼ 0、アンテナ 2〜3 本 | **SF8 で確定。**上げる理由が無い |
| `Miss` が数 % 出る、1 本 | まずアンテナの向き・高さを直す。それでも駄目なら SF10 |
| 全く届かない | SF ではなく配線・設定・アンテナを疑う。SF で 5dB 稼いでも足りない差 |

SF10 にすると平均電流が 4.3mA → 約 14.7mA、電波占有率が 10% → 34% になる。
**得られるのは 2.5dB × 2 段 = 5dB（距離にして 1.3〜1.8 倍）だけ**であることを
忘れないこと。同じ 5dB は、アンテナの向きを直すか高さを 2 倍にすれば無料で手に入る。

## 本番前チェックリスト（3 台）

| | 機体 | 追走ボート | プラットフォーム |
|---|---|---|---|
| `link_mode` | **TX** | RX | RX（途中で OFF にする） |
| `link_radio_ch` | フェーズ 2 で決めた CH。**3 台とも同じ** | 同左 | 同左 |
| `link_radio_prof` | フェーズ 5 で決めた SF。**3 台とも同じ** | 同左 | 同左 |
| `link_group` | **0 以外**。3 台とも同じ | 同左 | 同左 |
| 起動時の音声 | 「送信機モード」 | 「受信機モード」 | 「受信機モード」 |
| 目的地・ナビモード | ここが正 | 自動で機体に合う | 自動で機体に合う |

- **`link_mode` が TX の機体が 2 台無いこと。** 起動音声で 3 台ぶん確認する
- **`link_group` を 0 以外にすること。** 0 のままだと、同じ会場の他チームの PONS が
  同じ CH/SF だった場合に**他機の飛行をミラーし、`received/` にも他機のログが残る**。
  3 台とも同じ値であることを WIRELESS 画面で 1 台ずつ目視確認する
  （値は SD の `settings.txt` にだけ書く。git には既定 0 しか入っていない）
- プラットフォーム機は**予備機**。機体の PONS が壊れたら TX へ切り替えて載せ替える
- **3 台とも、起動直後の `log.txt` を 1 度は見ておく。**`BNO085 init OK` / `MS5611 init OK` /
  `GNSS CFG OK 2Hz/PVT/SAT/DOP/Air1g` の 3 行が揃っていること（フェーズ A）。
  ここが欠けていても画面には出ないまま飛べてしまう
- 電池はどれも満充電。受信機は +8.2mA で 1 時間ぶん短くなる
